The chapters show minimal snippets; the full code of every companion app lives next to the book, in the `apps/` folder of the [bakendpolyglot repository](https://github.com/sebastianluna-dev/bakendpolyglot). One repository keeps the book and the code in step: a change to a contract updates every stack and the chapter that describes it in the same commit, and each app has its own CI workflow that only runs when its folder changes.

| `apps/pulse` | Chapter 39 | NestJS, ASP.NET Core (SignalR), Spring, Go, FastAPI | Planned |

Each app follows the same layout: `contract/` (OpenAPI, Protobuf or event schemas), `db/migrations/` (one shared schema), `conformance/` (an HTTP-only test suite every stack must pass), `stacks/<stack>/` (one folder per implementation with its own README, tests and Dockerfile) and `compose.yaml`.

## Running an app

```bash
git clone https://github.com/sebastianluna-dev/bakendpolyglot.git
cd bakendpolyglot/apps/shelfwise
docker compose --profile express up --build            # Postgres + migrations + the Express stack
SHELFWISE_URL=http://localhost:3000 npm --prefix conformance test
```

Each stack folder has a README that starts at the entry point and follows one request through the layers, plus a short "From TypeScript" section with the surprises specific to that stack.
