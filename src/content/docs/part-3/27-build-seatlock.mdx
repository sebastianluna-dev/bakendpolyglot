Part III comes together in **SeatLock**, an event ticketing API. It is small, but it has every hard property a real ticketing system has: authenticated users from an identity provider, ownership rules, a scarce resource fought over by concurrent buyers, payments confirmed by webhook, retries everywhere, and a cache in front of read-heavy pages. It is built in five stacks: NestJS, ASP.NET Core (with controllers, as promised in Chapter 4), Spring Boot in Java, Go and Django. The code lives in the `seatlock` repository.

1. `GET /events/{id}` and `GET /events/{id}/seats`: public, cached (Chapter 25), seat **map** cached but availability always read fresh.
2. `POST /holds`: authenticated; claims up to six seats atomically for ten minutes.
3. `POST /holds/{id}/checkout` with an `Idempotency-Key`: only the holder; creates a pending order and a payment intent with the (simulated) payment provider.
4. `POST /webhooks/payments`: verified and deduplicated; a job marks the order paid and the seats sold.
5. The **hold reaper** runs every minute and releases expired holds.

## Claiming seats atomically

The central operation is the hold: several seats, all or nothing, with no chance of two users holding the same seat.

<FiveStacks note="Claim N seats in one transaction, or none">
<Stack id="nest" lib="Prisma">
```ts
return this.prisma.$transaction(async (tx) => {
  const hold = await tx.hold.create({ data: { userId, expiresAt: addMinutes(this.clock.now(), 10) } });
  const claimed = await tx.$executeRaw`
    UPDATE seats SET status = 'held', hold_id = ${hold.id}
    WHERE event_id = ${eventId} AND id = ANY(${seatIds}) AND status = 'available'`;
  if (claimed !== seatIds.length) throw new SeatsUnavailable(seatIds); // rolls back the transaction
  return hold;
});
```
</Stack>
<Stack id="cs" lib="EF Core ExecuteUpdate">
```csharp
await using var tx = await db.Database.BeginTransactionAsync(ct);
var hold = new Hold(userId, clock.GetUtcNow().AddMinutes(10));
db.Holds.Add(hold);
await db.SaveChangesAsync(ct);

var claimed = await db.Seats
    .Where(s => s.EventId == eventId && seatIds.Contains(s.Id) && s.Status == SeatStatus.Available)
    .ExecuteUpdateAsync(u => u.SetProperty(s => s.Status, SeatStatus.Held)
                              .SetProperty(s => s.HoldId, hold.Id), ct);
if (claimed != seatIds.Count) return Conflict(new SeatsUnavailableProblem(seatIds)); // tx disposed → rollback
await tx.CommitAsync(ct);
```
</Stack>
<Stack id="java" lib="Spring Data JPA">
```java
@Modifying
@Query("""
    update Seat s set s.status = 'HELD', s.holdId = :holdId
    where s.eventId = :eventId and s.id in :ids and s.status = 'AVAILABLE'""")
int claim(UUID eventId, List<UUID> ids, UUID holdId);

@Transactional
public Hold hold(UUID eventId, List<UUID> seatIds, String userId) {
    Hold hold = holds.save(new Hold(userId, clock.instant().plus(10, MINUTES)));
    if (seats.claim(eventId, seatIds, hold.getId()) != seatIds.size()) {
        throw new SeatsUnavailable(seatIds);   // runtime exception → rollback → 409
    }
    return hold;
}
```
</Stack>
<Stack id="go" lib="pgx">
```go
err := pgx.BeginFunc(ctx, s.db, func(tx pgx.Tx) error {
	if err := tx.QueryRow(ctx, `INSERT INTO holds (user_id, expires_at) VALUES ($1, $2) RETURNING id`,
		userID, s.now().Add(10*time.Minute)).Scan(&holdID); err != nil {
		return err
	}
	tag, err := tx.Exec(ctx, `UPDATE seats SET status = 'held', hold_id = $3
		WHERE event_id = $1 AND id = ANY($2) AND status = 'available'`, eventID, seatIDs, holdID)
	if err != nil {
		return err
	}
	if tag.RowsAffected() != int64(len(seatIDs)) {
		return ErrSeatsUnavailable // BeginFunc rolls back on error
	}
	return nil
})
```
</Stack>
<Stack id="django" lib="Django ORM">
```python
with transaction.atomic():
    hold = Hold.objects.create(user_id=user_id, expires_at=now() + timedelta(minutes=10))
    claimed = (Seat.objects
               .filter(event_id=event_id, id__in=seat_ids, status=Seat.AVAILABLE)
               .update(status=Seat.HELD, hold=hold))
    if claimed != len(seat_ids):
        raise SeatsUnavailable(seat_ids)    # leaving atomic() with an exception rolls back
```
</Stack>
</FiveStacks>

Every version uses the same idea from Chapter 23: one conditional update whose row count tells you whether you won. No locks are held while the user thinks; the hold is just state with an expiry.

<Pitfall title="Payment calls inside the transaction">
It is tempting to create the payment intent inside the checkout transaction. Do not: a slow payment provider then holds database locks and connections for seconds. Commit the pending order first, call the provider with its own idempotency key, and let the webhook move the order forward.
</Pitfall>

## Gate: Phase 3

The gate from the roadmap: **1,000 concurrent checkouts, zero seats oversold.** The repository includes a k6 script that has a thousand virtual users hold and buy random seats for a sold-out event, with retries and duplicate webhooks enabled.

- [ ] Run the invariant checks; each must return zero rows:

```sql
-- no seat belongs to two paid orders
SELECT seat_id FROM order_lines ol JOIN orders o ON o.id = ol.order_id
WHERE o.status = 'paid' GROUP BY seat_id HAVING count(*) > 1;

-- every sold seat is in exactly one paid order
SELECT s.id FROM seats s
LEFT JOIN order_lines ol ON ol.seat_id = s.id
LEFT JOIN orders o ON o.id = ol.order_id AND o.status = 'paid'
WHERE s.status = 'sold' GROUP BY s.id HAVING count(o.id) <> 1;
```
