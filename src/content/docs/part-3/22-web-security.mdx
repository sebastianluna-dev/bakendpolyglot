Security incidents in backends rarely involve clever cryptography. They involve a query built with string concatenation, a CORS policy set to `*` with credentials, an endpoint that fetches any URL it is given, or a login that can be tried a million times. This chapter walks through the attacks that keep appearing in the OWASP Top 10 lists, and the default in each stack that stops them.

## Injection

Any time input is concatenated into something that is later parsed (SQL, shell commands, LDAP filters, HTML), an attacker can change its meaning. The fix is never to concatenate: use **parameters**, which every driver and ORM in this book supports.

```sql
-- never: "SELECT * FROM events WHERE city = '" + city + "'"
SELECT * FROM events WHERE city = $1;   -- the value is sent separately, never parsed as SQL
```

Watch the escape hatches: raw SQL methods (`$queryRawUnsafe`, `FromSqlRaw` with interpolation, `JdbcTemplate` with string building, `fmt.Sprintf` into a query, Django’s `.extra()` and `raw()` with formatting). Code review should flag every one.

## CORS

Browsers stop a script from one origin reading responses from another, unless the server allows it. **CORS** is how the server says which origins may read. For requests with custom headers or methods, the browser first sends a **preflight** `OPTIONS` request and only proceeds if the answer allows it.

Configure CORS in each stack’s middleware with an explicit list of your frontends’ origins. Never combine a wildcard origin with credentials, and never reflect the `Origin` header back without checking it against the list. Remember that CORS protects users’ browsers, not your API: a script on any server can call your API regardless.

## CSRF

Cross-site request forgery tricks a logged-in user’s browser into sending a request your site did not intend, carrying the user’s cookies automatically. APIs that authenticate with bearer tokens in headers are not exposed, because browsers do not attach them on their own. Cookie-based sessions are: use `SameSite=Lax` or `Strict` cookies, and for state-changing requests add an anti-CSRF token (built into Django, ASP.NET and Spring Security for cookie sessions).

## SSRF

Server-side request forgery happens when your server fetches a URL the user controls: link previews, webhooks to user-supplied endpoints, image imports. The attacker supplies `http://169.254.169.254/` (the cloud metadata service) or `http://localhost:8080/admin` and your server dutifully fetches it from inside the network. Defend with an allow-list of destinations where possible, block private, loopback and link-local ranges after DNS resolution, disable redirects or re-check them, and run such fetches from an isolated egress proxy.

## Rate limiting

Rate limits protect against credential stuffing, scraping and accidental overload. The common algorithms:

| Algorithm | Behaviour | Good for |
| --- | --- | --- |
| Fixed window | N requests per clock minute | Simple quotas; bursty at window edges |
| Sliding window | N requests in any rolling minute | Fairer limits |
| Token bucket | Bucket of N tokens refilled steadily | Allowing short bursts with a steady average |
| Concurrency limit | At most N in flight | Protecting expensive endpoints |

These limiters keep state in the process, so with several replicas each replica allows its own 100. For a global limit, keep counters in Redis (Chapter 25) or enforce limits at the API gateway, which is where most companies put them.

## Security headers and transport

Serve only over HTTPS and send `Strict-Transport-Security`. For APIs, `Content-Type` must be accurate and `X-Content-Type-Options: nosniff` set; for anything that renders HTML, a `Content-Security-Policy` is the strongest XSS mitigation. Libraries such as `helmet` (Express) and the defaults in Spring Security set most headers for you.

## Dependencies and secrets

Most compromised applications are compromised through a dependency or a leaked credential, not their own code. Run dependency scanning in CI (Dependabot or Renovate plus `npm audit`, `dotnet list package --vulnerable`, OWASP Dependency-Check or Snyk, `govulncheck`, `pip-audit`), pin versions with lockfiles, and enable secret scanning on every repository.

<Pitfall title="Error messages that help attackers">
"User not found" versus "wrong password" lets an attacker enumerate accounts; detailed SQL errors reveal your schema; stack traces reveal frameworks and versions. Return generic messages to clients, detailed ones to logs, linked by the request id.
</Pitfall>

<InTheWild>
Companies run security in layers: a WAF and rate limits at the edge, an API gateway validating tokens, services enforcing authorization, databases with least-privilege users, and scanners in CI. As the senior on a team, you are expected to know which layer stops which attack, and to notice when a change removes one.
</InTheWild>
