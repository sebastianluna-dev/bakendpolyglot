## How a live coding interview works

The format varies between companies and between rounds, so ask the recruiter beforehand rather than guessing. The common shape is a short introduction, one problem (sometimes two, the second building on the first), and a few minutes at the end for your questions. You share a screen or a collaborative editor with one or two interviewers. Some editors run code, some only highlight it, and some do neither, so you should be able to write correct code without running it and to test it by hand.

What the interviewer can observe is narrow, and that is useful to know:

- **How you understand the problem.** Do you ask about the inputs, the outputs and the awkward cases before you type?
- **How you choose an approach.** Can you name a simple solution, say why it is slow, and find a better one?
- **Whether the code is correct and readable.** Clear names, no dead ends, edge cases handled.
- **How you check your work.** Do you find your own bugs by tracing an example, before the interviewer points them out?
- **How you communicate.** Can someone follow your reasoning while you work?

Notice that "knows the trick" is not on the list. Interviewers usually prefer a candidate who reaches a good solution steadily and explains it to one who writes the optimal answer in silence. The method below makes that steady path the default.

Two rules apply before you start. Ask whether you may use the language's documentation; some interviewers allow it, many do not. And unless the interviewer says otherwise, assume no AI assistant and no autocomplete. Practise under the same conditions, as the plan later in this chapter does.

## One method for every problem

Use the same six steps every time, out loud, in this order. The order matters more than speed: each step makes the next one cheaper, and skipping a step is where most interview bugs come from.

| Step | What you do | What you say |
| --- | --- | --- |
| 1. Restate | Put the problem in your own words: inputs, outputs, types | "So I get a list of prices and a budget, and I return the positions of two items that add up to it." |
| 2. Ask about edge cases | Empty input, one element, duplicates, negatives, no answer, size limits, whether you may change the input | "What should I return if no pair works? Can the same item count twice? How long can the list be?" |
| 3. Simple solution first | The brute force, its complexity, and whether to code it | "Checking every pair works and is O(n²). I'd like to do better, but that's my fallback." |
| 4. Improve | Find the repeated work and the data structure that removes it; agree before coding | "For each price I'm searching for its complement. A hash map makes that lookup O(1)." |
| 5. Trace | Run the code by hand on an example, then on the edge cases | "j is 0, price 12, I need 0, not seen, so I store 12 at 0…" |
| 6. State the complexity | Time and space, and the trade-off you made | "O(n) time, O(n) space for the map. If the input were sorted I could use two pointers and O(1) space." |

A few habits make the method work under pressure.

**Write the examples down first.** Put the inputs and expected outputs as comments at the top of the editor before any code. You will trace against them in step 5, and you will often see the algorithm while writing them.

**Say the brute force even if you won't code it.** It proves you understood the problem, it gives you something to fall back on, and the improvement usually comes from asking "what is the brute force doing twice?"

**Agree on the approach before you type.** One sentence ("I'll use a hash map from price to its first index, one pass") lets the interviewer redirect you before you spend fifteen minutes on the wrong idea.

**Narrate decisions, not keystrokes.** "I store the index only the first time I see a price, so the earliest one wins" is useful. "Now I'm typing a for loop" is not.

**When you get stuck, go smaller.** Solve the example by hand on paper, try an input of size two, or say what you know and what you don't. Saying "I'm not sure about this part" and moving forward is better than going silent, and interviewers can only give hints to someone who is talking.

<Pitfall title="Jumping to the clever answer">
Starting with the optimal solution you half-remember from practice is the most common way to fail a problem you could have solved. If you misremember a detail, you have no simpler version to fall back on and nothing on the screen that earns credit. Go through steps 1 to 3 first, even when you think you know the trick; they take a few minutes and protect the rest of the round.
</Pitfall>

## The method on one problem

Here is the method applied to problem 002 from the bank, roughly as it would sound in the room.

**Restate.** "I'm given an array of item prices and a budget. I return the indices of two different items whose prices add up exactly to the budget."

**Ask.** The answers turn a vague problem into a precise one:

- *If several pairs work, which one?* The pair whose second index is smallest; if that index pairs with several earlier items, the earliest of them.
- *If none works?* An empty array.
- *Can one item be used twice?* No: two different positions, although two items may have the same price.
- *Size and values?* Up to 10⁵ prices, each a positive integer that fits easily in 32 bits.

Written down as examples at the top of the editor:

```text
twoPrices([12, 7, 3, 9, 5], 12) -> [2, 3]   // 3 + 9; 7 + 5 also works but ends later
twoPrices([4, 4, 1], 8)         -> [0, 1]   // same price, different items
twoPrices([1, 2], 10)           -> []       // no pair
```

**Simple first.** Check every pair with two loops. With 10⁵ prices that is about 5 × 10⁹ comparisons, which is too slow, but it is correct and it shows what the work is. Looping `j` on the outside and `i` on the inside returns pairs in exactly the order the rules ask for:

```ts
for (let j = 0; j < prices.length; j++)
  for (let i = 0; i < j; i++)
    if (prices[i] + prices[j] === budget) return [i, j];
return [];
```

**Improve.** The inner loop searches the earlier prices for one value, `budget - prices[j]`. A hash map from price to its **first** index answers that in O(1), so one pass is enough. Storing only the first index keeps the "earliest `i`" rule, and checking before inserting stops an item from pairing with itself.

Look at what changes between the tabs and what doesn't. The algorithm is identical. What you have to remember is the vocabulary: `get` returning `undefined`, `null` or `None`, Go's two-value `ok` lookup, C#'s `TryGetValue` with an `out` variable, and the "insert only if absent" call (`putIfAbsent`, `TryAdd`, `setdefault`) that saves you an `if`. Those small differences are what the language sections train.

**Trace.** Run the first example by hand, one row per iteration. In an editor that can't run code, this table is your test:

| `j` | `prices[j]` | Need | In the map? | Map afterwards |
| --- | --- | --- | --- | --- |
| 0 | 12 | 0 | no | `{12: 0}` |
| 1 | 7 | 5 | no | `{12: 0, 7: 1}` |
| 2 | 3 | 9 | no | `{12: 0, 7: 1, 3: 2}` |
| 3 | 9 | 3 | yes, at 2 | return [2, 3] |

Then the edge cases. With `[4, 4, 1]` and 8, at `j = 0` you need 4, which isn't stored yet, so the item can't pair with itself. At `j = 1` you need 4 and find it at index 0. With no pair, the loop ends and returns the empty array. With an empty list, the loop never runs.

**Complexity.** One pass with O(1) map operations on average gives O(n) time, and the map holds at most n entries, so O(n) space. Say the trade-off too: you used memory to save time, and a sorted input would allow two pointers with O(1) extra space, which is a different problem (053 uses that idea).

<InterviewLens>
"How would you test this?" Name the cases before writing any of them: the two examples, no pair, an empty list, a duplicate price that must pair with itself only at another index, and the tie-breaking rule when several pairs work. Then, if there is time, write them the way the language sections show. Testing your own code without being asked is one of the clearest signals you can give.
</InterviewLens>

## TypeScript

For most readers of this book TypeScript is the home language, so this section is the one to read fastest. The gap is not the language but the editor. Every day it fills in method names, warns you about `undefined` and imports what you need. In an interview, you have to remember those things yourself. The section also covers the parts of the language that people rarely use: TypeScript has no heap and no deque, its numbers are all floating point, and its default sort compares numbers as strings. Those are the places where fluent TypeScript developers lose time.

Everything here runs on Node 22.18 or later with `node file.ts`, the way the files in `apps/interview-bank` do. Chapter 3 covers the runtime; this section covers only what you type in the round.

### Syntax by heart

These are the structures the problem bank uses. Learn the left column well enough to type it without thinking, and know the cost of each operation, because you will say it in step 6.

| Structure | Write it as | Operations to know |
| --- | --- | --- |
| List | `const a: number[] = []` | `push`, `pop`, `a[i]`, `a.at(-1)`, `a.length`: O(1). `includes`, `indexOf`, `splice`, `unshift`: O(n). `shift`: O(n) in the worst case |
| Map | `new Map<string, number>()` | `get`, `set`, `has`, `delete`, `size`: O(1) average. Iterates in insertion order |
| Set | `new Set<number>()` | `add`, `has`, `delete`, `size`: O(1) average |
| Stack | an array | `push`, `pop`, `at(-1)` to peek |
| Queue | an array plus a head index | `push` to enqueue, `a[head++]` to dequeue: O(1) |
| Deque | an array plus a head index | Pop from the back with `pop`, from the front with `head++`; works while you never add at the front |
| Heap | none built in | Write the `MinHeap` below: `push` and `pop` in O(log n) |
| Grid | `Array.from({ length: rows }, () => new Array(cols).fill(0))` | `grid[r][c]` |
| Pair | a tuple, `[number, string]` | Destructure with `const [count, title] = pair` |

In code, the everyday moves look like this:

```ts
const copies: number[] = [];
copies.push(4);
copies.push(9);
const last = copies.pop();          // 9
const top = copies.at(-1);          // 4, without removing it

const loansPerMember = new Map<string, number>();
loansPerMember.set("ana", (loansPerMember.get("ana") ?? 0) + 1);   // count with a default

const seen = new Set<number>([3, 1, 3]);   // {3, 1}
seen.add(7);

const key = (r: number, c: number) => `${r},${c}`;   // a grid cell as a Set or Map key
const visited = new Set<string>([key(0, 1)]);
```

The last two lines matter more than they look. `Map` and `Set` compare object keys by reference, so `new Set([[0, 1]]).has([0, 1])` is `false`: the two arrays are different objects. Whenever a key has more than one part, turn it into a string.

A queue is the one structure you have to build on the spot. The language does not promise that `shift` is O(1), and an engine may move every remaining element on each call, which turns a breadth-first search into O(n²). Keep a head index instead and let the array grow:

```ts
function bfsOrder(graph: Map<number, number[]>, start: number): number[] {
  const order: number[] = [];
  const seen = new Set<number>([start]);
  const queue: number[] = [start];
  let head = 0;
  while (head < queue.length) {
    const node = queue[head++];
    order.push(node);
    for (const next of graph.get(node) ?? []) {
      if (!seen.has(next)) {
        seen.add(next);
        queue.push(next);
      }
    }
  }
  return order;
}
```

The array keeps every node it has ever held, so memory is O(n) for the whole search instead of the size of the frontier. In an interview that is a fine trade, and you should say so.

<Pitfall title="One row, shared by the whole grid">
`new Array(rows).fill(new Array(cols).fill(0))` creates one inner array and puts the same reference in every row, so writing `grid[0][0] = 1` changes the first cell of every row. `fill` copies the value it is given, and for an array that value is a reference. Use `Array.from` with a function, which builds a new row each time.
</Pitfall>

### Strings and characters

There is no `char` type. `s[i]` is a string of length one, strings are immutable, and `s.length` counts UTF-16 code units, not letters. The bank uses ASCII input unless a problem says otherwise, so you can index freely. Ask about it when the input could be any text.

```ts
const s = "Shelfwise";
s[0];                         // "S"
s.at(-1);                     // "e"
s.slice(1, 4);                // "hel", end index excluded
s.charCodeAt(1) - 97;         // 7: the letter's position in the alphabet ("a" is 97)
String.fromCharCode(97 + 7);  // "h"
"  two   words ".trim().split(/\s+/);   // ["two", "words"]
"7".padStart(3, "0");         // "007"
[..."stressed"].reverse().join("");     // "desserts"
```

Counting letters with a fixed array of 26 is faster to write than a `Map` and is the standard move for anagram problems:

```ts
function letterCounts(word: string): number[] {
  const counts = new Array<number>(26).fill(0);
  for (const ch of word) counts[ch.charCodeAt(0) - 97]++;
  return counts;
}
```

For character classes, compare strings directly or use a short regular expression: `ch >= "0" && ch <= "9"` for a digit, `ch.charCodeAt(0) - 48` for its value, and `/[a-z]/i.test(ch)` for a letter. To build a long string, push the pieces into an array and `join` them at the end. Repeated `+=` is also fast in V8, but the array version reads the same in every language in this chapter.

### Sorting with a comparator

`sort` without arguments converts every element to a string and compares those, which is right for words and wrong for numbers:

```ts
[10, 9, 1].sort();                     // [1, 10, 9]
nums.sort((a, b) => a - b);            // ascending, in place
const desc = nums.toSorted((a, b) => b - a);   // descending, new array, nums unchanged
```

A comparator returns a negative number, zero or a positive number. Chain keys with `||`, which works because a tie returns `0` and `0` is falsy:

```ts
type Loan = { member: string; due: number };
loans.sort((a, b) => a.due - b.due || (a.member < b.member ? -1 : a.member > b.member ? 1 : 0));
```

The string comparison is written out because `a - b` does not work on strings. `a.localeCompare(b)` is shorter but depends on locale rules, so for problems that specify an order on plain ASCII, the explicit comparison is the safer choice. `sort` is stable, so elements that compare equal keep their original order. It sorts in place and returns the same array; `toSorted` returns a copy.

<Pitfall title="The default sort on numbers">
`ages.sort()` passes every test whose numbers have the same number of digits, then fails on `[9, 10]`. Always pass a comparator when sorting numbers, even when the examples happen to work without one.
</Pitfall>

### Iteration

```ts
for (let i = 0; i < titles.length; i++) { /* index and value */ }
for (const t of titles) { /* values */ }
for (const [i, t] of titles.entries()) { /* index and value, no counter to get wrong */ }
for (let i = titles.length - 1; i >= 0; i--) { /* backwards */ }
for (const [title, count] of stock) { /* a Map, in insertion order */ }
for (const [title, count] of Object.entries(counts)) { /* a plain object */ }
```

Do not use `for...in` on arrays: it walks the property names, which are strings, so `i + 1` becomes `"01"`. `forEach` cannot `break` or `return` from the outer function, so in an interview use `for...of`, which can.

### Numbers

TypeScript has one `number` type, a 64-bit float. Integers are exact up to `Number.MAX_SAFE_INTEGER` (2⁵³ − 1, about 9 × 10¹⁵), so the overflow bugs of the other five languages do not happen, but precision loss does: `2 ** 53 + 1 === 2 ** 53` is `true`. When a problem multiplies large values, say that you would switch to `bigint` (`2n ** 64n`) or keep the numbers as strings.

Division and remainder need care:

| You want | Write | Note |
| --- | --- | --- |
| Integer division toward zero | `Math.trunc(a / b)` | `Math.trunc(-7 / 2)` is `-3`, as in Java, C#, Kotlin and Go |
| Integer division rounding down | `Math.floor(a / b)` | `-4`, the same as Python's `//` |
| Remainder | `a % b` | Takes the sign of `a`: `-7 % 3` is `-1` |
| Always-positive modulo | `((a % m) + m) % m` | `2` for `-7` and `3`, as Python's `%` gives |
| Halve an index | `mid >> 1` | Bitwise operators truncate to 32 bits; fine for indices, wrong for large values |
| Sentinels | `Infinity`, `-Infinity` | Start a minimum at `Infinity` |

For parsing, `Number(s)` rejects trailing junk (`Number("12a")` is `NaN`) but accepts the empty string as `0`, while `Number.parseInt(s, 10)` stops at the first non-digit and returns `12`. When a problem defines what a valid number looks like, such as problem 038, parse it yourself character by character.

### Errors

Throw `Error` or a subclass of it. Under `strict`, the variable in `catch` has the type `unknown`, so narrow it before using it:

```ts
class NotFoundError extends Error {
  constructor(message: string) {
    super(message);
    this.name = "NotFoundError";
  }
}

const shelf = new Map<number, string>([[1, "Dune, copy 1"]]);

function findCopy(id: number): string {
  const copy = shelf.get(id);
  if (copy === undefined) throw new NotFoundError(`copy ${id} not found`);
  return copy;
}

function findCopyOrNull(id: number): string | null {
  try {
    return findCopy(id);
  } catch (err) {
    if (err instanceof NotFoundError) return null;
    throw err;          // anything else is a real failure: don't swallow it
  }
}
```

In algorithm rounds, ask in step 2 what to return when there is no answer. The bank's convention is an empty value (an empty array, `-1`, `null`) unless the problem says to throw, because that is easier to test and to explain.

### Concurrency basics

Node runs your code on one thread (Chapter 3). `async` functions do not run in parallel with each other; they take turns at every `await`. That makes concurrency questions in TypeScript about coordinating I/O, not about locks. The tools you need from memory are `Promise.all` to wait for several operations, `Promise.allSettled` when some may fail and you still want the rest, and a sleep:

```ts
import { setTimeout as sleep } from "node:timers/promises";

const [book, member] = await Promise.all([loadBook(id), loadMember(memberId)]);
await sleep(100);
```

The pattern most worth knowing is bounded concurrency, a fixed number of workers pulling from a shared list. Problem 199 builds it fully; this is its core:

```ts
async function mapLimit<T, R>(items: T[], limit: number, fn: (item: T) => Promise<R>): Promise<R[]> {
  const results = new Array<R>(items.length);
  let next = 0;
  async function worker(): Promise<void> {
    while (next < items.length) {
      const i = next++;
      results[i] = await fn(items[i]);
    }
  }
  const workers = Array.from({ length: Math.min(limit, items.length) }, () => worker());
  await Promise.all(workers);
  return results;
}
```

Writing to `results[i]` keeps the output in input order whatever order the calls finish in. There is no lock around `next++` because nothing else can run between reading `next` and incrementing it: the only place a worker gives up the thread is the `await`.

<InterviewLens>
"Two workers share `next` with no lock. Is that a race?" Not in Node: a function runs until it reaches an `await`, so the check and the increment happen as one step. Say what would break it: putting an `await` between `const i = next` and `next++`. Then say that in Go, Java, Kotlin or C# the same code would be a real data race, which is why those sections use a channel, an atomic counter or a concurrent queue instead.
</InterviewLens>

### The heap

TypeScript has no priority queue, so any problem that needs "the smallest so far" (the k closest points, merging k lists, Dijkstra's algorithm) starts with you writing one. Learn this version. It is short enough to type in three minutes and has nothing clever in it: an array, a `less` function, a loop that moves an item up after `push`, and a loop that moves an item down after `pop`.

```ts
class MinHeap<T> {
  items: T[] = [];
  less: (a: T, b: T) => boolean;

  constructor(less: (a: T, b: T) => boolean) {
    this.less = less;
  }

  get size(): number {
    return this.items.length;
  }

  peek(): T | undefined {
    return this.items[0];
  }

  push(item: T): void {
    const a = this.items;
    a.push(item);
    let i = a.length - 1;
    while (i > 0) {
      const parent = (i - 1) >> 1;
      if (!this.less(a[i], a[parent])) break;
      [a[i], a[parent]] = [a[parent], a[i]];
      i = parent;
    }
  }

  pop(): T | undefined {
    const a = this.items;
    if (a.length === 0) return undefined;
    const top = a[0];
    const end = a.pop()!;
    if (a.length > 0) {
      a[0] = end;
      let i = 0;
      while (true) {
        const left = 2 * i + 1;
        const right = left + 1;
        let smallest = i;
        if (left < a.length && this.less(a[left], a[smallest])) smallest = left;
        if (right < a.length && this.less(a[right], a[smallest])) smallest = right;
        if (smallest === i) break;
        [a[i], a[smallest]] = [a[smallest], a[i]];
        i = smallest;
      }
    }
    return top;
  }
}
```

The children of index `i` are at `2i + 1` and `2i + 2`, and its parent is at `(i - 1) >> 1`. That one fact is the whole data structure. The same class gives you every heap the bank needs:

```ts
const minHeap = new MinHeap<number>((a, b) => a < b);
const maxHeap = new MinHeap<number>((a, b) => a > b);
const byDue = new MinHeap<[number, string]>((a, b) => a[0] < b[0]);   // priority first, then the value
```

Two details are easy to get wrong. In `pop`, check whether the array is empty again after removing the last element, or a heap of size one puts its only item back. In the loops, compare with `less` and not with `<`, or the max-heap silently becomes a min-heap. If time is short, say that you would use this class and ask whether you may treat it as given; some interviewers allow that and want to see the algorithm that uses it.

The class uses plain fields instead of a constructor parameter property (`constructor(private less: …)`). That is deliberate: parameter properties, `enum` and `namespace` are not erasable syntax, and `node file.ts` refuses to run them.

### Mistakes when coming from the other languages

If TypeScript is not your daily language, these are the habits that will catch you. Each one gives a wrong answer instead of an error, which makes it expensive under time pressure.

**From Python.** `a[-1]` is `undefined`; use `a.at(-1)`. There is no `//`: use `Math.floor`, and remember that `%` keeps the sign of the left operand. `if (counts.get(k))` treats a count of `0` as missing; compare with `undefined` or use `has`. There is no `defaultdict`: write `map.set(k, (map.get(k) ?? 0) + 1)`. Tuples and lists compare by reference, so a `Set` of `[r, c]` pairs never finds anything. `x in arr` checks indices, not values; use `includes`.

**From Java, C# and Kotlin.** Objects have no `equals` or `hashCode` to override, so composite keys must be strings. `==` converts types before comparing; always write `===`. Reading past the end of an array returns `undefined` instead of throwing, and the bug shows up later as `NaN`. `new Array(n)` holds empty slots, not zeros, until you `fill` it. `const` stops you reassigning the variable, not changing the array.

**From Go.** A missing `Map` key gives `undefined`, not a zero value, so add `?? 0`. There are no multiple return values: return a tuple and destructure it. Arrays and objects are always shared by reference, like slices and maps, and never copied on assignment as Go arrays and structs are; copy with `[...a]` or `structuredClone`. `for (const x of a)` gives values; use `entries()` when you need the index.

## C#

C# reads so much like TypeScript and Java that the danger in a live round is code you half-remember: it compiles, then behaves differently. `int` is 32 bits and overflows without a word, a missing `Dictionary` key throws, `Substring` takes a length, and the built-in sort is not stable. In return the library has a real heap, a sorted set and tuples that work as keys. It lacks a deque, and its heap cannot change a priority.

Everything here runs on .NET 10 with `dotnet run file.cs`, the way the files in `apps/interview-bank` do: one file, top-level statements, no project. `System.Linq`, `System.Collections.Generic` and `System.Threading.Tasks` are imported for you; `StringBuilder` needs `using System.Text;` and the concurrent collections `using System.Collections.Concurrent;`. ### Syntax by heart

These are the structures the problem bank uses, with the costs you will name in step 6.

| Structure | Write it as | Operations to know |
| --- | --- | --- |
| List | `var a = new List<int>()`, or `new int[n]` for a fixed size | `Add`, `a[i]`, `a[^1]`, `RemoveAt(a.Count - 1)`, `Count`: O(1). `Insert(0, x)`, `RemoveAt(0)`, `Contains`, `IndexOf`, `Remove(x)`: O(n). Arrays use `Length` |

For a deque, use `LinkedList<T>`: O(1) at both ends and nothing to write. It allocates a node per item, which does not matter at interview sizes; a ring buffer avoids that but has wrap-around bugs to get wrong, so write one only if asked about memory. For grids you create (a `visited` array, a DP table), use `int[,]`: one allocation, every cell zero, no rows to forget. Use `int[][]` when the input arrives that way.

```csharp
var copies = new List<int>();
```

<FromTS title="Composite keys without strings">
In TypeScript a grid cell has to become the string `"r,c"` before it goes in a `Set`. In C#, tuples and records hash and compare by value, so `HashSet<(int, int)>` and `Dictionary<(int Row, int Col), int>` just work. Arrays do not: `int[]` compares by reference, as in TypeScript.
</FromTS>

Breadth-first search gets a real `Queue<T>`, and because `HashSet.Add` returns a `bool`, the "seen" check and the insert are one call:

```csharp
static List<int> BfsOrder(Dictionary<int, List<int>> graph, int start)
{
    var order = new List<int>();
    var seen = new HashSet<int> { start };
    var queue = new Queue<int>([start]);
    while (queue.Count > 0)
    {
        var node = queue.Dequeue();
        order.Add(node);
        foreach (var next in graph.GetValueOrDefault(node, []))
            if (seen.Add(next)) queue.Enqueue(next);
    }
    return order;
}
```

<Pitfall title="Reading a key that isn't there">
`counts[word]++` throws `KeyNotFoundException` the first time it meets a word: the indexer returns no default, unlike a Go map or `Map.get`. Use `TryGetValue` when you need to know whether the key was there and `GetValueOrDefault` when zero is the right answer.
</Pitfall>

### Strings and characters

Strings are immutable, and `s[i]` is a `char`, a 16-bit UTF-16 code unit. Arithmetic on a `char` gives an `int`; cast back with `(char)`. Single quotes make a `char`, double quotes a `string`, and they do not mix: `"a" == 'a'` does not compile.

```csharp
var s = "Shelfwise";
var first = s[0];                          // 'S', a char
var lastCh = s[^1];                        // 'e'
var part = s[1..4];                        // "hel", end index excluded
var sub = s.Substring(1, 4);               // "helf": the second argument is a length
var pos = s[1] - 'a';                      // 7: char minus char is an int
var letter = (char)('a' + 7);              // 'h': cast back to char
var digit = '7' - '0';                     // 7
var words = "  two   words ".Split(' ', StringSplitOptions.RemoveEmptyEntries);   // ["two", "words"]
var padded = "7".PadLeft(3, '0');          // "007"
var reversed = new string("stressed".Reverse().ToArray());   // "desserts"
var joined = string.Join(", ", new[] { 1, 2, 3 });            // "1, 2, 3"
```

For messy input, `Split(',', StringSplitOptions.RemoveEmptyEntries | StringSplitOptions.TrimEntries)` drops empty fields and trims the rest; pass `(char[]?)null` as the separator to split on any whitespace. For letter counts, `new int[26]` is already zeroed; compare two count arrays with `SequenceEqual`, never `==`. Build long strings with `StringBuilder` (`sb.Append(ch).Append(count)`, then `ToString()`). `char.IsDigit` and `char.IsLetter` accept any Unicode digit or letter; `char.IsAsciiDigit` and `char.IsAsciiLetter` are the strict versions. Spans (`s.AsSpan(start, length)`) avoid the copy `Substring` makes, but are worth raising only if asked about allocations.

### Sorting with a comparator

`Array.Sort` and `List.Sort` sort in place and return `void`, so `var sorted = Array.Sort(a)` does not compile. LINQ's `Order` and `OrderBy` return a new sequence.

```csharp
int[] nums = [10, 9, 1];
Array.Sort(nums);                                   // [1, 9, 10], in place
Array.Sort(nums, (a, b) => b.CompareTo(a));         // descending
var asc = nums.Order().ToArray();                   // a sorted copy; nums unchanged
```

A `Comparison<T>` returns a negative number, zero or a positive one. Use `CompareTo`, not `a - b`, which overflows: `[1, int.MinValue, 5]` sorted with `(a, b) => a - b` comes out as `[1, 5, -2147483648]`. Chain keys with a conditional:

```csharp
loans.Sort((a, b) => a.Due != b.Due ? a.Due.CompareTo(b.Due) : string.CompareOrdinal(a.Member, b.Member));
var ordered = loans.OrderBy(l => l.Due).ThenBy(l => l.Member, StringComparer.Ordinal).ToList();

record Loan(string Member, int Due);   // loans is a List<Loan>; type declarations go at the end of the file
```

`<` does not compile on strings, and the default string comparison is culture-sensitive: it sorts `["b", "a", "B", "A"]` as `a, A, b, B`, while ordinal order, what most problems mean by "lexicographic", is `A, B, a, b`. Pass `string.CompareOrdinal` or `StringComparer.Ordinal`. Tuples compare field by field, so a `List<(int, int)>` sorts with a plain `Sort()`.

<Pitfall title="An unstable sort that passes small tests">
`Array.Sort` and `List.Sort` use introsort, which is not stable. Small arrays go through insertion sort and happen to keep ties in order, so a five-element test passes and the same code fails on fifty. When ties must keep their original order, use `OrderBy(...).ThenBy(...)`, which is stable, or add the original index as the last key.
</Pitfall>

### Numbers

`int` is 32 bits and `long` is 64, everywhere. Overflow wraps silently unless you ask for a check:

```csharp
int a = 50_000, b = 50_000;
int wrong = a * b;                // -1794967296, and no error
long stillWrong = a * b;          // the same: the multiplication happens in int
long right = (long)a * b;         // 2500000000
int boom = checked(a * b);        // throws OverflowException
```

If values can pass about 2.1 × 10⁹, say so in step 2 and use `long`; beyond 64 bits there is `BigInteger` in `System.Numerics`. While practising, `#:property CheckForOverflowUnderflow=true` at the top of a file-based app turns every silent wrap into an exception.

| You want | Write | Note |
| --- | --- | --- |
| Integer division toward zero | `a / b` | `-7 / 2` is `-3`, and `7 / 2` is `3`: two ints never give 3.5 |
| A real quotient | `(double)a / b` | Cast before dividing; `(double)(a / b)` is already truncated |
| Integer division rounding down | `(int)Math.Floor((double)a / b)` | `-4`, like Python's `//`. Exact for `int`; for `long` use `FloorDiv` below |
| Remainder | `a % b` | Takes the sign of `a`: `-7 % 3` is `-1` |
| Always-positive modulo | `((a % m) + m) % m` | `2` for `-7` and `3` |
| Midpoint | `lo + (hi - lo) / 2` | `(lo + hi) / 2` overflows once the sum passes `int.MaxValue` |
| Sentinels | `int.MaxValue`, `int.MinValue` | `int.MaxValue + 1` wraps to `int.MinValue`, so never add to a sentinel |
| Absolute value | `Math.Abs(x)` | Throws `OverflowException` for `int.MinValue` |

```csharp
static long FloorDiv(long a, long b) => a / b - (a % b != 0 && (a < 0) != (b < 0) ? 1 : 0);
```

`int.Parse("12a")` throws `FormatException`, while `int.Parse(" 42 ")` returns 42 because surrounding whitespace is allowed. `int.TryParse(s, out var n)` returns `false` instead of throwing. `double.Parse` follows the machine's culture, and under `es-ES` it reads `"1.5"` as 15, so pass `CultureInfo.InvariantCulture` (from `System.Globalization`). When the problem defines the format, as 038 does, parse by hand.

### Errors

Exceptions are unchecked: there is no `throws` clause, and writing one is a syntax error. Throw a standard type (`ArgumentException`, `InvalidOperationException`) or declare your own in one line with a primary constructor:

```csharp
var shelf = new Dictionary<int, string> { [1] = "Dune, copy 1" };

string FindCopy(int id) =>
    shelf.TryGetValue(id, out var copy) ? copy : throw new NotFoundException($"copy {id} not found");

string? FindCopyOrNull(int id)
{
    try

        return FindCopy(id);

    {

    }
}
```

Rethrow with `throw;`, which keeps the stack trace; `throw e;` starts a new one. For "may be missing", the library uses the `Try` pattern, a `bool` plus an `out` value, and it suits your own helpers too. ### Concurrency basics

Here C# differs most from TypeScript. Tasks run on a pool of real threads, and the code after an `await` may resume on any of them (Chapter 4), so two tasks that touch one variable can race. Protect shared state with `Interlocked` for a number, `lock` for anything bigger, or a concurrent collection.

```csharp
var bookTask = LoadBook(bookId);           // both calls start here
var memberTask = LoadMember(memberId);
await Task.WhenAll(bookTask, memberTask);
var (book, member) = (await bookTask, await memberTask);   // already complete: no waiting
string[] titles = await Task.WhenAll(ids.Select(LoadBook));   // results in input order
await Task.Delay(100);                     // a sleep that does not block a thread
```

The TypeScript `mapLimit` translates directly, except that `next++` is now a real race. `Interlocked.Increment` makes the read and the increment one atomic step, so each index goes to exactly one worker:

```csharp
static async Task<R[]> MapLimit<T, R>(T[] items, int limit, Func<T, Task<R>> fn)
{
    var results = new R[items.Length];
    var next = -1;
    async Task Worker()
    {
        int i;
        while ((i = Interlocked.Increment(ref next)) < items.Length)
            results[i] = await fn(items[i]);
    }
    var workers = Enumerable.Range(0, Math.Min(limit, items.Length)).Select(_ => Worker());
    await Task.WhenAll(workers);
    return results;
}
```

The more common C# version starts a task per item and lets a `SemaphoreSlim` admit `limit` at a time:

```csharp
static async Task<R[]> MapLimitGate<T, R>(T[] items, int limit, Func<T, Task<R>> fn)
{
    using var gate = new SemaphoreSlim(limit);
    var tasks = items.Select(async item =>
    {
        await gate.WaitAsync();
        try { return await fn(item); }
        finally { gate.Release(); }
    });
    return await Task.WhenAll(tasks);
}
```

Both keep results in input order. `Parallel.ForEachAsync` with `MaxDegreeOfParallelism` is the built-in version; name it, then write one of these if asked for the mechanism. For other shared state:

```csharp
var total = 0;
await Task.WhenAll(Enumerable.Range(0, 8).Select(_ => Task.Run(() =>
{
    for (var k = 0; k < 100_000; k++) Interlocked.Increment(ref total);   // total++ here loses updates
})));                                      // total is 800000

var gate = new Lock();                     // C# 13 and .NET 9; before that, new object()
lock (gate) loansPerMember[m] = loansPerMember.GetValueOrDefault(m) + 1;
```

`ConcurrentDictionary` and `ConcurrentQueue` cover shared collections; workers draining one `ConcurrentQueue` with `TryDequeue` are another correct `mapLimit`.

<InterviewLens>
"Several threads write into `results` with no lock. Is that safe?" Yes: `Interlocked.Increment` hands out each index once, so no two workers share a slot, and `await Task.WhenAll` makes every write visible before you read the array. Then say what would break it: `next++` instead, which lets two workers read the same value, so one item runs twice and another never runs.
</InterviewLens>

### The heap

`PriorityQueue<TElement, TPriority>` is a min-heap that stores each element with a separate priority. In Java and Python the element is its own priority; here, for plain numbers, you write the value twice: `heap.Enqueue(x, x)`.

```csharp
var byDue = new PriorityQueue<string, int>();      // element, then priority; smallest priority first
byDue.Enqueue("Dune", 14);
byDue.Enqueue("Emma", 3);
byDue.Enqueue("Ulysses", 7);
var next = byDue.Peek();                           // "Emma", without removing it
var title = byDue.Dequeue();                       // "Emma"; Dequeue and Peek throw when empty
while (byDue.TryDequeue(out var t, out var due))   // the element and its priority
    Console.WriteLine($"{t} {due}");               // "Ulysses 7", then "Dune 14"

var maxHeap = new PriorityQueue<int, int>(Comparer<int>.Create((a, b) => b.CompareTo(a)));
var byDueThenId = new PriorityQueue<string, (int Due, int Id)>();   // tuples compare field by field
```

Equal priorities are not guaranteed to come out first in, first out; if that matters, add a sequence number to the priority tuple. For "the k largest", keep a min-heap of size k. `EnqueueDequeue` adds an item and removes the smallest in one step, cheaper than the two calls:

```csharp
static int KthLargest(int[] nums, int k)
{
    var heap = new PriorityQueue<int, int>();      // a min-heap of the k largest so far
    foreach (var x in nums)
    {
        if (heap.Count < k) heap.Enqueue(x, x);
        else heap.EnqueueDequeue(x, x);           // add x, then remove the smallest, in one step
    }
    return heap.Peek();
}
```

**The queue cannot update a priority.** There is no decrease-key, and the `Remove` added in .NET 9 scans the whole queue. For Dijkstra's algorithm, use lazy deletion: on a shorter path, enqueue the node again with the new distance, and skip any dequeued entry worse than the best known.

```csharp
static int[] ShortestFrom(List<(int To, int Cost)>[] graph, int source)
{
    var dist = new int[graph.Length];
    Array.Fill(dist, int.MaxValue);
    dist[source] = 0;
    var heap = new PriorityQueue<int, int>();
    heap.Enqueue(source, 0);
    while (heap.TryDequeue(out var node, out var d))
    {
        if (d > dist[node]) continue;             // stale: a shorter path was found after this was queued
        foreach (var (next, cost) in graph[node])
        {
            if (d + cost < dist[next])
            {
                dist[next] = d + cost;
                heap.Enqueue(next, d + cost);     // queue it again instead of updating the old entry
            }
        }
    }
    return dist;
}
```

The heap can hold one entry per edge, so say O(E log E) in step 6. Unreachable nodes keep `int.MaxValue`, which is never added to, since only finite distances are queued. For a truly updatable queue, `SortedSet<(int Dist, int Node)>` has `Min`, `Remove` and `Add` in O(log n).

### Mistakes when coming from the other languages

Each of these fails to compile or gives a wrong answer, and costs minutes.

**From TypeScript.** `7 / 2` is `3`, so an average of `int` values needs a cast before dividing. `Substring(1, 4)` takes a length; `s[1..4]` is the slice you meant. A missing key throws instead of returning `undefined`. `'ab'` is an invalid `char` literal: strings need double quotes. An array's `ToString()` prints `System.Int32[]`, so debug with `string.Join(", ", a)`. And numbers that were safe up to 2⁵³ now overflow near 2.1 × 10⁹.

**From Java and Kotlin.** `substring(1, 4)` ends at index 4; C#'s `Substring(1, 4)` takes four characters. `Dictionary` throws where `map.get(k)` returned `null`. `List.Sort` is unstable, where `Collections.sort` and Kotlin's `sortBy` are stable. Kotlin's `1..4` includes 4; C#'s `s[1..4]` stops before it. There is no `Math.floorMod`, so use the formula from the numbers table. `length` and `size()` become `Length` on arrays and strings and `Count` on collections.

**From Go.** C#'s `int` is always 32 bits, while Go's is 64 on the machines you use, so a sum that was fine in Go overflows here. A missing key throws; `GetValueOrDefault` gives Go's zero value. `pts[0].X = 5` on a `List` of structs or tuples does not compile, because the indexer returns a copy; replace the whole element. Arrays are references, so `var b = a` shares the array that Go would copy.

**From Python.** `a[-1]` throws; write `a[^1]`. `//` starts a comment, so `a // b` stops compiling. `%` keeps the sign of the left operand, and integers are not unbounded. `if (count)` does not compile: write `if (count > 0)`. `x in items` is `items.Contains(x)`, O(n) on a `List`. Tuples as dictionary keys work just as in Python.

## Java

Java reads so much like C# that the traps are the same kind: code you half-remember compiles, then does something else. `==` compares references on strings and boxed `Integer` values, `map.get` returns `null` and the `int` you assign it to throws, `Arrays.sort` on an `int[]` takes no comparator, and length is spelled three ways: `a.length`, `s.length()`, `list.size()`. In return the library has a heap, a real deque, sorted maps and records that work as keys. It lacks tuples and a heap that can change a priority.

Everything here runs on Java 21 with `java File.java`, the way the files in `apps/interview-bank` do: the launcher compiles the file in memory and runs the `main` of its first class, with no project. In the round, `import java.util.*;` saves remembering where each type lives; add `java.util.function.*`, `java.util.stream.*`, `java.util.concurrent.*` and `java.util.concurrent.atomic.*` as needed. The short `void main()` is a preview in Java 21, so type the full `public static void main(String[] args)`. Chapter 5 covers the runtime; this section covers only what you type in the round.

### Syntax by heart

These are the structures the problem bank uses, with the costs you will name in step 6.

| Structure | Write it as | Operations to know |
| --- | --- | --- |
| List | `List<Integer> a = new ArrayList<>()` | `add`, `get(i)`, `set(i, x)`, `getLast()`, `removeLast()`, `size()`: O(1), `add` amortized. `add(0, x)`, `remove(0)`, `contains`, `indexOf`: O(n) |
| Array | `int[] a = new int[n]` | `a[i]` and `a.length`, a field with no parentheses: O(1). Zeroed on creation, fixed size |
| Map | `Map<String, Integer> m = new HashMap<>()` | `get`, `getOrDefault`, `put`, `putIfAbsent`, `merge`, `computeIfAbsent`, `containsKey`, `remove`, `size()`: O(1) average. Iteration order is not specified |
| Set | `Set<Integer> s = new HashSet<>()` | `add` (returns `false` if already there), `contains`, `remove`, `size()`: O(1) average |
| Stack | `Deque<Integer> st = new ArrayDeque<>()` | `push`, `pop`, `peek`: O(1). `pop` throws when empty; `peek` returns `null` |
| Queue | `Deque<Integer> q = new ArrayDeque<>()` | `offer` at the back, `poll` and `peek` at the front: O(1). Both return `null` when empty |
| Deque | `Deque<Integer> d = new ArrayDeque<>()` | `offerFirst`, `offerLast`, `pollFirst`, `pollLast`, `peekFirst`, `peekLast`: O(1). No indexing, no `null` elements |
| Heap | `new PriorityQueue<Integer>()` | `offer`, `poll`: O(log n). `peek`, `size()`: O(1). Smallest first |
| Grid | `int[][] g = new int[rows][cols]` | `g[r][c]`; `g.length` rows, `g[0].length` columns. Zeroed |
| Pair | a record, `record Cell(int r, int c) {}`, or an `int[]` | `new Cell(r, c)`, `cell.r()`. A record is equal by value, so it works as a key; an `int[]` is not |

`ArrayDeque` is your stack, queue and deque. Leave `Stack` and `LinkedList` to old code: the `Stack` documentation itself points to `Deque`, and `ArrayDeque`'s says it is likely to be faster than either in its role. Generics take only objects, so `List<int>` does not compile; write `List<Integer>`, or use an `int[]` when the size is fixed.

The everyday moves:

```java
List<Integer> copies = new ArrayList<>();
copies.add(4);
copies.add(9);
int last = copies.getLast();               // 9, without removing it (Java 21)
copies.removeLast();                       // pop from the end: O(1)

Map<String, Integer> loansPerMember = new HashMap<>();
loansPerMember.put("ana", loansPerMember.getOrDefault("ana", 0) + 1);   // count with a default
loansPerMember.merge("ana", 1, Integer::sum);                           // the same, in one call

Deque<Character> stack = new ArrayDeque<>();
stack.push('(');

stack.pop();                               // pop throws on an empty stack; peek returns null

Deque<Integer> queue = new ArrayDeque<>();
queue.offer(1);                            // in at the back
queue.offer(2);

Deque<Integer> deque = new ArrayDeque<>();

deque.offerFirst(2);

deque.pollLast();                          // O(1) at both ends

int[][] grid = new int[3][4];              // zeroed; grid.length is 3, grid[0].length is 4
```

For a composite key, declare a record, inside the class or even inside the method. As in the C# section, records compare by value and arrays do not:

```java
record Cell(int r, int c) {}

Set<Cell> visited = new HashSet<>();
visited.add(new Cell(0, 1));
boolean found = visited.contains(new Cell(0, 1));    // true: records compare by value

Set<int[]> broken = new HashSet<>();
broken.add(new int[] {0, 1});
boolean lost = broken.contains(new int[] {0, 1});    // false: arrays compare by reference
```

`int[]` is still the quickest pair when nothing looks it up, such as a heap entry or a stack frame. A `Map` hands out `Map.Entry` pairs, read with `getKey()` and `getValue()`; `Map.entry(k, v)` makes one.

In breadth-first search, `HashSet.add` returning a `boolean` makes the "seen" check and the insert one call:

```java
static List<Integer> bfsOrder(Map<Integer, List<Integer>> graph, int start) {
    List<Integer> order = new ArrayList<>();
    Set<Integer> seen = new HashSet<>(List.of(start));
    Deque<Integer> queue = new ArrayDeque<>(List.of(start));
    while (!queue.isEmpty()) {
        int node = queue.poll();
        order.add(node);
        for (int next : graph.getOrDefault(node, List.of()))
            if (seen.add(next)) queue.offer(next);
    }
    return order;
}
```

<Pitfall title="Boxed integers">
Boxing is silent, and three bugs come with it. `==` on two `Integer` values compares references: values from −128 to 127 are cached, so `a == b` passes small tests, while two boxed 1000s are different objects on a default JVM. Write `a.equals(b)`. `int c = counts.get("zoe")` throws `NullPointerException` for a missing key, because `null` cannot unbox. And `list.remove(1)` on a `List<Integer>` removes index 1, not the value 1; write `list.remove(Integer.valueOf(1))`.
</Pitfall>

### Strings and characters

Strings are immutable, and `s.charAt(i)` returns a `char`, a UTF-16 code unit. Arithmetic on a `char` gives an `int`; cast back with `(char)`.

```java
String s = "Shelfwise";
char first = s.charAt(0);                  // 'S'
char lastCh = s.charAt(s.length() - 1);    // 'e'
String part = s.substring(1, 4);           // "hel": begin and end, end excluded
int pos = s.charAt(1) - 'a';               // 7: char minus char is an int
char letter = (char) ('a' + 7);            // 'h': cast back to char
int digit = '7' - '0';                     // 7
char[] chars = s.toCharArray();            // a copy you can change; new String(chars) turns it back
String[] words = "  two   words ".trim().split("\\s+");   // ["two", "words"]
String padded = String.format("%03d", 7);  // "007"
String reversed = new StringBuilder("stressed").reverse().toString();   // "desserts"
String joined = String.join(", ", List.of("a", "b", "c"));             // "a, b, c"
```

`String.join` takes strings only; print an `int[]` with `Arrays.toString(a)`. Build long strings with `StringBuilder` (`append`, `setCharAt`, `deleteCharAt`, then `toString()`). For letter counts, `new int[26]` with `counts[ch - 'a']++`, compared with `Arrays.equals`, never `==`.

Compare strings with `equals`. `==` compares references, and often passes anyway because identical literals are one object:

```java
String typed = new StringBuilder("du").append("ne").toString();
boolean same = typed == "dune";            // false: two different objects
boolean equal = typed.equals("dune");      // true
```

<Pitfall title="split takes a regular expression">
`split` reads its argument as a regex and drops trailing empty strings. `"a.b.c".split(".")` returns an empty array, because `.` matches every character; write `split("\\.")`. `"a,b,,".split(",")` gives `["a", "b"]`; pass a limit of `-1` to keep the empty fields. A leading separator does give a leading `""`, so `trim()` before splitting on `"\\s+"`.
</Pitfall>

### Sorting with a comparator

`Arrays.sort` on a primitive array sorts ascending and has no comparator overload: `Arrays.sort(nums, (a, b) -> b - a)` on an `int[]` does not compile. Object arrays and lists take one, and an `int[][]` is an array of objects:

```java
int[] nums = {10, 9, 1};
Arrays.sort(nums);                                  // [1, 9, 10], in place; int[] takes no comparator
Integer[] boxed = {10, 9, 1};
Arrays.sort(boxed, Comparator.reverseOrder());      // [10, 9, 1]: an Integer[] does
int[][] intervals = {{5, 6}, {1, 3}, {2, 4}};
Arrays.sort(intervals, (a, b) -> Integer.compare(a[0], b[0]));   // int[][] is an array of objects
```

For an `int[]` in descending order, sort it and read it backwards. Use `Integer.compare` in comparators, not `a - b`, which overflows: `[1, Integer.MIN_VALUE, 5]` sorted with `(a, b) -> a - b` comes out as `[1, 5, -2147483648]`. Chain keys with `Comparator`'s factory methods:

```java
record Loan(String member, int due) {}

loans.sort(Comparator.comparingInt(Loan::due).thenComparing(Loan::member));   // bob, ana, eve
loans.sort(Comparator.comparingInt(Loan::due).reversed());                     // latest first; ties keep their order
loans.sort(Comparator.comparingInt(Loan::due).thenComparing(Loan::member, Comparator.reverseOrder()));
```

`reversed()` reverses the whole chain so far; to reverse only the second key, pass `Comparator.reverseOrder()` to `thenComparing`. Prefer method references: `Comparator.comparingInt(l -> l.due()).reversed()` does not compile, because Java can no longer infer that `l` is a `Loan`. Write `(Loan l) -> l.due()` if you need a lambda.

Strings sort in ordinal order, by UTF-16 code unit: `["b", "a", "B", "A"]` becomes `A, B, a, b`, usually what a problem means by "lexicographic". `List.sort`, `Collections.sort` and `Arrays.sort` on objects are guaranteed stable, unlike C#. For primitive arrays the documentation names a dual-pivot quicksort; stability cannot matter there, since equal `int` values are indistinguishable.

```java
int[][] dirs = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

for (int i = 0; i < titles.length; i++) { /* index and value */ }
for (String t : titles) { /* values */ }
```

### Numbers

`int` is 32 bits and `long` is 64. Overflow wraps silently; instead of C#'s `checked`, there are the `Math.*Exact` methods:

```java
int a = 50_000, b = 50_000;
int wrong = a * b;                    // -1794967296, and no error
long stillWrong = a * b;              // the same: the multiplication happens in int
long right = (long) a * b;            // 2500000000
int boom = Math.multiplyExact(a, b);  // throws ArithmeticException
long big = 3_000_000_000L;            // without the L, this does not compile
```

If values can pass about 2.1 × 10⁹, say so in step 2 and use `long`; beyond 64 bits there is `java.math.BigInteger`.

| You want | Write | Note |
| --- | --- | --- |
| Integer division toward zero | `a / b` | `-7 / 2` is `-3`, and `7 / 2` is `3` |
| A real quotient | `(double) a / b` | Cast before dividing; `(double) (a / b)` is already truncated |
| Integer division rounding down | `Math.floorDiv(a, b)` | `-4` for `-7` and `2`, like Python's `//` |
| Remainder | `a % b` | Takes the sign of `a`: `-7 % 3` is `-1` |
| Always-positive modulo | `Math.floorMod(a, m)` | `2` for `-7` and `3`; the result takes the sign of `m` |
| Midpoint | `lo + (hi - lo) / 2` | `(lo + hi) / 2` can overflow |
| Sentinels | `Integer.MAX_VALUE`, `Integer.MIN_VALUE`, `Long.MAX_VALUE` | `MAX_VALUE + 1` wraps to `MIN_VALUE`: never add to a sentinel |
| Checked arithmetic | `Math.addExact`, `Math.multiplyExact`, `Math.toIntExact` | Throw `ArithmeticException` instead of wrapping |
| Absolute value | `Math.abs(x)` | Stays negative for `Integer.MIN_VALUE`; `Math.absExact` throws |

`Integer.parseInt("12a")` throws `NumberFormatException`, and so does `Integer.parseInt(" 42 ")`: unlike C#, whitespace is not allowed, so `strip()` first. A value past `Integer.MAX_VALUE` throws too; use `Long.parseLong`. There is no `TryParse`, so you catch the exception. When the problem defines the format, as 038 does, parse by hand.

### Errors

Java alone in this book has checked exceptions (Chapter 5), which every caller must catch or declare. In an interview, throw unchecked ones: `IllegalArgumentException` for bad input, `IllegalStateException` for a call at the wrong time, or your own nested class that extends `RuntimeException`:

```java
static final Map<Integer, String> shelf = Map.of(1, "Dune, copy 1");

static String findCopy(int id) {
    String copy = shelf.get(id);
    if (copy == null) throw new NotFoundException("copy " + id + " not found");
    return copy;
}

static String findCopyOrNull(int id) {
    try {
        return findCopy(id);
    } catch (NotFoundException e) {
        return null;          // anything else keeps propagating: don't catch Exception here
    }
}

static class NotFoundException extends RuntimeException {
    NotFoundException(String message) { super(message); }
}
```

For "may be missing" in a return type, the library's answer is `Optional.ofNullable(shelf.get(id))`, read with `orElse`. When you call something that throws a checked exception, such as `Thread.sleep` or `Future.get`, `main(String[] args) throws Exception` is acceptable in a round. A lambda passed as a `Function` or `Runnable` cannot throw one at all; a `Callable` can. Unlike C#, `throw e;` keeps the original stack trace, which Java records when the exception is created.

### Concurrency basics

Platform threads are OS threads; Java 21 adds virtual threads, which the JVM parks cheaply while they block (Chapter 5). Either way, shared variables can race, so the tools are those of C#: `AtomicInteger` for a number, a lock for anything bigger, or a concurrent collection. Work goes to an `ExecutorService`, which is `AutoCloseable` since Java 19: closing it waits for the submitted tasks.

```java
try (ExecutorService exec = Executors.newVirtualThreadPerTaskExecutor()) {
    Future<String> book = exec.submit(() -> loadBook(7));     // both calls start here
    Future<String> member = exec.submit(() -> loadMember(3));
    System.out.println(member.get() + " borrows " + book.get());   // get blocks until each is done
}

CompletableFuture<String> book = CompletableFuture.supplyAsync(() -> loadBook(7));
CompletableFuture<String> member = CompletableFuture.supplyAsync(() -> loadMember(3));
String line = book.thenCombine(member, (b, m) -> m + " borrows " + b).join();   // join: no checked exception
```

`Future.get` throws the checked `ExecutionException`, wrapping whatever the task threw; `join` throws an unchecked one. `CompletableFuture.allOf(...)` waits for many.

The TypeScript `mapLimit` translates directly, with an `AtomicInteger` in place of `next++`. `getAndIncrement` reads and increments in one atomic step, so each index goes to exactly one worker:

```java
static <T, R> List<R> mapLimit(List<T> items, int limit, Function<T, R> fn) throws Exception {
    List<R> results = new ArrayList<>(Collections.nCopies(items.size(), null));
    AtomicInteger next = new AtomicInteger();
    try (ExecutorService pool = Executors.newFixedThreadPool(limit)) {
        List<Future<?>> workers = new ArrayList<>();
        for (int w = 0; w < Math.min(limit, items.size()); w++)
            workers.add(pool.submit(() -> {
                int i;
                while ((i = next.getAndIncrement()) < items.size())
                    results.set(i, fn.apply(items.get(i)));   // each index goes to one worker
            }));
        for (Future<?> f : workers) f.get();   // wait, and rethrow a worker's failure
    }
    return results;
}
```

With virtual threads, the idiomatic version starts a thread per item and lets a `Semaphore` admit `limit` at a time:

```java
static <T, R> List<R> mapLimitGate(List<T> items, int limit, Function<T, R> fn) throws Exception {
    Semaphore gate = new Semaphore(limit);
    try (ExecutorService exec = Executors.newVirtualThreadPerTaskExecutor()) {
        List<Future<R>> futures = new ArrayList<>();
        for (T item : items)
            futures.add(exec.submit(() -> {
                gate.acquire();                // at most `limit` threads get past here
                try { return fn.apply(item); }
                finally { gate.release(); }
            }));
        List<R> results = new ArrayList<>();
        for (Future<R> f : futures) results.add(f.get());   // in input order
        return results;
    }
}
```

Both keep results in input order. A fixed pool of `limit` threads with one task per item also works: the pool size is the limit. For other shared state:

```java
AtomicInteger total = new AtomicInteger();
try (ExecutorService pool = Executors.newFixedThreadPool(8)) {
    for (int w = 0; w < 8; w++)
        pool.submit(() -> { for (int k = 0; k < 100_000; k++) total.incrementAndGet(); });
}                                          // close() waits for every task to finish
// total.get() is 800000; a plain int[] counter with ++ loses updates

Map<String, Integer> counts = new ConcurrentHashMap<>();
counts.merge("ana", 1, Integer::sum);      // atomic on a ConcurrentHashMap

ReentrantLock lock = new ReentrantLock();
lock.lock();
try { loansPerMember.merge("ana", 1, Integer::sum); }
finally { lock.unlock(); }
```

On Java 21 a virtual thread that blocks inside `synchronized` pins its carrier thread, which is why Chapter 5 prefers `ReentrantLock`.

<InterviewLens>
"Why `AtomicInteger` and not a `volatile int`?" `volatile` makes writes visible, but `next++` is still a read, an add and a write: two workers can read the same value, so one item runs twice and another never runs. `getAndIncrement` is one atomic step. Then say why the plain `List` is safe: each slot has one writer, `set` never resizes it, and `f.get()` makes every write visible before `mapLimit` returns.
</InterviewLens>

### The heap

`PriorityQueue<E>` is a min-heap whose elements are their own priorities, as in Python and unlike C#. Pass a comparator for anything else:

```java
PriorityQueue<Integer> minHeap = new PriorityQueue<>(List.of(14, 3, 7));
int smallest = minHeap.peek();             // 3, without removing it; peek and poll return null when empty
PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Comparator.reverseOrder());
PriorityQueue<Integer> alsoMax = new PriorityQueue<>((a, b) -> Integer.compare(b, a));

PriorityQueue<int[]> byDue = new PriorityQueue<>((a, b) -> Integer.compare(a[0], b[0]));   // {day, copyId}
byDue.offer(new int[] {14, 101});
byDue.offer(new int[] {3, 102});
byDue.offer(new int[] {7, 103});
while (!byDue.isEmpty()) {
    int[] e = byDue.poll();
    System.out.println(e[0] + " " + e[1]);      // "3 102", then "7 103", then "14 101"
}
```

With more fields, a record such as `Due(int day, String title)` and `Comparator.comparingInt(Due::day).thenComparing(Due::title)` reads better. Ties come out in no guaranteed order, so add a tie-breaker when order matters. Printing a heap or looping over it shows the internal array order (`minHeap` above prints `[3, 14, 7]`); only `poll` gives sorted order. For "the k largest", keep a min-heap of size k:

```java
static int kthLargest(int[] nums, int k) {
    PriorityQueue<Integer> heap = new PriorityQueue<>();   // a min-heap of the k largest so far
    for (int x : nums) {
        heap.offer(x);
        if (heap.size() > k) heap.poll();                  // drop the smallest
    }
    return heap.peek();
}
```

**The queue cannot update a priority.** There is no decrease-key, and `remove(Object)` is a linear scan. For Dijkstra's algorithm, use lazy deletion as in the C# section: push the node again with the new distance, and skip stale entries.

```java
static int[] shortestFrom(List<List<int[]>> graph, int source) {   // graph.get(u) holds {to, cost}
    int[] dist = new int[graph.size()];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[source] = 0;
    PriorityQueue<int[]> heap = new PriorityQueue<>(Comparator.comparingInt(e -> e[0]));   // {dist, node}
    heap.offer(new int[] {0, source});
    while (!heap.isEmpty()) {
        int[] top = heap.poll();
        int d = top[0], node = top[1];
        if (d > dist[node]) continue;             // stale: a shorter path was found after this was queued
        for (int[] edge : graph.get(node)) {
            int next = edge[0], nd = d + edge[1];
            if (nd < dist[next]) {
                dist[next] = nd;
                heap.offer(new int[] {nd, next});   // queue it again instead of updating the old entry
            }
        }
    }
    return dist;
}
```

As in C#, say O(E log E). For a truly updatable queue, a `TreeSet<int[]>` ordered by distance, then node, has `first()`, `remove` and `add` in O(log n).

| `IntStream.range(0, n)` | A range; `boxed().toList()` makes it a list |
| `Arrays.fill(a, -1)`, `a.clone()`, `Arrays.copyOfRange(a, lo, hi)` | Filling, and copying an input you must not change |
| `Arrays.toString(a)`, `Arrays.deepToString(grid)` | Printing arrays while debugging |
| `Arrays.stream(a).sum()`, `.max().getAsInt()` | Folds in one call; `max` returns an `OptionalInt` |
| `List.of(...)`, `Map.of(...)`, `Set.of(...)` | Quick immutable collections; no `null`, and `Set.of` throws on duplicates |
| `Collectors.groupingBy(f, Collectors.counting())` | Counting and grouping into a `Map` |
| `Arrays.binarySearch(a, x)` | Binary search; a negative result is `-(insertionPoint) - 1` |
| `TreeMap`, `TreeSet` | Sorted data with `floorKey`, `ceilingKey`, `firstKey`, `pollFirst`, `headMap` in O(log n) |

### Mistakes when coming from the other languages

Each of these fails to compile or gives a wrong answer, and costs minutes.

**From TypeScript.** `==` on strings compares references; use `equals`. `7 / 2` is `3`. A missing key gives `null`, and assigning it to an `int` throws. Lists use `get(i)`, not `a[i]`, and there is no `at(-1)`. `<` does not compile on strings: use `compareTo`. Printing an array shows `[I@` and a hash. Numbers that were safe up to 2⁵³ now overflow near 2.1 × 10⁹.

**From C#.** `substring(1, 4)` ends at index 4, where `Substring(1, 4)` takes four characters. `map.get` returns `null` where the indexer throws. `==` on strings compares references, not text. There are no value tuples: write a record. `PriorityQueue` takes one type parameter, not an element and a priority. `Math.abs(Integer.MIN_VALUE)` stays negative instead of throwing. `Thread.sleep` needs a `throws` or a `catch`.

**From Kotlin.** `==` is Kotlin's `===`, so strings and boxed numbers need `equals`. `List.of` and `new ArrayList<>()` are both just `List`, and `add` on the immutable one throws `UnsupportedOperationException`. There are no ranges: write the counted `for`. Record accessors need parentheses, `p.x()`, and there is no `copy`. Checked exceptions exist.

**From Go.** A missing key returns `null`, not a zero value; use `getOrDefault`. `int` is always 32 bits, so a sum that was fine in Go overflows. There are no multiple return values: return a record or an `int[]`. `int[] b = a` shares the array that Go would copy; use `a.clone()`. `charAt` indexes UTF-16 units, not bytes.

**From Python.** `a[-1]` throws. `//` starts a comment; `%` keeps the sign of the left operand, so use `Math.floorMod`. Integers are bounded. `x in items` is `items.contains(x)`, O(n) on a `List`. `if (count)` does not compile. `"ab" * 3` is `"ab".repeat(3)`.

### Writing and running a quick test

Every Java file in the bank is one class with static methods and a `main` that calls a `check` helper. Here is that `main` for problem 002, with an `expectThrows` helper added for the `findCopy` example:

```java
public static void main(String[] args) {
    check(Arrays.equals(twoPrices(new int[] {12, 7, 3, 9, 5}, 12), new int[] {2, 3}));
    check(twoPrices(new int[] {1, 2}, 10).length == 0);
    expectThrows(NotFoundException.class, () -> findCopy(2));
    System.out.println("002 ok");
}

static void check(boolean ok) {
    if (!ok) throw new AssertionError("test failed");
}

static void expectThrows(Class<? extends Throwable> type, Runnable act) {
    try {
        act.run();
    } catch (Throwable e) {
        if (type.isInstance(e)) return;
        throw new AssertionError("expected " + type.getSimpleName() + ", got " + e);
    }
    throw new AssertionError("expected " + type.getSimpleName());
}
```

`java P002TwoPrices.java` runs the file; a failing `check` throws, and the stack trace gives the line. The bank avoids Java's `assert` because assertions are off unless you run `java -ea`: without the flag, a failing `assert` passes in silence.

To see which case failed, put the cases in a list of records:

```java
record Case(int[] prices, int budget, int[] want) {}

List<Case> cases = List.of(
    new Case(new int[] {12, 7, 3, 9, 5}, 12, new int[] {2, 3}),
    new Case(new int[] {4, 4, 1}, 8, new int[] {0, 1}),
    new Case(new int[] {1, 2}, 10, new int[] {}),
    new Case(new int[] {}, 5, new int[] {}));

for (Case c : cases) {
    int[] got = twoPrices(c.prices(), c.budget());
    if (!Arrays.equals(got, c.want()))
        throw new AssertionError("twoPrices(" + Arrays.toString(c.prices()) + ", " + c.budget() + ") = "
            + Arrays.toString(got) + ", want " + Arrays.toString(c.want()));
}
```

A record holding arrays compares them by reference, so compare the fields with `Arrays.equals`, not the records. The message names the failing row. A real project would make it a JUnit 5 `@ParameterizedTest` fed by a `@MethodSource`, run by Maven or Gradle (Chapter 17); in the round, one file is enough. When the editor cannot run code, write the table as comments and trace each row by hand, as in step 5.

## Kotlin

Kotlin is the easiest language in this chapter to half-know. If you have read the Java section, you know its runtime library already: the same `HashMap`, the same `PriorityQueue`, the same 32-bit `Int` that wraps without a word. What Kotlin changes is everything you type around them. Collections are read-only or mutable, a missing map key is a `null` the compiler makes you handle, `==` calls `equals`, ranges include their end, and there is no C-style `for` loop and no ternary operator. The traps are the places where Kotlin looks like the language you came from and means something else.

Everything here compiles with Kotlin 2.1 on JDK 21, standard library only, the way the files in `apps/interview-bank` do. Chapter 6 covers the language; this section covers only what you type in the round.

### Syntax by heart

These are the structures the problem bank uses, with the costs you will name in step 6.

| Structure | Write it as | Operations to know |
| --- | --- | --- |
| List | `val a = mutableListOf<Int>()`, or `IntArray(n)` for a fixed size | `add`, `a[i]`, `a.last()`, `removeLast()`, `size`: O(1). `add(0, x)`, `removeAt(0)`, `x in a`, `indexOf`: O(n) |
| Map | `val m = HashMap<String, Int>()` | `m[k]` (`null` when missing), `m[k] = v`, `getOrDefault`, `getOrPut`, `k in m`, `remove`, `size`: O(1) average. `mutableMapOf()` is a `LinkedHashMap` and keeps insertion order |
| Set | `val s = HashSet<Int>()` | `add` (returns `false` if already there), `x in s`, `remove`: O(1) average |
| Stack | `ArrayDeque<Char>()` | `addLast`, `removeLast`, `last()`: O(1). `removeLast` throws when empty; `removeLastOrNull` returns `null` |
| Queue | `ArrayDeque<Int>()` | `addLast`, `removeFirst`, `first()`: O(1) |
| Deque | `ArrayDeque<Int>()` | O(1) at both ends, and `d[i]` is O(1) too |
| Heap | `PriorityQueue<Int>()`, imported from `java.util` | `add`, `poll`, `peek`, as in the Java section |
| Grid | `Array(rows) { IntArray(cols) }` | `g[r][c]`, `g.size`, `g[0].size` |
| Pair | `r to c`, `Pair(r, c)`, `Triple`, or a `data class` | Destructure with `val (r, c) = cell`. Equal by value, so it works as a key |

`ArrayDeque` with no import is `kotlin.collections.ArrayDeque`, Kotlin's own ring buffer. It is a stack, a queue and a deque, and it can be indexed, so you never need `java.util.Stack` or `LinkedList`. Import `java.util.PriorityQueue` by name: `import java.util.*` takes priority over the default imports, and `ArrayDeque` silently becomes Java's, which has no indexing.

Three types look like "an array of ints". `IntArray` is Java's `int[]`: fixed size, unboxed, zeroed, and the type in every bank signature (`intArrayOf(1, 2)`, `IntArray(n) { it * 2 }`). `Array<Int>` is a boxed `Integer[]`, rarely what you want except as the outer type of a grid. `List<Int>` is read-only and has no `add`; `MutableList<Int>` is the one you change. Convert with `toList()`, `toMutableList()` and `toIntArray()`. `val` stops you reassigning the variable, not changing the list.

The everyday moves:

```kotlin
val copies = mutableListOf<Int>()
copies.add(4)
copies += 9                                // the same as add
val top = copies.last()                    // 9, without removing it
val popped = copies.removeLast()           // 9

val loansPerMember = HashMap<String, Int>()
loansPerMember["ana"] = (loansPerMember["ana"] ?: 0) + 1       // count with a default
loansPerMember["ana"] = loansPerMember.getOrDefault("ana", 0) + 1
val byAuthor = HashMap<String, MutableList<String>>()
byAuthor.getOrPut("Le Guin") { mutableListOf() }.add("Earthsea")  // group without an if

val seen = mutableSetOf(3, 1, 3)           // [3, 1]
val added = seen.add(7)                    // true; false if 7 was already there

val visited = hashSetOf(0 to 1)            // a Pair: equal by value
val found = (0 to 1) in visited            // true
val cells = hashSetOf(Cell(2, 3))          // data class Cell(val r: Int, val c: Int)

val stack = ArrayDeque<Char>()
stack.addLast('(')
val peek = stack.last()                    // '(' without removing it
val ch = stack.removeLastOrNull()          // '('; null on an empty stack, where removeLast throws

val deque = ArrayDeque<Int>()
deque.addLast(5)
deque.addFirst(2)
val front = deque.first()                  // 2
deque.removeLast()                         // O(1) at both ends

val grid = Array(3) { IntArray(4) }        // 3 rows of 4 zeros; grid[r][c]
```

`getOrPut` is the one to memorise: it returns the existing value or stores a new one, which removes the `if` from every grouping and adjacency-list problem.

There is no ternary operator, because `if` is an expression. `when` replaces `switch` and also replaces a chain of `else if`:

```kotlin
val bigger = if (a > b) a else b           // no ternary: if is an expression
val kind = when {
    ch.isDigit() -> "digit"
    ch in 'a'..'z' -> "lower"
    else -> "other"
}
val result = when (op) {
    "+" -> a + b
    "-" -> a - b
    else -> error("unknown operator $op")
}
```

In breadth-first search, `ArrayDeque` is the queue, and since a set's `add` returns a `Boolean`, the "seen" check and the insert are one call:

```kotlin
fun bfsOrder(graph: Map<Int, List<Int>>, start: Int): List<Int> {
    val order = mutableListOf<Int>()
    val seen = hashSetOf(start)
    val queue = ArrayDeque(listOf(start))
    while (queue.isNotEmpty()) {
        val node = queue.removeFirst()
        order.add(node)
        for (next in graph[node].orEmpty())
            if (seen.add(next)) queue.addLast(next)
    }
    return order
}
```

<FromTS title="Equality compares content">
In Kotlin `==` calls `equals`, so strings, lists, pairs and data classes compare by content, and `===` is the reference check. That is why `Pair` and data classes work as `HashSet` and `HashMap` keys with no `"r,c"` strings. Arrays are the exception: `IntArray` keeps Java's reference equality, so two arrays with the same values are not `==`.
</FromTS>

<Pitfall title="Checking an array result">
`check(twoPrices(prices, 12) == intArrayOf(2, 3))` always fails, and `println(result)` prints something like `[I@7b23ec81`. Compare arrays with `contentEquals` and print them with `contentToString()`, or turn them into lists with `toList()`, which compare and print by content.
</Pitfall>

### Strings and characters

Strings are immutable, and `s[i]` is a `Char`, a UTF-16 code unit as in Java. `Char` minus `Char` is an `Int` and `Char` plus `Int` is a `Char`, so you need no casts. Single quotes make a `Char`, and `"a" == 'a'` does not compile.

```kotlin
val s = "Shelfwise"
val first = s[0]                           // 'S', a Char
val lastCh = s.last()                      // 'e'
val part = s.substring(1, 4)               // "hel", end index excluded
val alsoPart = s.substring(1..3)           // "hel": a range includes its end
val pos = s[1] - 'a'                       // 7: Char minus Char is an Int
val letter = 'a' + 7                       // 'h': Char plus Int is a Char
val code = s[1].code                       // 104
val fromCode = Char(104)                   // 'h'
val digit = '7'.digitToInt()               // 7, the same as '7' - '0'
val words = "  two   words ".trim().split(Regex("\\s+"))     // [two, words]
val padded = "7".padStart(3, '0')          // "007"
val reversed = "stressed".reversed()       // "desserts"
val joined = listOf(1, 2, 3).joinToString(", ")             // "1, 2, 3"
val sortedKey = "listen".toCharArray().sorted().joinToString("")   // "eilnst"
```

`take(n)`, `drop(n)` and `takeLast(n)` save index arithmetic and never throw on short strings. `split` with a string splits on that literal text, not a regular expression, and keeps empty fields: `"a,b,,".split(",")` has four elements. Pass a `Regex` for a pattern. Use templates (`"next: ${n + 1}"`) instead of concatenation, and `buildString { append(ch).append(count) }` for long strings.

For letter counts, `IntArray(26)` and `counts[ch - 'a']++` is the standard move; compare two count arrays with `contentEquals`. `s.groupingBy { it }.eachCount()` gives a `Map<Char, Int>` when the alphabet is open. `ch.isDigit()` accepts any Unicode digit, while `ch in '0'..'9'` is the strict ASCII test. `<` works on strings and compares by code unit, so `"B" < "a"` and `sorted()` give the ordinal order most problems mean.

### Sorting with a comparator

`sort()` sorts a `MutableList` or an array in place. `sorted()` returns a new `List`, and on an `IntArray` that list is a `List<Int>`; use `sortedArray()` to keep the array type. A read-only `List` has no `sort` at all.

```kotlin
val nums = intArrayOf(10, 9, 1)
nums.sort()                                     // [1, 9, 10], in place
val desc = nums.sortedDescending()              // [10, 9, 1], a new List<Int>
val copy = nums.sortedArray()                   // a sorted IntArray copy

val loans = mutableListOf(Loan("cy", 3), Loan("ana", 7), Loan("bo", 3))
loans.sortBy { it.due }                         // in place, stable: cy stays before bo
val ordered = loans.sortedWith(compareBy<Loan> { it.due }.thenBy { it.member })
val sameOrder = loans.sortedWith(compareBy({ it.due }, { it.member }))
val latestFirst = loans.sortedWith(compareByDescending<Loan> { it.due }.thenBy { it.member })
loans.sortWith { a, b -> if (a.due != b.due) a.due.compareTo(b.due) else a.member.compareTo(b.member) }

data class Loan(val member: String, val due: Int)
```

`compareBy` with one or more selectors is the shortest correct comparator; it needs `compareBy<Loan>` only when nothing else gives the compiler the type, as before `thenBy`. List sorts are stable, as in the Java section. Write comparators with `compareTo`, never `a - b`: `listOf(1, Int.MIN_VALUE, 5).sortedWith { a, b -> a - b }` returns `[1, 5, -2147483648]`. `Pair` is not `Comparable`, so `pairs.sorted()` does not compile; write `pairs.sortedWith(compareBy({ it.first }, { it.second }))`.

<Pitfall title="A sorted() that sorts nothing">
`xs.sorted()` on its own line compiles, runs and leaves `xs` as it was: it returns a new list, which you threw away, and the compiler does not warn. Write `xs.sort()` to sort in place or `val ys = xs.sorted()` for a copy.
</Pitfall>

### Iteration

There is no `for (int i = 0; i < n; i++)`. Every counted loop goes over a range:

```kotlin
for (i in 0 until n) { }                   // 0 to n - 1
for (i in 0..<n) { }                       // the same
for (i in 0..n) { }                        // 0 to n: n included
for (i in titles.indices) { }              // every valid index
for ((i, t) in titles.withIndex()) { }     // index and value
for (i in n - 1 downTo 0) { }              // backwards
for (i in 0 until 10 step 3) { }           // 0, 3, 6, 9
for ((title, count) in stock) { }          // a Map: each entry destructures
for ((dr, dc) in dirs) { }                 // dirs = listOf(1 to 0, -1 to 0, 0 to 1, 0 to -1)
repeat(3) { }                              // three times, with the counter as it
```

`10..0` is an empty range, not a countdown, so the loop runs zero times; use `downTo`. To leave nested loops, label the outer one: `outer@ for (...)`, then `break@outer` or `continue@outer`. A bare `return` inside `forEach { }` returns from the enclosing function, not from the lambda, so use a `for` loop when you need `break`. Adding to a list inside its own `for` throws `ConcurrentModificationException`, as in Java; `removeAll { it % 2 == 0 }` removes in place.

### Numbers

`Int` is 32 bits and `Long` is 64, and overflow wraps silently, as in the Java section. What Kotlin adds is that it never widens for you:

```kotlin
val a = 50_000
val b = 50_000
val wrong = a * b                          // -1794967296, and no error
val right = a.toLong() * b                 // 2500000000
val big = 3_000_000_000                    // too big for Int, so inferred as Long
```

`val total: Long = a * b` does not compile, where Java compiles it and gets it wrong; `val x = a * b` is wrong in both. Convert one operand before multiplying. `Math.multiplyExact` throws on overflow, and `java.math.BigInteger` goes past 64 bits.

| You want | Write | Note |
| --- | --- | --- |
| Integer division toward zero | `a / b` | `-7 / 2` is `-3`, and `7 / 2` is `3` |
| A real quotient | `a.toDouble() / b` | Convert before dividing |
| Integer division rounding down | `a.floorDiv(b)` | `(-7).floorDiv(2)` is `-4`, like Python's `//` |
| Remainder | `a % b` | Takes the sign of `a`: `-7 % 3` is `-1` |
| Always-positive modulo | `a.mod(m)` | `(-7).mod(3)` is `2`; without the parentheses, `-7.mod(3)` is `-(7.mod(3))`, which is `-1` |
| Midpoint | `lo + (hi - lo) / 2` | `(lo + hi) / 2` overflows once the sum passes `Int.MAX_VALUE` |
| Sentinels | `Int.MAX_VALUE`, `Int.MIN_VALUE`, `Long.MAX_VALUE` | `Int.MAX_VALUE + 1` wraps to `Int.MIN_VALUE` |
| Bits | `1 shl k`, `x shr 1`, `x ushr 1`, `x and 1`, `x or y`, `x xor y`, `x.inv()` | Kotlin has no `<<` or `&` operators; these are infix functions |
| Larger, smaller | `maxOf(a, b, c)`, `minOf(a, b)` | No import; `abs` needs `import kotlin.math.abs` |

`"42".toInt()` throws `NumberFormatException` on `"12a"` and also on `" 42 "`; `toIntOrNull()` returns `null` instead, which pairs well with `?:`. `"1.5".toDouble()` ignores the machine's locale. When the problem defines what a valid number looks like, as 038 does, parse it by hand.

### Errors

Kotlin has no checked exceptions and no `throws` clause. `throw` and `try` are expressions, so the usual shapes are short:

```kotlin
class NotFoundException(message: String) : RuntimeException(message)

val shelf = mapOf(1 to "Dune, copy 1")

fun findCopy(id: Int): String = shelf[id] ?: throw NotFoundException("copy $id not found")

fun findCopyOrNull(id: Int): String? =
    try {
        findCopy(id)
    } catch (e: NotFoundException) {
        null                                   // anything else keeps propagating
    }

fun loanDays(days: Int): Int {
    require(days in 1..30) { "days must be 1 to 30, was $days" }   // IllegalArgumentException
    return days
}
```

Three standard functions save you writing exception classes: `require(cond) { message }` throws `IllegalArgumentException` for bad arguments, `check(cond) { message }` throws `IllegalStateException` for broken assumptions, and `error(message)` throws `IllegalStateException` with the type `Nothing`, so `map[key] ?: error("no owner")` has the value's type. `runCatching { ... }` catches everything, which suits tests and is too broad in real code.

Know what the library throws: `IndexOutOfBoundsException` for a bad index, `NoSuchElementException` for `first()` or `max()` on an empty collection and `getValue(k)` on a missing key, and `NullPointerException` for `!!`. Each has a partner that returns `null` instead (`getOrNull`, `firstOrNull`, `maxOrNull`, `m[k]`), and that partner plus `?:` is usually the clearer code.

### Concurrency basics

Chapter 6 introduced coroutines, the usual answer in a Kotlin backend. But they live in `kotlinx.coroutines`, a separate library, and a plain `kotlinc` file does not have it, so ask whether the editor includes it. If not, use the JDK as in the Java section, with Kotlin syntax: `thread { }` from `kotlin.concurrent` starts a thread, `synchronized(lock) { }` is a function rather than a keyword, and executors, atomics and concurrent maps come from `java.util.concurrent`.

Bounded concurrency is a fixed-size pool, with one future per item:

```kotlin
import java.util.concurrent.Callable
import java.util.concurrent.Executors

fun <T, R> mapLimit(items: List<T>, limit: Int, fn: (T) -> R): List<R> =
    Executors.newFixedThreadPool(limit).use { pool ->
        val futures = items.map { item -> pool.submit(Callable { fn(item) }) }
        futures.map { it.get() }               // in input order; get() rethrows a task's failure
    }
```

At most `limit` calls run at once, and reading the futures in order keeps results in input order. `use` closes the pool, which waits for its tasks (executors are `AutoCloseable` since JDK 19). A failing task surfaces as an `ExecutionException` whose `cause` is the original error. For I/O-bound work, `Executors.newVirtualThreadPerTaskExecutor()` fits the same `use` block (Chapter 5).

For shared state, the rules are Java's:

```kotlin
val total = AtomicInteger()
val workers = List(8) { thread { repeat(100_000) { total.incrementAndGet() } } }
workers.forEach { it.join() }              // total.get() is 800000; a plain var with ++ loses updates

val counts = ConcurrentHashMap<String, Int>()
counts.merge("ana", 1, Int::plus)          // an atomic count

val lock = Any()
synchronized(lock) { loans["bo"] = (loans["bo"] ?: 0) + 1 }
```

If the editor has `kotlinx.coroutines`, this is the version to write, and the one to name even if it does not:

```kotlin
suspend fun <T, R> mapLimit(items: List<T>, limit: Int, fn: suspend (T) -> R): List<R> = coroutineScope {
    val gate = Semaphore(limit)
    items.map { item -> async { gate.withPermit { fn(item) } } }.awaitAll()
}
```

One coroutine per item; the `Semaphore` (from `kotlinx.coroutines.sync`, not `java.util.concurrent`) admits `limit` at a time. `awaitAll` keeps input order, and `coroutineScope` cancels the other children if one fails. Call it from `runBlocking { }` in `main`.

"Why not coroutines?" They need the `kotlinx.coroutines` dependency, and they pay off for I/O fan-out with timeouts and cancellation; for CPU-bound work a fixed pool the size of the core count is the right tool anyway. Then name the coroutine version: `coroutineScope`, `async`, `awaitAll` and a `Semaphore` with `withPermit`. You have shown the Kotlin answer and where its boundary is.

### The heap

The heap is `java.util.PriorityQueue`, a min-heap, with the caveats of the Java section: `poll` returns `null` when empty, there is no decrease-key, and iteration is not in sorted order. Kotlin makes the comparator shorter:

```kotlin
val byDue = PriorityQueue<Pair<Int, String>>(compareBy { it.first })   // smallest due first
byDue.add(14 to "Dune")
byDue.add(3 to "Emma")
byDue.add(7 to "Ulysses")
val next = byDue.peek()                    // (3, Emma), without removing it
val (due, title) = byDue.poll()            // 3, "Emma"
while (byDue.isNotEmpty()) println(byDue.poll())   // (7, Ulysses), then (14, Dune)

val maxHeap = PriorityQueue<Int>(compareByDescending { it })
val byDueThenTitle = PriorityQueue<Pair<Int, String>>(compareBy({ it.first }, { it.second }))
val cheap = PriorityQueue<IntArray>(compareBy { it[0] })   // [priority, value], no boxing per field
```

`poll()` and `peek()` return a platform type (Chapter 6): the compiler lets you treat the result as non-null, and on an empty heap the `null` becomes a `NullPointerException` as soon as you destructure it or use it as an `Int`. Guard with `isNotEmpty()`. For "the k largest", keep a min-heap of size k:

```kotlin
fun kthLargest(nums: IntArray, k: Int): Int {
    val heap = PriorityQueue<Int>()            // a min-heap of the k largest so far
    for (x in nums) {
        heap.add(x)
        if (heap.size > k) heap.poll()         // drop the smallest
    }
    return heap.peek()
}
```

For Dijkstra's algorithm, use lazy deletion: queue a node again on a shorter path, and skip stale entries when they come out:

```kotlin
fun shortestFrom(graph: List<List<Pair<Int, Int>>>, source: Int): IntArray {
    val dist = IntArray(graph.size) { Int.MAX_VALUE }
    dist[source] = 0
    val heap = PriorityQueue<Pair<Int, Int>>(compareBy { it.first })   // (distance, node)
    heap.add(0 to source)
    while (heap.isNotEmpty()) {
        val (d, node) = heap.poll()
        if (d > dist[node]) continue           // stale: a shorter path was found after this was queued
        for ((next, cost) in graph[node]) {
            if (d + cost < dist[next]) {
                dist[next] = d + cost
                heap.add(dist[next] to next)   // queue it again instead of updating the old entry
            }
        }
    }
    return dist
}
```

The heap can hold one entry per edge, so say O(E log E). For "the largest key at most x", use `java.util.TreeMap` and declare the result nullable: `val floor: Int? = shelves.floorKey(15)`.

| `List(n) { it }`, `IntArray(n) { -1 }`, `(0 until n).toList()` | Building a list or array from its index |
| `a.sum()`, `a.sumOf { }`, `a.maxOf { }`, `a.maxBy { }`, `a.count { }` | Folds in one call; `max()` on an empty list throws, `maxOrNull()` does not |

| `a.scan(0) { acc, x -> acc + x }` | A prefix-sum list of size n + 1 |
| `binarySearch(x)` on a sorted list or array | Binary search; a negative result is `-(insertionPoint) - 1` |
| `buildList { }`, `buildString { }`, `buildMap { }` | Building with mutation, returning a read-only result |
| `intersect`, `union`, `subtract` | Set algebra, returning a new set |
| `getOrNull(i)`, `firstOrNull { }`, `indexOfFirst { }`, `lastIndex` | Lookups that do not throw |
| `x.countOneBits()`, `x.toString(2)`, `"1101".toInt(2)` | Counting bits and binary strings |

### Mistakes when coming from the other languages

Each of these fails to compile or gives a wrong answer, and costs minutes.

**From TypeScript.** There is no `cond ? a : b`; write `if (cond) a else b`. `0..n` includes `n`, so a loop over indices is `0 until n` or `indices`. `7 / 2` is `3` on `Int`. `listOf` gives a list without `add`; start with `mutableListOf`. `m[k] + 1` does not compile because `m[k]` is `Int?`; write `(m[k] ?: 0) + 1`. `'ab'` is not a valid `Char` literal: strings need double quotes.

**From C#.** `substring(1, 4)` ends at index 4 instead of taking four characters, and `1..4` includes 4, unlike C#'s `s[1..4]`. There is no `TryGetValue`: write `m[k]?.let { ... }` or `m[k] ?: default`. There is no `checked`; use `Math.addExact`. Tuples become `Pair`, `Triple` or a data class, and `Pair` does not sort the way a C# tuple does. `PriorityQueue` takes one type and a comparator, not a separate priority.

**From Java.** `==` calls `equals`, so `s1 == s2` is right for strings and boxed numbers, and `===` is Java's `==`. `split(".")` splits on a literal dot, not a regex, and keeps trailing empty strings. On a `MutableList<Int>`, `remove(1)` removes the value 1: on `[5, 7, 1]` Java's `remove(1)` deletes the 7 and Kotlin's deletes the 1. Use `removeAt(1)` for an index. Bit operators are words (`shl`, `and`, `xor`), and `when` never falls through.

**From Go.** A missing key is `null`, not a zero value; add `?: 0` or use `getOrDefault`. `Int` is 32 bits, where Go's `int` is 64 on the machines you use. Arrays and lists are references, so `val b = a` shares; copy with `a.copyOf()` or `toMutableList()`. There are no multiple return values: return a `Pair` or a data class and destructure it.

**From Python.** `a[-1]` throws; write `a.last()`. `//` starts a comment, so floor division is `floorDiv`, and `mod` is the `%` you expect. Integers are not unbounded. `if (items)` does not compile: write `items.isNotEmpty()`. `range(n)` is `0 until n`, not `0..n`. Slices are `subList(1, 3)`, `slice(1..2)` or `substring(1, 3)`. `Pair` works as a dictionary key, as tuples do.

## Go

Go has the fewest features of the six languages, its strength and its trap in a live round. There is little to remember, but much of what the others put in a library you write by hand: there is no set and no deque, and `container/heap` wants five methods before it does anything. The traps are quiet. `append` may or may not share memory with the slice you passed in, a missing map key returns zero, map order changes from run to run, and `s[i]` is a byte. In return, arrays and structs work as map keys, `int` is 64 bits on the machines you will use, and goroutines and channels are part of the language.

Everything here is Go 1.24, the version in the bank's `go.mod`. The bank keeps one package per problem (`go/p002/`, `package p002`) with an exported function and a `_test.go` file, run with `go test ./p002/`; a shared editor usually wants `package main` and `func main()`. Either way, an unused import or variable is a compile error, so delete what you stop using. Chapter 7 covers the language and the runtime; this section covers only what you type in the round.

### Syntax by heart

These are the structures the problem bank uses, with the costs you will name in step 6.

| Structure | Write it as | Operations to know |
| --- | --- | --- |
| List | `a := []int{}`, or `make([]int, 0, n)` | `a = append(a, x)`, `a[i]`, `a[len(a)-1]`, `len(a)`: O(1), `append` amortized. `slices.Contains`, `slices.Index`, `slices.Insert`: O(n) |
| Map | `m := map[string]int{}` | `m[k]`, `v, ok := m[k]`, `m[k] = v`, `delete(m, k)`, `len(m)`: O(1) average. A missing key reads as zero. Order is random |
| Set | `map[int]bool` or `map[int]struct{}` | `s[x] = true`, `if s[x]`, `delete(s, x)`: O(1) average |
| Stack | a slice | `append` to push, `a[len(a)-1]` to peek, `a = a[:len(a)-1]` to pop: O(1) |
| Queue | a slice | `append` to enqueue, `q[0]` then `q = q[1:]` to dequeue: O(1) |
| Deque | a slice, or `container/list` | A slice pops from both ends; `list.List` also pushes at the front: O(1) |
| Heap | `container/heap` over your own slice type | `heap.Push`, `heap.Pop`: O(log n). `h[0]` peeks. `heap.Init`: O(n) |
| Grid | `make([][]int, rows)`, then `make([]int, cols)` per row | `g[r][c]`; `len(g)` rows, `len(g[0])` columns. Zeroed |
| Pair | an array, `[2]int`, or a struct | Compared with `==` by value, so both work as map keys |

`make([]int, n)` gives n zeros; `make([]int, 0, n)` gives an empty slice with room for n. `len` counts elements and `cap` the array underneath. The everyday moves:

```go
copies := []int{}
copies = append(copies, 4)
copies = append(copies, 9)
last := copies[len(copies)-1]   // 9, without removing it
copies = copies[:len(copies)-1] // pop from the end: O(1)

loansPerMember := map[string]int{}
loansPerMember["ana"]++        // a missing key reads as 0, so counting needs no default
n, ok := loansPerMember["zoe"] // 0, false: the two-value form tells "missing" from "zero"
delete(loansPerMember, "ana")  // no error if the key is not there

byAuthor := map[string][]string{}
byAuthor["Herbert"] = append(byAuthor["Herbert"], "Dune") // a missing key is a nil slice, and append accepts it

seen := map[int]bool{3: true, 1: true}
seen[7] = true
isNew := !seen[5] // true: a missing key reads as false

present := map[int]struct{}{} // a set that stores nothing per key
present[7] = struct{}{}
_, has := present[7] // true

stack := []byte{}
stack = append(stack, '(')
top := stack[len(stack)-1] // '(' without removing it; on an empty stack this panics
stack = stack[:len(stack)-1]

queue := []int{1}
queue = append(queue, 2) // in at the back
first := queue[0]        // 1, out at the front
queue = queue[1:]

grid := make([][]int, 3) // 3 nil rows
for r := range grid {
	grid[r] = make([]int, 4) // each row its own zeroed array
}
```

The zero on a missing key is a gift for counting and a trap when zero is a real value: use comma-ok to tell them apart. Writing to a nil map panics, and `var m map[string]int` declares one, so create maps with a literal or `make`. For sets, `map[int]bool` reads better and `map[int]struct{}` stores nothing per key; pick one.

The bug Go is known for comes from the slice header (Chapter 7). Slicing makes a new header over the same array, and `append` writes into that array whenever there is spare capacity:

```go
base := make([]int, 3, 10) // [0 0 0], room for 10
a := append(base, 1)
b := append(base, 2) // writes into the same array as a
fmt.Println(a, b)    // [0 0 0 2] [0 0 0 2]
sub := base[:2]      // a view, not a copy
sub[0] = 7           // base[0] is 7 too
```

In a round it shows up in backtracking. Saving `path` itself saves a header over an array the next step overwrites; with `[1, 2, 3]` the result holds `[2]` twice and no `[3]`. Save a copy:

```go
func subsets(nums []int) [][]int {
	var res [][]int
	var path []int
	var walk func(i int)
	walk = func(i int) {
		if i == len(nums) {
			res = append(res, slices.Clone(path)) // a copy: path's array is about to be reused
			return
		}
		walk(i + 1)                  // without nums[i]
		path = append(path, nums[i]) // with it
		walk(i + 1)
		path = path[:len(path)-1] // undo
	}
	walk(0)
	return res
}
```

For breadth-first search, `q = q[1:]` is the whole queue. It is O(1) but frees nothing at once: dequeued slots stay in the array until a later `append` outgrows it and copies only the live part. At interview sizes that is fine; say so if asked about memory.

```go
func bfsOrder(graph map[int][]int, start int) []int {
	order := []int{}
	seen := map[int]bool{start: true}
	queue := []int{start}
	for len(queue) > 0 {
		node := queue[0]
		queue = queue[1:]
		order = append(order, node)
		for _, next := range graph[node] { // a node with no entry gives a nil slice: zero iterations
			if !seen[next] {
				seen[next] = true
				queue = append(queue, next)
			}
		}
	}
	return order
}
```

The same two reslices give a sliding-window deque: push at the back, drop from the front with `d = d[1:]` and from the back with `d = d[:len(d)-1]`. Pushing at the front of a slice is O(n); when you need it, `container/list` is a doubly linked list whose values are `any`:

```go
d := list.New()
d.PushBack(5)
d.PushFront(2)
front := d.Front().Value.(int) // 2: Value is any, so assert the type back
d.Remove(d.Back())             // O(1) at both ends; Front and Back are nil when empty
```

Composite keys need no work, because arrays and structs compare by value:

```go
type cell struct{ r, c int }

visited := map[cell]bool{{0, 1}: true} // the key type can be left out inside a map literal
visited[cell{2, 3}] = true
found := visited[cell{0, 1}] // true: structs compare field by field

dist := map[[2]int]int{{0, 0}: 0} // an array works too
dist[[2]int{1, 0}] = 1
p := [2]int{1, 0}
q := p                    // arrays and structs copy on assignment
q[0] = 9                  // p is still [1 0]
same := p == [2]int{1, 0} // true: == compares the contents
```

<FromTS title="Keys without strings">
The TypeScript section turns a grid cell into the string `"r,c"`. In Go, `map[[2]int]bool` or a map keyed by a small struct just works, and the compiler checks the key's type. Slices, maps and functions are not comparable, so `map[[]int]bool` does not compile: use the array.
</FromTS>

### Strings and characters

A string is an immutable sequence of bytes, usually UTF-8. `s[i]` is a `byte` and `len(s)` counts bytes, while `range` decodes the string into `rune` values, Unicode code points. The bank uses ASCII unless a problem says otherwise; ask when the input could be any text.

```go
s := "Shelfwise"
first := s[0]                             // 83: a byte, the code of 'S'
part := s[1:4]                            // "hel", end index excluded
pos := int(s[1] - 'a')                    // 7: byte minus byte is a byte
letter := string(rune('a' + pos))         // "h"
digit := int('7' - '0')                   // 7
words := strings.Fields("  two   words ") // [two words]
fields := strings.Split("a,b,,", ",")     // [a b  ]: 4 fields, the empty ones kept
padded := fmt.Sprintf("%03d", 7)          // "007"
text := strconv.Itoa(42)                  // "42"
n, err := strconv.Atoi("12a")             // 0 and an error
runes := []rune("stressed")
slices.Reverse(runes)
reversed := string(runes) // "desserts"
```

```go
for i, r := range "née" {
	fmt.Println(i, string(r)) // 0 n, then 1 é, then 3 e: the index jumps over é's two bytes
}
// len("née") is 4: it counts bytes
```

`s[0] = 'J'` does not compile; convert to `[]byte(s)`, change it, and convert back with `string(b)`. Build long strings with `strings.Builder` (`WriteString`, `WriteByte`, then `String()`). `strconv.Atoi` rejects surrounding spaces and out-of-range values as well as junk. Letter counts go in a fixed array, and since arrays compare with `==`, an anagram check is one comparison and grouping anagrams is a `map[[26]int][]string`:

```go
func letterCounts(word string) [26]int {
	var counts [26]int // an array, zeroed
	for i := 0; i < len(word); i++ {
		counts[word[i]-'a']++
	}
	return counts
}
```

For character classes, `c >= '0' && c <= '9'` is the ASCII test; `unicode.IsDigit` and `unicode.IsLetter` take a `rune` and accept any Unicode digit or letter.

<Pitfall title="string(n) is not a number">
`string(n)` with an `int` compiles and returns the character with that code: `string(65)` is `"A"`, not `"65"`. `go vet` flags it, but a shared editor will not run vet. Use `strconv.Itoa`.
</Pitfall>

### Sorting with a comparator

The `slices` functions take a comparison that returns a negative number, zero or a positive one; the older `sort.Slice` takes two indices and a `bool` "less". Mixing up the shapes at least fails to compile.

```go
nums := []int{10, 9, 1}
slices.Sort(nums) // [1 9 10], in place

slices.SortFunc(nums, func(a, b int) int { return cmp.Compare(b, a) }) // [10 9 1]

sort.Slice(nums, func(i, j int) bool { return nums[i] < nums[j] }) // [1 9 10]: indices and a less

stock := map[string]int{"emma": 2, "dune": 5}
titles := slices.Sorted(maps.Keys(stock)) // [dune emma], Go 1.23 and later
```

Prefer `cmp.Compare` to `a - b`, which can still overflow. Chain keys with `cmp.Or`, which returns its first non-zero argument:

```go
type loan struct {
	member string
	due    int
}
```

```go
slices.SortFunc(loans, func(a, b loan) int {
	return cmp.Or(cmp.Compare(a.due, b.due), strings.Compare(a.member, b.member))
}) // bob, ana, eve: by due, then by name
slices.SortStableFunc(loans, func(a, b loan) int {
	return cmp.Compare(b.due, a.due)
}) // ana, eve, bob: latest first, ties keep their order
```

Strings compare byte by byte, so `<` gives ordinal order: `["b", "a", "B", "A"]` sorts to `A B a b`. `slices.SortFunc` and `sort.Slice` are not guaranteed stable, and as in C#, small inputs can keep ties in order while larger ones do not. When ties must keep their order, use `slices.SortStableFunc` or `sort.SliceStable`.

### Iteration

```go
for i, t := range titles { // index and value; write _ for the one you don't need
	fmt.Println(i, t)
}
for i := range titles { // one variable is the index, not the value
	fmt.Println(titles[i])
}
for i := range 3 { // 0, 1, 2: range over an int, Go 1.22 and later
	fmt.Println(i)
}
for i := len(titles) - 1; i >= 0; i-- { // backwards
	fmt.Println(titles[i])
}
for title, count := range stock { // a map, in a different order on every run
	fmt.Println(title, count)
}
for _, title := range slices.Sorted(maps.Keys(stock)) { // a map, in key order
	fmt.Println(title, stock[title])
}
for _, d := range [][2]int{{1, 0}, {-1, 0}, {0, 1}, {0, -1}} { // the four neighbours
	nr, nc := r+d[0], c+d[1]

		fmt.Println(grid[nr][nc])
	}

```

`for cond { }` is the while loop. The range variable is a copy, so `b.title = "?"` inside `for _, b := range books` changes nothing; write `books[i].title`. Map order is unspecified and the runtime varies it on purpose, so sort the keys whenever the answer depends on order. Deleting entries during a map range is safe. Since Go 1.22 each iteration has its own loop variables, so a goroutine that captures `i` sees that iteration's value.

### Numbers

`int` is 32 or 64 bits by platform, and 64 on any machine you are likely to interview on, so `math.MaxInt` is about 9.2 × 10¹⁸. Overflow still wraps silently, with no checked mode:

```go
a, b := 3_000_000_000, 4_000_000_000
fmt.Println(a * b) // -6446744073709551616: past math.MaxInt, it wraps without a word

var x, y int32 = 50_000, 50_000
fmt.Println(x * y)               // -1794967296: int32 wraps near 2.1 × 10⁹
fmt.Println(int64(x) * int64(y)) // 2500000000

big := math.MaxInt
fmt.Println(big+1 == math.MinInt) // true
```

Constant expressions are checked, so `x := math.MaxInt + 1` does not compile. Types never mix implicitly: `int` with `float64` or `int64` is a compile error until you convert one side. Beyond 64 bits there is `math/big`.

| You want | Write | Note |
| --- | --- | --- |
| Integer division toward zero | `a / b` | `-7 / 2` is `-3`, and `7 / 2` is `3` |
| A real quotient | `float64(a) / float64(b)` | `3.5` |
| Division rounding down | `floorDiv(a, b)` below | `-4` for `-7` and `2`, like Python's `//`; not built in |
| Remainder | `a % b` | Takes the sign of `a`: `-7 % 3` is `-1` |
| Always-positive modulo | `((a % m) + m) % m` | `2` for `-7` and `3` |
| Smaller and larger | `min(a, b)`, `max(a, b, c)` | Built in since Go 1.21 |
| Sentinels | `math.MaxInt`, `math.MinInt` | Never add to a sentinel |
| Absolute value | write it | `math.Abs` is for `float64` |

```go
func floorDiv(a, b int) int {
	q := a / b
	if a%b != 0 && (a < 0) != (b < 0) {
		q-- // truncation went up; step down
	}
	return q
}
```

### Errors

Errors are values (Chapter 7): return `error` last, check it at once, and wrap it with `%w` to add context:

```go
var ErrNotFound = errors.New("not found")

var shelf = map[int]string{1: "Dune, copy 1"}

func findCopy(id int) (string, error) {
	title, ok := shelf[id]
	if !ok {
		return "", fmt.Errorf("copy %d: %w", id, ErrNotFound) // %w keeps ErrNotFound in the chain
	}
	return title, nil
}

func main() {
	_, err := findCopy(2)
	fmt.Println(err)                         // copy 2: not found
	fmt.Println(errors.Is(err, ErrNotFound)) // true: Is looks through every %w
	fmt.Println(err == ErrNotFound)          // false: the wrapper is a different value

	_, err = strconv.Atoi("12a")
	var numErr *strconv.NumError
	if errors.As(err, &numErr) { // As finds an error of a given type and fills the variable
		fmt.Println(numErr.Func, numErr.Num) // Atoi 12a
	}
}
```

`%v` instead of `%w` prints the same message but cuts the chain, so `errors.Is` returns `false`. `panic` is for bugs: an index out of range or a nil map write panics on its own, which is right for a broken invariant. Most algorithm functions return no error; the bank returns an empty slice or `-1`, and for "may be missing", a second `bool`, the comma-ok shape of a map read.

### Concurrency basics

Goroutines run in parallel on real threads (Chapter 7), so the TypeScript `mapLimit` with its unguarded `next++` would be a data race. The short Go version starts a goroutine per item and lets a buffered channel admit `limit` at a time:

```go
func mapLimit[T, R any](items []T, limit int, fn func(T) R) []R {
	results := make([]R, len(items))
	gate := make(chan struct{}, limit) // a buffered channel as a semaphore: limit slots
	var wg sync.WaitGroup
	for i, item := range items {
		wg.Add(1)
		go func() { // i and item are new variables in every iteration (Go 1.22)
			defer wg.Done()
			gate <- struct{}{}        // take a slot; blocks while all limit are taken
			defer func() { <-gate }() // give it back
			results[i] = fn(item)     // each goroutine writes only its own slot
		}()
	}
	wg.Wait()
	return results
}
```

The worker pool is the closest match to the TypeScript version, with a channel in place of the shared counter:

```go
func mapLimitPool[T, R any](items []T, limit int, fn func(T) R) []R {
	results := make([]R, len(items))
	jobs := make(chan int)
	var wg sync.WaitGroup
	for range min(limit, len(items)) {
		wg.Add(1)
		go func() {
			defer wg.Done()
			for i := range jobs { // each index is received by exactly one worker
				results[i] = fn(items[i])
			}
		}()
	}
	for i := range items {
		jobs <- i
	}
	close(jobs) // ends every worker's range loop
	wg.Wait()
	return results
}
```

Both keep results in input order. Call `wg.Add(1)` before the `go` statement, or `Wait` can return before the goroutine starts; the `wg.Go` method that does both arrives in Go 1.25. For other shared state, `sync/atomic` handles one number and `sync.Mutex` anything bigger:

```go
var total atomic.Int64
var wg sync.WaitGroup
for range 8 {
	wg.Add(1)
	go func() {
		defer wg.Done()
		for range 100_000 {
			total.Add(1) // total++ on a plain int here loses updates
		}
	}()
}
wg.Wait()
fmt.Println(total.Load()) // 800000

var mu sync.Mutex
loansPerMember := map[string]int{}
mu.Lock()
loansPerMember["ana"]++ // anything bigger than one number goes under a mutex
mu.Unlock()
```

With a plain `int`, the loop prints a different wrong number each run, and `go run -race` or `go test -race` reports `WARNING: DATA RACE` with both lines. The detector sees only races that actually happen while it runs.

<InterviewLens>
"Many goroutines write to `results` with no lock. Is that a race?" No: each goroutine writes a different element, and `wg.Wait()` returns only after every `Done`, so all the writes are visible afterwards. Then say what would be one: a shared `next++`, an `append` to one shared slice, or writes to one map, which can crash the program with "concurrent map writes".
</InterviewLens>

### The heap

`container/heap` is a set of functions over any type that implements `heap.Interface`: `Len`, `Less` and `Swap` from `sort.Interface`, plus `Push` and `Pop`. You write the five methods on a slice type, then call `heap.Push` and `heap.Pop`, which use them to keep the order. Learn this version from the package documentation:

```go
type IntHeap []int

func (h IntHeap) Len() int           { return len(h) }
func (h IntHeap) Less(i, j int) bool { return h[i] < h[j] } // > for a max-heap
func (h IntHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *IntHeap) Push(x any)        { *h = append(*h, x.(int)) }
func (h *IntHeap) Pop() any {
	old := *h
	x := old[len(old)-1]
	*h = old[:len(old)-1]
	return x
}
```

`Push` and `Pop` take pointer receivers because they change the length. Your `Pop` removes the last element because `heap.Pop` has already swapped the root there.

```go
h := &IntHeap{14, 3, 7}
heap.Init(h) // O(n): arrange an existing slice as a heap
heap.Push(h, 1)
smallest := (*h)[0] // 1: the root is the minimum
for h.Len() > 0 {
	fmt.Print(heap.Pop(h), " ") // 1 3 7 14
}
```

<Pitfall title="h.Push is not heap.Push">
Calling your own method, `h.Push(x)`, compiles and appends without restoring the order, and `h.Pop()` returns whatever is last: push 5, 1 and 3 that way and it returns 3. Always call `heap.Push(h, x)` and `heap.Pop(h)`.
</Pitfall>

For "the k largest", keep a min-heap of size k:

```go
func kthLargest(nums []int, k int) int {
	h := &IntHeap{} // a min-heap of the k largest so far
	for _, x := range nums {
		heap.Push(h, x)
		if h.Len() > k {
			heap.Pop(h) // drop the smallest
		}
	}
	return (*h)[0]
}
```

For pairs, write the same five methods on a slice of structs. Dijkstra's algorithm then uses lazy deletion, as in the C# and Java sections:

```go
type entry struct{ dist, node int }

type entryHeap []entry

func (h entryHeap) Len() int           { return len(h) }
func (h entryHeap) Less(i, j int) bool { return h[i].dist < h[j].dist }
func (h entryHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }
func (h *entryHeap) Push(x any)        { *h = append(*h, x.(entry)) }
func (h *entryHeap) Pop() any {
	old := *h
	x := old[len(old)-1]
	*h = old[:len(old)-1]
	return x
}
```

```go
type edge struct{ to, cost int }

func shortestFrom(graph [][]edge, source int) []int {
	dist := make([]int, len(graph))
	for i := range dist {
		dist[i] = math.MaxInt
	}
	dist[source] = 0
	h := &entryHeap{{0, source}}
	for h.Len() > 0 {
		e := heap.Pop(h).(entry) // Pop returns any: assert the type back
		if e.dist > dist[e.node] {
			continue // stale: a shorter path was found after this was queued
		}
		for _, ed := range graph[e.node] {
			if nd := e.dist + ed.cost; nd < dist[ed.to] {
				dist[ed.to] = nd
				heap.Push(h, entry{nd, ed.to}) // queue it again instead of updating the old entry
			}
		}
	}
	return dist
}
```

Say O(E log E). Unreachable nodes keep `math.MaxInt`, which is never added to.

**There is no decrease-key by value, only by index.** `heap.Fix(h, i)` repairs the order after you change the element at index `i`, in O(log n). The catch is knowing `i`, since `Swap` keeps moving elements: each item must carry its index, and `Swap` and `Push` must update it.

```go
type item struct {
	node, dist int
	index      int // where the item sits in the heap right now
}

type itemHeap []*item

func (h itemHeap) Len() int           { return len(h) }
func (h itemHeap) Less(i, j int) bool { return h[i].dist < h[j].dist }
func (h itemHeap) Swap(i, j int) {
	h[i], h[j] = h[j], h[i]
	h[i].index, h[j].index = i, j // keep every index current
}
func (h *itemHeap) Push(x any) {
	it := x.(*item)
	it.index = len(*h)
	*h = append(*h, it)
}
func (h *itemHeap) Pop() any {
	old := *h
	it := old[len(old)-1]
	*h = old[:len(old)-1]
	return it
}
```

```go
byNode := map[int]*item{}
for node, d := range []int{9, 4, 7} {
	byNode[node] = &item{node: node, dist: d}
	heap.Push(h, byNode[node])
}
byNode[0].dist = 1           // decrease-key: change the priority...
heap.Fix(h, byNode[0].index) // ...then repair the heap from that index, O(log n)
first := heap.Pop(h).(*item) // node 0, distance 1
```

### Mistakes when coming from the other languages

**From TypeScript.** `for x := range nums` gives indices: write `for _, x := range nums`. A missing key gives `0`, not `undefined`. `7 / 2` is `3`. There is no ternary and no `while`. Assigning a struct or array copies it. Map order is random, not insertion order.

**From C#.** Errors are returned, not thrown. A missing key does not throw. `m[k].x = 5` does not compile when the map holds structs: read, change and store back. `pts[0].x = 5` works on a slice, but `range` hands you a copy. Use `int32` when a problem insists on 32-bit behaviour.

**From Java.** `==` on strings compares the text. There is no boxing and no `null` from `map[string]int`. One built-in, `len`, measures strings, slices and maps. A slice is your stack and queue. `slices.SortFunc` is not stable where `Collections.sort` is.

**From Kotlin.** `0 until n` is `range n`. There is no `?:` and no null `int`: the zero value and comma-ok take their place. Nothing is read-only: a callee can change a slice you pass. Struct assignment copies, so there is no `copy()` to call.

**From Python.** `a[-1]` fails to compile with a constant and panics with a variable. Slicing shares the array instead of copying it. `/` truncates toward zero and `%` keeps the sign of the left operand. There is no `in`: use a map or `slices.Contains`. `len(s)` counts bytes.

## Python

Python is the language in which interview code is shortest, which is why the print edition shows every bank solution in it. The standard library has almost everything a round needs: a heap, a deque, a counter, binary search, memoisation and integers that never overflow. The danger is that Python's mistakes are silent. A grid built with `*` shares one row, a default argument keeps its value between calls, `-7 // 2` is `-4`, and `if i:` treats a found index of `0` as missing. Each runs without an error and gives a wrong answer.

Everything here runs on Python 3.12 with `python3 file.py`, standard library only, the way the files in `apps/interview-bank` do. The type hints follow the bank's style (`list[int]`, `int | None`); Python does not check them at run time. Chapter 8 covers the language; this section covers only what you type in the round.

### Syntax by heart

These are the structures the problem bank uses, with the costs you will name in step 6.

| Structure | Write it as | Operations to know |
| --- | --- | --- |
| List | `a: list[int] = []` | `append`, `pop()`, `a[i]`, `a[-1]`, `len(a)`: O(1), `append` amortized. `pop(0)`, `insert(0, x)`, `x in a`, `index`, `remove(x)`: O(n). A slice `a[i:j]` is a copy: O(j − i) |
| Dict | `d: dict[str, int] = {}` | `d[k]` (raises `KeyError` if missing), `d.get(k)`, `d.get(k, 0)`, `setdefault`, `k in d`, `del d[k]`, `len(d)`: O(1) average. Keeps insertion order, guaranteed since 3.7 |
| Set | `s: set[int] = set()` | `add`, `x in s`, `discard`, `remove`: O(1) average. `{}` is an empty dict, not a set |
| Stack | a list | `append`, `pop()`, `a[-1]` to peek |
| Queue | `deque()` from `collections` | `append` at the back, `popleft` at the front: O(1) |
| Deque | `deque()` | `append`, `appendleft`, `pop`, `popleft`: O(1). `d[i]` is O(1) at the ends and O(n) toward the middle |
| Heap | a plain list plus `heapq` | `heappush`, `heappop`: O(log n). `h[0]` peeks in O(1). `heapify` is O(n). Smallest first |
| Grid | `[[0] * cols for _ in range(rows)]` | `g[r][c]`; `len(g)` rows, `len(g[0])` columns |
| Pair | a tuple, `(r, c)` | Unpack with `r, c = cell`. Hashable and equal by value, so it works as a key, and it sorts element by element |

The everyday moves:

```python
from collections import Counter, defaultdict, deque

copies: list[int] = [4, 9, 2]
top = copies[-1]                     # 2, without removing it; negative indices count from the end
last = copies.pop()                  # 2; pop() on an empty list raises IndexError
first_two = copies[:2]               # [4, 9], a new list: slices copy
backwards = copies[::-1]             # [9, 4], a reversed copy

loans_per_member: dict[str, int] = {}
loans_per_member["ana"] = loans_per_member.get("ana", 0) + 1   # count with a default

by_author: dict[str, list[str]] = {}
by_author.setdefault("Le Guin", []).append("Earthsea")         # group without an if
grouped: defaultdict[str, list[str]] = defaultdict(list)
grouped["Herbert"].append("Dune")    # a missing key is created as list() on first use

seen = {3, 1, 3}                     # {1, 3}
seen.add(7)

visited = {(0, 1)}                   # a tuple hashes by value
found = (0, 1) in visited            # True

queue = deque([1, 2])
queue.append(3)                      # in at the back
front = queue.popleft()              # 1, in O(1); list.pop(0) moves every other element
queue.appendleft(0)                  # deque([0, 2, 3])
recent = deque(maxlen=3)             # keeps the last three: appending a fourth drops the oldest

grid = [[0] * 4 for _ in range(3)]   # 3 rows of 4 zeros; grid[r][c]
```

`setdefault` evaluates its default on every call, even when the key exists, so keep it cheap. `defaultdict` calls its factory only for a missing key, but even reading one inserts it, so test membership with `in`. For counting, `Counter` is shorter than either:

```python
votes = Counter(["dune", "emma", "dune", "ulysses", "emma"])
dune = votes["dune"]                 # 2
zoe = votes["zoe"]                   # 0, and nothing is inserted
top_two = votes.most_common(2)       # [('dune', 2), ('emma', 2)]: ties in first-seen order
same = Counter("listen") == Counter("silent")   # True: the one-line anagram check
```

`most_common` orders equal counts by when each element was first seen, which is often the tie-break a problem asks for; say so when you rely on it. A key must be hashable, and a list is not: `{[0, 1]}` raises `TypeError: unhashable type: 'list'`. Convert with `tuple(cells)`, or `frozenset(s)` for a set.

<FromTS title="Composite keys without strings">
In TypeScript a grid cell becomes `"r,c"` before it goes in a `Set`. In Python, tuples hash and compare by value, so `visited = {(r, c)}` just works, and `==` compares lists and dicts by content: `[[1, 2]] == [[1, 2]]` is `True`.
</FromTS>

Breadth-first search uses a `deque`. `set.add` returns `None`, so checking and inserting take two lines:

```python
def bfs_order(graph: dict[int, list[int]], start: int) -> list[int]:
    order: list[int] = []
    seen = {start}
    queue = deque([start])
    while queue:
        node = queue.popleft()
        order.append(node)
        for nxt in graph.get(node, []):
            if nxt not in seen:
                seen.add(nxt)
                queue.append(nxt)
    return order
```

The loop variable is `nxt` because `next` is a built-in function.

<Pitfall title="One row, shared by the whole grid">
`[[0] * 4] * 3` holds the same inner list three times, so `grid[0][0] = 1` changes the first cell of every row. `*` copies references; the inner `[0] * 4` is safe only because integers are immutable. Build rows in a comprehension, and copy a grid with `[row[:] for row in grid]`.
</Pitfall>

### Strings and characters

There is no `char` type: `s[i]` is a string of length one. Strings are immutable, and `len(s)` counts code points, not UTF-16 units or bytes.

```python
s = "Shelfwise"
first = s[0]                         # 'S'
last_ch = s[-1]                      # 'e'
part = s[1:4]                        # 'hel', end index excluded
pos = ord(s[1]) - ord("a")           # 7: the letter's position in the alphabet
letter = chr(ord("a") + 7)           # 'h'
digit = int("7")                     # 7; ord("7") - ord("0") also works
words = "  two   words ".split()     # ['two', 'words']: any run of whitespace
fields = "a,b,,".split(",")          # ['a', 'b', '', '']: empty fields kept
padded = "7".zfill(3)                # '007'
reversed_s = "stressed"[::-1]        # 'desserts'
joined = ", ".join(map(str, [1, 2, 3]))   # '1, 2, 3'; join takes strings only
sorted_key = "".join(sorted("listen"))    # 'eilnst'
```

`split()` with no argument splits on runs of whitespace and drops empty strings at both ends; `split(" ")` splits on each single space, so the same input gives `['', '', 'two', '', '', 'words', '']`. `s[0] = "x"` raises `TypeError`. To build a string, append pieces to a list and `"".join` them at the end: repeated `+=` can cost quadratic time, and CPython's optimization of it is not guaranteed.

For letter counts, `counts = [0] * 26` with `counts[ord(ch) - ord("a")] += 1` is the standard move, and two count lists compare with `==`. `<` compares strings by code point, so `"B" < "a"`, and `sorted` gives the ordinal order most problems mean.

The `str.is...` methods follow Unicode, not ASCII. `"é".isalpha()` is `True`, and so are `"٣".isdigit()` (an Arabic-Indic three) and `"²".isdigit()`, although `int("²")` raises `ValueError`. `isalnum`, `isspace` and the rest are just as broad. When the problem means ASCII, write `"0" <= ch <= "9"` or `ch.isascii() and ch.isalnum()`.

### Sorting with a comparator

`list.sort()` sorts in place and returns `None`; `sorted(x)` takes any iterable and returns a new list. Instead of a comparator, both take a `key` function that maps each element to the value to sort by:

```python
from dataclasses import dataclass
from functools import cmp_to_key


@dataclass
class Loan:
    member: str
    due: int


nums = [10, 9, 1]
nums.sort()                                   # [1, 9, 10], in place
desc = sorted(nums, reverse=True)             # [10, 9, 1], a new list
words = sorted(["b", "a", "B", "A"])          # ['A', 'B', 'a', 'b']: by code point
by_length = sorted(["ccc", "a", "bb"], key=len)   # ['a', 'bb', 'ccc']

loans = [Loan("cy", 3), Loan("ana", 7), Loan("bo", 3)]
loans.sort(key=lambda loan: loan.due)                            # stable: cy stays before bo
ordered = sorted(loans, key=lambda loan: (loan.due, loan.member))      # bo, cy, ana
latest_first = sorted(loans, key=lambda loan: (-loan.due, loan.member))  # ana, bo, cy
```

A tuple key sorts by its first element, then the second. Negating a number reverses one key, but a string cannot be negated; for "due ascending, member descending", sort by the secondary key first, then by the primary one, and let stability do the rest.

```python
by_member_desc = sorted(loans, key=lambda loan: loan.member, reverse=True)
by_member_desc.sort(key=lambda loan: loan.due)    # cy, bo, ana: ties keep the earlier order
```

The sort is guaranteed stable, even with `reverse=True`. When the order really comes from comparing two elements, as in "arrange numbers to form the largest number", wrap a comparator in `functools.cmp_to_key`:

```python
def largest_number(nums: list[int]) -> str:
    def compare(a: str, b: str) -> int:
        if a + b > b + a:
            return -1                        # a goes first
        if a + b < b + a:
            return 1
        return 0

    digits = sorted(map(str, nums), key=cmp_to_key(compare))
    return "".join(digits).lstrip("0") or "0"


assert largest_number([3, 30, 34, 5, 9]) == "9534330"
assert largest_number([0, 0]) == "0"
```

<Pitfall title="A sort that returns None">
`nums = nums.sort()` sorts the list, then replaces it with `None`; the error appears lines later as `'NoneType' object is not subscriptable`. `sorted(nums)` alone on a line builds a sorted copy and throws it away. Write `nums.sort()` or `nums = sorted(nums)`.
</Pitfall>

### Iteration

```python
titles = ["Dune", "Emma", "Ulysses"]
stock = {"Dune": 2, "Emma": 0}

for i in range(len(titles)): ...               # indices 0 to 2
for t in titles: ...                           # values
for i, t in enumerate(titles): ...             # index and value; enumerate(titles, 1) starts at 1
for i in range(len(titles) - 1, -1, -1): ...   # backwards: 2, 1, 0
for t in reversed(titles): ...                 # values backwards, without a copy
for title, count in stock.items(): ...         # a dict, in insertion order
for t, n in zip(titles, [2, 0, 5]): ...        # two lists in step; stops at the shorter
for dr, dc in ((1, 0), (-1, 0), (0, 1), (0, -1)): ...   # the four neighbours of a cell
for i in range(0, 10, 3): ...                  # 0, 3, 6, 9
```

`range` stops before its end, so counting down to index 0 needs a stop of `-1`. `zip(a, b, strict=True)` raises `ValueError` when the lengths differ instead of dropping the tail. A few `itertools` functions replace index arithmetic:

```python
from itertools import chain, groupby, islice, pairwise

steps = list(pairwise([1, 4, 9]))              # [(1, 4), (4, 9)]: neighbours
both = list(chain([1, 2], [3]))                # [1, 2, 3]
head = list(islice(range(100), 3))             # [0, 1, 2]: the first three of any iterator
runs = [(k, len(list(g))) for k, g in groupby("aaabcc")]   # [('a', 3), ('b', 1), ('c', 2)]
```

`groupby` groups consecutive equal elements only, so sort first. There are no labelled breaks: put nested loops in a function and `return`. Adding a key to a dict inside its own loop raises `RuntimeError`; removing from a list inside its own loop silently skips elements (removing every even value from `[2, 4, 6]` that way leaves `[4]`). Loop over a copy, `list(d)` or `a[:]`, or build a new list.

### Numbers

`int` has no fixed size, so `50_000 * 50_000` is `2500000000`, `2 ** 100` is exact and `(lo + hi) // 2` is a safe midpoint. The overflow bugs of the other five languages do not exist. Division is where Python differs:

| You want | Write | Note |
| --- | --- | --- |
| Integer division rounding down | `a // b` | `-7 // 2` is `-4`. C#, Java, Kotlin and Go truncate their integer `/` toward zero and give `-3`, as TypeScript's `Math.trunc(-7 / 2)` does |
| Remainder | `a % b` | Takes the sign of `b`: `-7 % 3` is `2`, `7 % -3` is `-2`. The other five give `-1` for `-7 % 3` |
| Both at once | `divmod(a, b)` | `divmod(-7, 2)` is `(-4, 1)`, always with `a == q * b + r` |
| Ceiling division | `-(-a // b)` | `-(-7 // 2)` is `4`, with no float involved |
| A real quotient | `a / b` | Always a `float`: `6 / 3` is `2.0` |
| Sentinels | `math.inf`, `-math.inf` | Compare with any `int`; `int(math.inf)` raises `OverflowError` |
| Rounding | `round(x)` | Rounds halves to even: `round(2.5)` is `2`. `int(-2.7)` truncates to `-2` |
| Bits | `1 << k`, `x >> 1`, `x & 1`, `x ^ y`, `x.bit_count()` | Negative numbers act as infinite two's complement: `~5` is `-6`; mask with `& 0xFFFFFFFF` for 32-bit answers |

Python's `%` is the always-positive modulo the other sections had to build, so `(i + k) % n` is safe for a negative `k` here and only here. When a problem wants truncating division, as expression evaluators do, write `q = abs(a) // abs(b)` and negate `q` if exactly one operand is negative. `int(a / b)` also truncates, but through a `float`, which holds integers exactly only up to 2⁵³. Floats are IEEE doubles, as everywhere: `0.1 + 0.2 == 0.3` is `False`, so compare with `math.isclose`.

`int(" 42 ")` is `42`, `int("12a")` raises `ValueError`, and `int("ff", 16)` is `255`. `int` also accepts underscores and non-ASCII digits (`int("1_000")`, `int("٣")`), so when a problem defines a valid number, as 038 does, parse by hand. Since Python 3.11, converting between `int` and `str` in base 10 raises `ValueError` past 4,300 digits: `str(10 ** 4300)` fails, and so does printing `math.factorial(2000)`. `sys.set_int_max_str_digits(0)` removes the limit.

### Errors

Raise `Exception` or a subclass. A custom exception takes two lines, and `ValueError` is the standard type for a bad argument:

```python
class NotFoundError(Exception):
    pass


shelf = {1: "Dune, copy 1"}


def find_copy(copy_id: int) -> str:
    copy = shelf.get(copy_id)
    if copy is None:
        raise NotFoundError(f"copy {copy_id} not found")
    return copy


def find_copy_or_none(copy_id: int) -> str | None:
    try:
        return find_copy(copy_id)
    except NotFoundError:
        return None          # anything else keeps propagating


def loan_days(days: int) -> int:

        raise ValueError(f"days must be 1 to 30, was {days}")
    return days
```

Never write a bare `except:`; it also catches `KeyboardInterrupt`. Inside `except`, a bare `raise` re-raises with the original traceback, and `raise NotFoundError(...) from e` chains the cause. Python style leans toward EAFP, "easier to ask forgiveness than permission": try the operation and catch the failure, as `find_copy_or_none` does. LBYL, "look before you leap", tests first: `if k in d`. For a dict, `d.get(k)` is shorter than either.

Know what the library raises: `IndexError` for a bad list index, `pop` on an empty list, `heappop` on an empty heap and `popleft` on an empty deque; `KeyError` for `d[k]` and `set.remove`; `ValueError` for `list.index` or `list.remove` of a missing value, a bad `int(...)` and `max([])`, which `max(a, default=0)` avoids.

In the bank, a function returns an empty value (`[]`, `-1`, `None`) when there is no answer, unless the problem says to raise. Declare it, `-> int | None`, and test it with `is None`: in problem 002, `if i:` would treat a match at index 0 as no match.

### Concurrency basics

In standard CPython the GIL lets one thread run Python bytecode at a time (Chapter 8). Threads still help with I/O, because waiting releases the lock, but CPU-bound Python code gets no faster with more threads. Python 3.13 added an optional free-threaded build without the GIL; it is a separate build, not the default, so assume the standard one. The GIL does not make your code thread-safe either: `total += 1` is a read, an add and a write, and another thread can run in between, so shared state still needs a `threading.Lock`.

`asyncio` is the closest thing to Node: one event loop, with tasks taking turns at every `await`. `gather` runs awaitables concurrently and returns their results in the order you passed them:

```python
import asyncio


async def load_book(book_id: int) -> str:
    await asyncio.sleep(0.1)                  # stands in for a network call
    return f"book {book_id}"


async def main() -> None:
    titles = await asyncio.gather(*(load_book(i) for i in [7, 3, 9]))
    print(titles)                             # ['book 7', 'book 3', 'book 9'], in about 0.1 s


asyncio.run(main())
```

With `return_exceptions=True`, `gather` returns failures as values in their slots, like `Promise.allSettled`. The `mapLimit` from the TypeScript section becomes a semaphore that admits `limit` coroutines at a time:

```python
from collections.abc import Awaitable, Callable


async def map_limit[T, R](items: list[T], limit: int, fn: Callable[[T], Awaitable[R]]) -> list[R]:
    gate = asyncio.Semaphore(limit)

    async def run(item: T) -> R:
        async with gate:                      # at most `limit` coroutines get past here
            return await fn(item)

    return await asyncio.gather(*(run(item) for item in items))
```

`[T, R]` after the name is the type-parameter syntax added in 3.12, and `gather` keeps the results in input order. For blocking calls, use a thread pool, whose size is the limit:

```python
from concurrent.futures import ThreadPoolExecutor
import threading


def map_limit_threads[T, R](items: list[T], limit: int, fn: Callable[[T], R]) -> list[R]:
    with ThreadPoolExecutor(max_workers=limit) as pool:
        return list(pool.map(fn, items))      # input order; a task's exception is raised here


total = 0
lock = threading.Lock()


def add_many() -> None:
    global total
    for _ in range(100_000):
        with lock:                            # without it, updates can be lost
            total += 1


with ThreadPoolExecutor(max_workers=8) as pool:
    for _ in range(8):
        pool.submit(add_many)
# leaving the with block waits for every task: total is 800000
```

`pool.map` yields results in input order whatever order they finish in, and re-raises a task's exception when its result is read.

### The heap

`heapq` is a set of functions that keep a plain list in min-heap order. There is no heap class, no max-heap and no comparator:

```python
import heapq

heap: list[int] = []
for x in [14, 3, 7]:
    heapq.heappush(heap, x)
smallest = heap[0]                     # 3, without removing it
popped = heapq.heappop(heap)           # 3; IndexError on an empty heap

nums = [5, 1, 8, 3]
heapq.heapify(nums)                    # in place, O(n)

max_heap = [-x for x in [5, 1, 8]]     # negate for a max-heap
heapq.heapify(max_heap)
largest = -max_heap[0]                 # 8

by_due: list[tuple[int, int, str]] = []
for seq, (due, title) in enumerate([(14, "Dune"), (3, "Emma"), (3, "Ulysses")]):
    heapq.heappush(by_due, (due, seq, title))   # (priority, tie-break, item)
while by_due:
    due, _, title = heapq.heappop(by_due)
    print(due, title)                  # 3 Emma, then 3 Ulysses, then 14 Dune
```

Tuples compare element by element, so a heap of `(priority, item)` compares the items whenever two priorities tie. For numbers or strings that is a harmless extra key; for dicts it raises `TypeError: '<' not supported between instances of 'dict' and 'dict'`. A sequence number in the middle prevents that and makes ties come out first in, first out. The list is in heap order, not sorted order: after `heapify`, `nums` is `[1, 3, 8, 5]`.

For "the k largest", keep a min-heap of size k. `heappushpop(heap, x)` pushes and then pops in one step, cheaper than the two calls; `heapreplace` pops first and then pushes, so it can return an element larger than `x`, and it raises `IndexError` on an empty heap.

```python
def kth_largest(nums: list[int], k: int) -> int:
    heap = nums[:k]
    heapq.heapify(heap)                # a min-heap of the k largest so far
    for x in nums[k:]:
        heapq.heappushpop(heap, x)     # add x, then drop the smallest
    return heap[0]
```

For a one-off answer, `heapq.nlargest(k, nums)` and `nsmallest` do the same, and take a `key`.

**There is no decrease-key.** For Dijkstra's algorithm, use lazy deletion as in the C# section: push the node again with the new distance, and skip stale entries.

```python
import math


def shortest_from(graph: list[list[tuple[int, int]]], source: int) -> list[float]:
    dist = [math.inf] * len(graph)     # graph[u] holds (to, cost) pairs
    dist[source] = 0
    heap = [(0, source)]               # (distance, node)
    while heap:
        d, node = heapq.heappop(heap)
        if d > dist[node]:
            continue                   # stale: a shorter path was found after this was queued
        for nxt, cost in graph[node]:
            if d + cost < dist[nxt]:
                dist[nxt] = d + cost
                heapq.heappush(heap, (d + cost, nxt))   # queue it again instead of updating
    return dist
```

Say O(E log E), since the heap can hold one entry per edge. Unreachable nodes keep `math.inf`.

| --- | --- |

`@cache` turns a recursive definition into a DP solution, with two catches. The recursion limit is 1,000 frames by default. `sys.setrecursionlimit(10 ** 6)` lets plain recursion go deeper, but a function wrapped in `@cache` passes through C code at every level and, on Python 3.12, can still crash on a separate, lower limit of the C stack that depends on the platform and version. For deep inputs, write the bottom-up loop. And a module-level cache keeps its entries between test cases, which is wrong once the function reads anything besides its arguments; define the cached helper inside the solution function, so it starts empty on every call.

### Mistakes when coming from the other languages

Each of these runs and gives a wrong answer, or fails far from its cause.

<Pitfall title="A default list shared by every call">
`def visit(node, seen=[])` creates the list once, when the function is defined, and every call that omits `seen` shares it, so the second test sees the first test's nodes. Default to `None` and create the list inside: `if seen is None: seen = []`.
</Pitfall>

**From every language.** Built-in names are not reserved: after `max = 0`, the call `max(a, b)` raises `TypeError: 'int' object is not callable`. The usual victims are `max`, `min`, `sum`, `list`, `dict`, `str`, `id` and `next`. In a nested function, assigning to an outer variable (`count += 1` in a DFS helper) raises `UnboundLocalError` unless you declare it `nonlocal`. And recursion stops at 1,000 frames, which a depth-first search on a path of 10⁴ nodes reaches; use an explicit stack.

**From TypeScript.** Empty containers are falsy: `[]`, `set()`, `""` and an empty dict, along with `0` and `None`. In JavaScript `[]` is truthy, so `if (items)` and `if items:` mean different things. `a[len(a)]` raises `IndexError` and `d[k]` raises `KeyError` instead of returning `undefined`. `x in a` checks values, not indices. There is no `++`: `i++` is a syntax error, and `++i` is two unary pluses that change nothing. The ternary is `a if cond else b`.

**From C#, Java and Kotlin.** `7 / 2` is `3.5`; integer division is `//`, and it rounds down, so `-7 // 2` is `-4`. `is` checks identity: it looks right in small tests because CPython caches small integers, as Java caches boxed ones, but `1000 is int("1000")` is `False`. Use `==` for values and `is` only for `None`. Closures capture variables, not values: `[lambda: i for i in range(3)]` gives three functions that all return `2`. `list.sort()` returns `None`, where Kotlin's `sorted()` returns a list.

**From Go.** A missing key raises instead of giving a zero value; use `d.get(k, 0)` or `defaultdict(int)`. Assignment never copies: `b = a` shares the list, as a slice shares its array, and there is no array type that copies; write `a[:]`, or `[row[:] for row in grid]` for a grid. Multiple return values feel familiar: `q, r = divmod(a, b)` returns and unpacks a tuple, and `for i, x in enumerate(a)` is `for i, x := range a`.

### Writing and running a quick test

Every Python file in the bank ends with its checks under `if __name__ == "__main__":`, which runs them when the file is executed, not when it is imported. For 002, plus a check that `find_copy` raises:

```python
if __name__ == "__main__":
    assert two_prices([12, 7, 3, 9, 5], 12) == [2, 3]
    assert two_prices([4, 4, 1], 8) == [0, 1]
    assert two_prices([1, 2], 10) == []
    try:
        find_copy(2)
    except NotFoundError:
        pass
    else:
        raise AssertionError("expected NotFoundError")
    print("002 ok")
```

`python3 p002_two_prices.py` runs the file. A failing `assert` raises `AssertionError`, and the traceback gives the line. No helper is needed, because `==` compares lists, dicts and tuples by content. Two warnings. `python3 -O` removes every `assert`, so a failing check passes in silence, as Java's `assert` does without `-ea`; the bank never runs with `-O`. And `assert (got == want, "message")` asserts a non-empty tuple, which is always true: Python prints a `SyntaxWarning`, but the check never fails. Write the message after a comma, without parentheses.

To see which case failed, loop over a table with a message:

```python
cases = [
    ([12, 7, 3, 9, 5], 12, [2, 3]),
    ([4, 4, 1], 8, [0, 1]),
    ([1, 2], 10, []),
    ([], 5, []),
]
for prices, budget, want in cases:
    got = two_prices(prices, budget)
    assert got == want, f"two_prices({prices}, {budget}) = {got}, want {want}"
```

A wrong answer now prints, for example, `AssertionError: two_prices([1, 2], 10) = [0, 0], want []`. It is the shape the other sections use, with less ceremony. A real project would use pytest, where a plain `assert` in a `test_` function reports both values and `@pytest.mark.parametrize` turns the table into one test per row (Chapters 8 and 17); `unittest` is the built-in alternative. In the round, the file and its asserts are enough. When the editor cannot run code, write the table as comments and trace each row by hand, as in step 5.

## The backend round

Many backend loops include a practical round, instead of an algorithm problem or alongside one. It usually takes one of three forms: build a small endpoint, write a query against a schema you are given, or review a pull request with planted problems. Some rounds combine them and end with "what would you change before this goes to production?" Ask the recruiter which to expect, whether there is a starter project, and whether the code will run against a real database.

The six steps still apply. What changes is what each one is about:

| Step | In an algorithm round | In the backend round |
| --- | --- | --- |
| 1. Restate | Inputs, outputs, types | The operation as a contract: method, path, body, success response |
| 2. Ask about edge cases | Empty input, duplicates, limits | Errors: which failures exist, which status code each one gets, what the error body looks like |
| 3. Simple solution first | The brute force | The happy path end to end, with a fake store, before any hardening |
| 4. Improve | A better data structure | Harden: validation, every error case, concurrency, the constraint in the database |
| 5. Trace | Run an example by hand | Walk one request through each branch, or list the tests that would |
| 6. State the complexity | Time and space | Queries per request, which index each one uses, what happens when two requests race |

Step 2 is the easiest to skip and the one that matters most here: "What should happen if the copy is already on loan?" shows that you think about the contract, not only the code. Step 3 protects you as before: a working endpoint with two error cases missing beats a perfect validation layer and no endpoint.

### A small endpoint

Here is a task as an interviewer might phrase it, using Shelfwise from Chapter 18:

> Members borrow copies of books. Add `POST /loans`, which lends a copy to a member. A copy can only be on loan to one member at a time, and a member can have at most five open loans. Loans are due in 21 days.

**Restate and ask.** "So the client sends a copy id and a member id, and I create a loan and return it with 201." Then the questions, each of which settles a branch of the code:

- *Is there an error format already?* In Shelfwise, yes: Problem Details (Chapter 12), with a `type` URL ending in a stable code such as `copy-on-loan`.
- *400 or 422 for a bad body?* Shelfwise uses 400 `invalid-body` when the body is not JSON at all, and 422 `validation`, with an `errors` member listing each field, when it is JSON with wrong values (Chapter 13).
- *If both the copy and the member are missing, which error?* Either 404 will do; check the copy first.
- *Authentication?* Out of scope for this round, which is normal. Say where it would go (Chapters 19 and 21) and move on.

**Write the contract down.** Just as you wrote examples at the top of the editor in the algorithm round, write the responses. This list is your plan, your checklist and, later, your test cases:

```text
POST /loans  {"copyId": 1, "memberId": 10}
201                 Location: /loans/{id}, body: the loan
400 invalid-body    the body is not JSON
422 validation      copyId or memberId missing, not an integer, or below 1
404 not-found       no such copy, or no such member
409 loan-limit      the member already has 5 open loans
409 copy-on-loan    the copy already has an open loan
```

**Simple first, behind an interface.** Put storage behind four operations, so the handler needs no database and a fake can test it. The fourth is the important one. In Postgres, `insertLoan` is a plain `INSERT`: if the copy is already out, the partial unique index rejects it, and the store reports that as "no loan" (Chapter 18 showed that translation in every stack). The handler never checks whether the copy is free. The database decides, which also covers two librarians lending the same copy in the same second.

Each tab assumes a `Loan` type that matches the contract. In a real codebase the rules would live in a service, as in Shelfwise; in an interview, keeping them in the handler is fine if you say so.

```kotlin
        return ResponseEntity.created(URI.create("/loans/${loan.id}")).body(loan)
    }

    private fun problem(
        status: Int, code: String, title: String, detail: String, errors: Map<String, List<String>>? = null,
    ) =
        ResponseEntity.status(status).contentType(MediaType.APPLICATION_PROBLEM_JSON).body(
            ProblemDetail.forStatusAndDetail(HttpStatusCode.valueOf(status), detail).apply {
                type = URI.create("https://shelfwise.dev/problems/$code")
                this.title = title
                if (errors != null) setProperty("errors", errors)
            },
        )
}
```

```go
// Registered with mux.HandleFunc("POST /loans", h.lend).
func (h *handlers) lend(w http.ResponseWriter, r *http.Request) {
	var req struct {
		CopyID   int64 `json:"copyId"`
		MemberID int64 `json:"memberId"`
	}
	if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
		problem(w, 400, "invalid-body", "Malformed JSON", "The request body is not valid JSON.", nil)
		return
	}
	errs := map[string][]string{}
	if req.CopyID < 1 {
		errs["copyId"] = []string{"must be a positive integer"}
	}
	if req.MemberID < 1 {
		errs["memberId"] = []string{"must be a positive integer"}
	}
	if len(errs) > 0 {
		problem(w, 422, "validation", "Request is invalid", "One or more fields are invalid.", errs)
		return
	}

	ctx := r.Context()
	ok, err := h.store.CopyExists(ctx, req.CopyID)
	if err != nil {
		serverError(w, r, err)
		return
	}
	if !ok {
		problem(w, 404, "not-found", "Resource not found", fmt.Sprintf("Copy %d does not exist.", req.CopyID), nil)
		return
	}
	ok, err = h.store.MemberExists(ctx, req.MemberID)
	if err != nil {
		serverError(w, r, err)
		return
	}
	if !ok {
		problem(w, 404, "not-found", "Resource not found", fmt.Sprintf("Member %d does not exist.", req.MemberID), nil)
		return
	}
	open, err := h.store.CountOpenLoans(ctx, req.MemberID)
	if err != nil {
		serverError(w, r, err)
		return
	}
	if open >= maxLoans {
		detail := fmt.Sprintf("Member %d has %d open loans.", req.MemberID, maxLoans)
		problem(w, 409, "loan-limit", "Loan limit reached", detail, nil)
		return
	}

	loan, err := h.store.InsertLoan(ctx, req.CopyID, req.MemberID, time.Now().AddDate(0, 0, loanDays))
	if errors.Is(err, ErrCopyOnLoan) {
		problem(w, 409, "copy-on-loan", "Copy is already on loan", fmt.Sprintf("Copy %d has an open loan.", req.CopyID), nil)
		return
	}
	if err != nil {
		serverError(w, r, err)
		return
	}
	w.Header().Set("Location", fmt.Sprintf("/loans/%d", loan.ID))
	w.Header().Set("Content-Type", "application/json")
	w.WriteHeader(http.StatusCreated)
	_ = json.NewEncoder(w).Encode(loan)
}
```

```python
@app.exception_handler(RequestValidationError)
async def invalid_request(request: Request, e: RequestValidationError) -> JSONResponse:
    if any(err["type"] == "json_invalid" for err in e.errors()):
        return problem(400, "invalid-body", "Malformed JSON", "The request body is not valid JSON.")
    errors: dict[str, list[str]] = {}
    for err in e.errors():
        errors.setdefault(".".join(map(str, err["loc"][1:])) or "body", []).append(err["msg"])
    return problem(422, "validation", "Request is invalid", "One or more fields are invalid.", errors=errors)

        return problem(404, "not-found", "Resource not found", f"Copy {body.copyId} does not exist.")
    if not await store.member_exists(body.memberId):
        return problem(404, "not-found", "Resource not found", f"Member {body.memberId} does not exist.")

    loan = await store.insert_loan(body.copyId, body.memberId, due_at)
    if loan is None:
```

The order of checks is the same in every tab, and you should be able to explain it. Shape comes first, because it needs no database. The 404s come next, because "this does not exist" tells the client more than any rule about it. The insert comes last, so the database has the final word on the rule it can enforce by itself. The differences between the tabs are what to remember:

- **Where the 400 comes from.** Only Go decodes the body itself. Express rejects malformed JSON inside `express.json()`, so the 400 is written in error middleware. ASP.NET Core and Spring answer 400 before your code runs: ASP.NET with an empty body unless you add `AddProblemDetails` and `UseStatusCodePages`, and Spring Boot with Problem Details when `spring.mvc.problemdetails.enabled=true` is set. FastAPI reports malformed JSON as a 422, so the handler picks it out by its `json_invalid` type.
- **How strict "an integer" is.** Send `"copyId": "1"`. Express answers 422 and Go 400, but ASP.NET Core's web defaults and Pydantic's lax mode both read it as 1. The contract says `integer`, so mention it when the stack is lenient.
- **Missing versus zero.** C#, Java and Kotlin bind to nullable types and turn a missing field into 0, so one check covers both. Go gets the zero value for free.

Once it works, harden it aloud, in order of risk: reject unknown fields, which the contract forbids (Chapter 13); turn unexpected exceptions into a 500 Problem Details response that quotes the request id (Chapter 12); limit the body size; pass a clock in, so a test can check the due date (Chapter 17). The interviewer may stop you after two of these. What they want to see is that you know what is left.

Two `if` statements and a helper that writes Problem Details work in every framework, as the tabs show, and the interviewer is listening for the status codes, not for `@Valid`. Say "in production I'd use the framework's validation", and keep going.
</Pitfall>

**Testing it quickly.** The contract you wrote down is already the test list. Read it back as cases:

1. A free copy and a member under the limit: 201, `Location: /loans/{id}`, and a due date 21 days later.
2. Malformed JSON: 400 `invalid-body`.
3. A missing field and a zero id: 422 `validation`, with the field named in `errors`. A string id gets whatever the stack's binding decides, as above.
4. An unknown copy and an unknown member: 404 `not-found`, once each.

### A SQL exercise

The second common task gives you a schema and asks for a query. On the Shelfwise tables from Chapter 14:

> Librarians want the ten members with the most overdue loans, and for each one, how overdue their oldest loan is.

**Ask first.** What counts as overdue? Still open (`returned_at IS NULL`) and past `due_at`. Do members with none appear? No. How are ties ordered? By the oldest due date. Each answer changes the query.

```sql
SELECT m.id, m.name, count(*) AS overdue, min(l.due_at) AS oldest_due
FROM loans l
JOIN members m ON m.id = l.member_id
WHERE l.returned_at IS NULL
  AND l.due_at < now()
GROUP BY m.id
ORDER BY overdue DESC, oldest_due
LIMIT 10;
```

Read it out in logical order: take the loans, keep the open and overdue ones, attach each to its member, group, count, sort, keep ten. `GROUP BY m.id` is enough to select `m.name` because `id` is the primary key, so PostgreSQL knows the name depends on it. Some databases don't accept that; if unsure, add `m.name` to the `GROUP BY`.

**The index.** Next comes "How do you make this fast?" Start from what exists. Shelfwise already has `loans_member_open_idx`, a partial index on `member_id` for open loans only, and PostgreSQL can use it here because its condition matches the query's `returned_at IS NULL`: the plan reads the open loans through it and filters them by date, so the history is never scanned. The better index matches the query's own filter:

```sql
CREATE INDEX loans_open_due_idx ON loans (due_at) INCLUDE (member_id) WHERE returned_at IS NULL;
```

Say why in three parts. It is **partial**, so it holds only open loans, and there can never be more of those than copies. It is **ordered by `due_at`**, so `due_at < now()` becomes a range scan over the overdue loans alone. And it **includes `member_id`**, so the join key comes from the index and the plan becomes an index-only scan. Then name the cost from Chapter 14: one more index to update on every lend and return, worth it only if the report runs often, which is a question to ask. End with "I'd confirm it with `EXPLAIN ANALYZE`", not with a number you can't measure in the room.

A common follow-up is the same count for every member, including those with no loans. That needs a `LEFT JOIN`, which has a trap.

<Pitfall title="The LEFT JOIN that quietly loses rows">
To count open loans for every member, the condition on loans goes in the `ON` clause and you count a right-hand column: `LEFT JOIN loans l ON l.member_id = m.id AND l.returned_at IS NULL` with `count(l.id)`. Move `l.returned_at IS NULL` into `WHERE` and members whose loans are all returned vanish, because every joined row has a non-null `returned_at`. Members who never borrowed survive, since their joined columns are all `NULL`. And `count(*)` shows 1 for every member with no open loans. Both bugs pass a test with only active members, so include one member of each kind in your examples.
</Pitfall>

**The invariant.** Last comes the question that links the SQL to the endpoint: "How do you guarantee a copy is never lent twice at once?" A check in the application can be passed by two concurrent requests. The strong answer is the one Shelfwise uses:

```sql
CREATE UNIQUE INDEX one_open_loan_per_copy ON loans (copy_id) WHERE returned_at IS NULL;
```

Explain the `WHERE`: a plain `UNIQUE (copy_id)` would allow one loan per copy, ever, while the partial index allows any number of returned loans and at most one open one. If two transactions insert an open loan for the same copy, the second waits for the first to commit, then fails with a unique violation (SQLSTATE `23505`) naming `one_open_loan_per_copy`. That is what the store turns into `null` and the handler into 409 `copy-on-loan`. It is Chapter 23's lesson in its smallest form: when the database can evaluate the rule atomically, let it, and keep any application check only for clearer errors.

<InterviewLens>
"And the five-loan limit? Is it safe?" No, and saying so unprompted is a strong signal. Two requests for a member with four open loans can both count four and both insert, which leaves six. No unique index can express "at most five". Serialise lending per member instead: in one transaction, `SELECT 1 FROM members WHERE id = $1 FOR UPDATE`, then count, then insert. A second request for the same member waits at the lock, and its count then sees the first loan. Another option is a new `open_loans` column on `members`, updated with a conditional write, `SET open_loans = open_loans + 1 WHERE id = $1 AND open_loans < 5`, which is Chapter 23's seat claim. Name the cost: lending to one member becomes sequential, which is harmless at a library's scale.
</InterviewLens>

### A code-review exercise

In the third format, the interviewer shares a pull request and asks you to review it out loud. The problems planted in it differ widely in severity, and telling them apart is part of the test. The snippet is TypeScript, with Express 5 and `pg`, because every reader of this book can read it; the problems are the same in any language.

Read it and find at least six problems before reading on.

```ts
// POST /members/:id/checkout   body: { "copyIds": [12, 40, 41] }
// Lends several copies in one request and emails the member a receipt.
app.post("/members/:id/checkout", async (req, res) => {
  const member = (await pool.query(`SELECT * FROM members WHERE id = ${req.params.id}`)).rows[0];

  const loans = [];
  for (const copyId of req.body.copyIds) {
    const inserted = await pool.query(
      "INSERT INTO loans (copy_id, member_id, due_at) VALUES ($1, $2, now() + interval '21 days') RETURNING id",
      [copyId, member.id],
    );
    const book = await pool.query(
      "SELECT b.title FROM copies c JOIN books b ON b.id = c.book_id WHERE c.id = $1",
      [copyId],
    );
    loans.push({ id: inserted.rows[0].id, copyId, title: book.rows[0].title });
  }

  for (let attempt = 1; attempt <= 3; attempt++) {
    try {
      await fetch("http://mailer.internal/receipts", {
        method: "POST",
        body: JSON.stringify({ to: member.email, loans }),
      });
      break;
    } catch (err) {
      console.log(err);
    }
  }

  res.status(201).json(loans);
});
```

Read it twice: once for intent (what should be true when it returns 201?) and once for risk. Then raise the findings most severe first, not in line order, so that if time runs out after three, the interviewer has heard the three that matter.

1. **SQL injection.** `req.params.id` is pasted into the SQL text, so the path becomes part of the query. *Fix:* parse the id as a positive integer, return 400 `invalid-id` otherwise, and pass it as `$1` (Chapter 22).
2. **No transaction around the inserts.** If the third copy is already on loan, its insert fails after the first two loans are committed. The client sees an error and retries, and now the first copy fails too, because it is on loan to this same member. *Fix:* one transaction (`BEGIN`, `COMMIT`, `ROLLBACK` on any error) on one pooled client, so a checkout succeeds or fails as a whole (Chapter 23).
3. **The business rules are bypassed.** An unknown member makes `member.id` throw: a 500, not a 404. The five-loan limit is never checked. A copy on loan becomes a 500, not 409 `copy-on-loan`. And `copyIds` is not validated, so a missing array throws and ten thousand ids are accepted. *Fix:* validate the body (Chapter 13) and reuse the rules of `POST /loans` instead of half-duplicating them.
4. **A retry that can send the receipt twice, or report a failure as success.** If the mailer accepts the email but the response is lost, the next attempt sends it again. And `fetch` rejects only on network errors, so a 503 from the mailer resolves normally and the loop stops as if the receipt had gone out. The attempts also run back to back. *Fix:* an `Idempotency-Key` derived from the checkout (Chapter 24), a check of `res.ok`, and backoff with jitter (Chapter 37).
5. **No timeout.** Nothing bounds how long the `fetch` can take, so a slow mailer makes every checkout slow. *Fix:* `signal: AbortSignal.timeout(2000)`, shorter than the caller's own deadline (Chapter 37).
6. **The error is swallowed.** After three failures the member gets a 201, no receipt and no one is told; `console.log` carries no request id and raises no alert. *Fix:* structural. Record a "send receipt" job in the same transaction as the loans and let a worker deliver it with retries (Chapter 24's jobs, or Chapter 34's outbox), so the checkout no longer depends on the mailer.
7. **N+1 queries.** Each copy costs an insert and a lookup: 2n round trips for n copies (Chapter 15). *Fix:* one `INSERT … SELECT … FROM unnest($2::bigint[])` with `RETURNING`, and one title query with `c.id = ANY($2)`.
8. **Smaller things.** `SELECT *` loads unused columns. The `fetch` sets no `Content-Type`, so the body goes out as `text/plain;charset=UTF-8`. The `21 days` is hard-coded, though Shelfwise reads `LOAN_DAYS` from configuration (Chapter 16).

Naming, formatting and a type for `loans` are not on the list. Raise them only once everything else is done, labelled as nits.

Phrasing matters as much as finding. Chapter 48 gave the rules: label each comment, explain why, propose a fix. In the room that becomes one or two sentences per finding: the label, what goes wrong and for which input, and the change:

> **Blocking:** the member id goes into the SQL text unescaped, so the path decides what the query does. Parse it as a positive integer and pass it as `$1`.

> **Question:** if the mailer accepts the email but the response is lost, the retry sends a second receipt. Does the mailer accept an idempotency key? If not, I'd move the email to a job written in the same transaction as the loans.

The first states a fact and a fix, because the problem is certain. The second asks, because the answer depends on a system you can't see, which is how a senior reviewer handles it in a real team too. Describe what the code does, not what its author failed to do.
