Most of these problems need nothing more than a loop, an array and a hash map. They are the first problems to practise in a language you rarely write, because they train the vocabulary every other topic uses: creating and filling an array, looking a key up with a default, counting, and returning a pair.

## 001 · Duplicate Barcodes

**Arrays and Hashing · Easy**

Every copy in a Shelfwise branch carries a barcode label, and a stocktake produces the list of labels scanned on the shelves. Given that list, return `true` if any barcode appears more than once and `false` otherwise. Two barcodes are the same only if the strings are exactly equal, so case matters. An empty list has no duplicates.

```text
Example 1
  input:  barcodes = ["SW-1042", "SW-0007", "SW-2210", "SW-0007"]
  output: true         (SW-0007 is scanned twice)

Example 2
  input:  barcodes = ["SW-1042", "SW-0007", "SW-2210"]
  output: false
```

Constraints: `0 ≤ barcodes.length ≤ 10⁵`, `1 ≤ barcodes[i].length ≤ 20`.

**Approach.** The simple solution compares every pair of barcodes: O(n²). Sorting a copy puts equal barcodes next to each other, so one pass over neighbours finds a duplicate in O(n log n). The pairwise version keeps asking "have I seen this one before?", and a hash set answers that in O(1): walk the list once, return `true` as soon as a barcode is already in the set, and add it otherwise. In C#, Java and Kotlin, `add` returns `false` when the element was already there, so the check and the insert are one call.

<Solutions n="001" />

**Complexity.** O(n) time, O(n) space for the set of barcodes seen so far.

**Common mistake.** Keeping the seen barcodes in a list instead of a set: `contains` on a list scans it, so the "one pass" solution is O(n²) again and times out on 10⁵ barcodes.

## 002 · Two Prices for a Budget

**Arrays and Hashing · Easy**

A shop lists item prices in an array. Given a budget, return the positions of two different items whose prices add up to exactly the budget, as `[i, j]` with `i < j`. If several pairs work, return the one whose `j` is smallest, and among those the smallest `i`. If no pair works, return an empty array. Two items may have the same price, but one item cannot be counted twice.

```text
Example 1
  input:  prices = [12, 7, 3, 9, 5], budget = 12
  output: [2, 3]        (3 + 9; 7 + 5 also works but ends later)

Example 2
  input:  prices = [4, 4, 1], budget = 8
  output: [0, 1]        (same price, different items)
```

Constraints: `0 ≤ prices.length ≤ 10⁵`, `1 ≤ prices[i] ≤ 10⁹`, `1 ≤ budget ≤ 2 × 10⁹`.

**Approach.** The simple solution checks every pair, with `j` in the outer loop and `i` in the inner one so that the first pair found is the one the rules ask for: O(n²). The inner loop is only looking for one value, `budget - prices[j]`, among the earlier prices. A hash map from price to the first index where it appeared answers that in O(1), so one pass is enough. Check the map before adding the current price, so an item never pairs with itself, and store only the first index of each price, so the earliest `i` wins.

<Solutions n="002" />

**Complexity.** O(n) time, O(n) space for the map.

**Common mistake.** Storing every index of a price (overwriting the map entry) instead of the first one, which returns `[1, 2]` instead of `[0, 2]` for `[3, 3, 9]` and a budget of 12.

## 003 · Same Letters, Different Order

**Arrays and Hashing · Easy**

Given two words made of lowercase English letters, return `true` if one is a rearrangement of the other: the same letters, each used the same number of times, in any order. A word counts as a rearrangement of itself, and two empty words are rearrangements of each other.

```text
Example 1
  input:  a = "dusty", b = "study"
  output: true

Example 2
  input:  a = "aab", b = "abb"
  output: false        (same letters, different counts)
```

Constraints: `0 ≤ a.length, b.length ≤ 5 × 10⁴`, both contain only `a`–`z`.

**Approach.** The simple solution sorts both words and compares them: O(n log n). Sorting does more than the question needs, because only the number of times each letter appears matters, not its position. With only 26 possible letters, an array of 26 counters indexed by `letter - 'a'` is a hash map that never collides. If the lengths differ, return `false` straight away; otherwise add one for each letter of `a`, subtract one for each letter of `b`, and the words match exactly when every counter ends at zero.

<Solutions n="003" />

**Complexity.** O(n) time, O(1) space (26 counters, whatever the length of the words).

**Common mistake.** Comparing the sets of letters instead of their counts, which says `"aab"` and `"abb"` match because both use only `a` and `b`.

## 004 · The Missing Ticket

**Arrays and Hashing · Easy**

A SeatLock event printed tickets numbered `1` to `n`, and every ticket but one was scanned at the door. You get the scanned numbers in the order they were scanned, each exactly once, so the array has `n - 1` elements. Return the number of the ticket that was never scanned. If nothing was scanned, `n` is 1 and the answer is `1`.

```text
Example 1
  input:  scanned = [3, 1, 4, 5]
  output: 2            (tickets 1 to 5; 2 is absent)

Example 2
  input:  scanned = [1]
  output: 2            (the missing ticket can be the last one)
```

Constraints: `0 ≤ scanned.length ≤ 10⁵`, the numbers are distinct and between `1` and `scanned.length + 1`.

**Approach.** The simple solution checks each candidate from `1` to `n` against the whole array: O(n²). Putting the scanned numbers in a hash set makes each check O(1), for O(n) time and O(n) space. But the numbers `1` to `n` are known in advance, and their sum is `n × (n + 1) / 2`, so the missing ticket is that total minus the sum of the scanned ones, with no extra memory at all. In C#, Java and Kotlin do the arithmetic in a 64-bit `long`; Go's `int` is already 64 bits on the usual platforms, and Python and TypeScript numbers are exact at this size.

<Solutions n="004" />

**Complexity.** O(n) time, O(1) space.

**Common mistake.** Computing `n * (n + 1) / 2` in a 32-bit `int` in C#, Java or Kotlin: the product overflows once `n` passes 46,340, so the code returns a wrong answer for tickets `1` to `70000`.

## 005 · The Majority Genre

**Arrays and Hashing · Easy**

Shelfwise records the genre of every book borrowed in a month. Given that list, return the genre that accounts for more than half of the loans. If no genre has a strict majority (including when the list is empty), return an empty string. At most one genre can have more than half, so the answer is never ambiguous.

```text
Example 1
  input:  loans = ["mystery", "poetry", "mystery", "history", "mystery"]
  output: "mystery"    (3 of 5)

Example 2
  input:  loans = ["poetry", "history", "poetry", "history"]
  output: ""           (exactly half is not a majority)
```

Constraints: `0 ≤ loans.length ≤ 10⁵`, `1 ≤ loans[i].length ≤ 30`.

**Approach.** The simple solution counts each genre by scanning the whole list again: O(n²). Every rescan repeats counting that has already been done, so keep a hash map from genre to count instead and update it in one pass. The moment a genre's count `c` satisfies `c × 2 > n`, it is the majority and can be returned; if the loop ends, there is none. If the interviewer asks for O(1) space, the follow-up is the Boyer–Moore voting algorithm, which keeps one candidate and one counter, plus a second pass to confirm the candidate really has a majority.

<Solutions n="005" />

**Complexity.** O(n) time, O(k) space for the map, where k is the number of distinct genres.

**Common mistake.** Testing `count >= n / 2` with integer division, which returns `"poetry"` for `["poetry", "history"]`: compare `count * 2 > n` so that exactly half never counts.

## 006 · The Unpaired Seat

**Arrays and Hashing · Easy**

SeatLock's audit log writes a seat's number once when a hold is placed and once when it is released. After a failed deploy, exactly one hold was never released. Given the log as an array of seat numbers in any order, where every seat appears exactly twice except one that appears once, return that seat.

```text
Example 1
  input:  log = [14, 3, 14, 8, 3]
  output: 8

Example 2
  input:  log = [21]
  output: 21
```

Constraints: `1 ≤ log.length ≤ 10⁵` and odd, `1 ≤ log[i] ≤ 10⁹`, exactly one seat appears once.

**Approach.** The simple solution counts each seat by scanning the log again: O(n²). A hash set fixes that in one pass: add a seat the first time you see it, remove it the second time, and the one left at the end is the answer, for O(n) time and O(n) space. The set can go entirely, because XOR does the same pairing in a single integer: `x ^ x` is `0`, `x ^ 0` is `x`, and the order does not matter, so XOR-ing every number in the log cancels the pairs and leaves the unpaired seat. In TypeScript `^` works on 32-bit integers, which is enough for seat numbers up to 10⁹.

<Solutions n="006" />

**Complexity.** O(n) time, O(1) space.

**Common mistake.** Sorting and comparing neighbours two at a time (`log[i]` with `log[i + 1]`) without handling the case where the unpaired seat sorts last: for `[4, 4, 9]` the loop reads past the end of the array.

## 007 · Add One to a Digit Array

**Arrays and Hashing · Easy**

A non-negative integer is stored as an array of its decimal digits, most significant first, with no leading zeros (the number zero is `[0]`). Return a new array holding the digits of that number plus one, in the same format. Do not modify the input array.

```text
Example 1
  input:  digits = [1, 2, 9]
  output: [1, 3, 0]

Example 2
  input:  digits = [9, 9, 9]
  output: [1, 0, 0, 0]  (the result has one more digit)
```

Constraints: `1 ≤ digits.length ≤ 10⁴`, `0 ≤ digits[i] ≤ 9`.

**Approach.** The tempting solution converts the digits to a number, adds one and converts back, but 10⁴ digits do not fit in a 64-bit integer, and even where big integers exist (Python's `int`, Java's `BigInteger`) the conversion skips the carry logic the problem is about. Do what you would do on paper instead: copy the array and walk it from the last digit. A digit below 9 is increased and the copy returned at once, because the carry stops there; a 9 becomes 0 and the carry moves one place left. If the loop finishes, every digit was 9, so the answer is a 1 followed by that many zeros, one digit longer than the input.

<Solutions n="007" />

**Complexity.** O(n) time, O(n) space for the copy that is returned.

**Common mistake.** Converting the digits to an integer: twenty 9s already overflow a 64-bit integer, and in TypeScript precision is lost past 2⁵³, so `[9, 9, …, 9]` comes back wrong.

## 008 · Best Single Trade

**Arrays and Hashing · Easy**

An array holds the price of one item on consecutive days. You may buy it on one day and sell it on a later day, once. Return the largest profit (sell price minus buy price) you can make. If no trade makes a profit, including when there are fewer than two days, return `0`.

```text
Example 1
  input:  prices = [8, 3, 6, 1, 7, 4]
  output: 6            (buy at 1, sell at 7 the next day)

Example 2
  input:  prices = [9, 7, 4, 2]
  output: 0            (the price only falls)
```

Constraints: `0 ≤ prices.length ≤ 10⁵`, `0 ≤ prices[i] ≤ 10⁴`.

**Approach.** The simple solution tries every buy day with every later sell day: O(n²). For a fixed sell day, the best buy day is simply the cheapest day before it, and the inner loop recomputes that minimum from scratch each time. Keep it in a variable instead: walk the prices once, update the lowest price seen so far, and compare today's price minus that lowest with the best profit so far. Starting the lowest price at the largest integer (or infinity) makes an empty array return `0` with no special case.

<Solutions n="008" />

**Complexity.** O(n) time, O(1) space.

**Common mistake.** Subtracting the overall minimum from the overall maximum, which ignores the order of the days: for `[5, 9, 1]` it returns 8, but you cannot buy at 1 after selling at 9, so the answer is 4.

## 009 · Rotate the Carousel

**Arrays and Hashing · Easy**

The SeatLock home page shows featured event IDs in a carousel. Each tick moves every slide one position to the right, and the last slide wraps around to the front. Given the slides and a number of ticks `k`, rotate the array **in place** so that it holds the order after `k` ticks; the function returns nothing. `k` may be larger than the number of slides, and an empty carousel stays empty.

```text
Example 1
  input:  slides = [1, 2, 3, 4, 5], k = 2
  output: [4, 5, 1, 2, 3]

Example 2
  input:  slides = [10, 20], k = 5
  output: [20, 10]      (5 ticks on 2 slides is the same as 1)
```

Constraints: `0 ≤ slides.length ≤ 10⁵`, `0 ≤ k ≤ 10⁹`.

**Approach.** The simple solution performs `k` single-step rotations: O(n × k), hopeless for `k` up to 10⁹. The first fix is `k %= n`, since every `n` ticks bring the carousel back where it started. Writing each slide to position `(i + k) % n` of a new array is O(n) but uses O(n) extra memory. Three reversals do it in place: reverse the whole array, then reverse the first `k` slides, then the rest, and every slide lands `k` places to the right. C#, Kotlin and Go have a built-in range reverse (`Array.Reverse`, `IntArray.reverse`, `slices.Reverse` on a subslice); TypeScript, Java and Python use a short helper.

<Solutions n="009" />

**Complexity.** O(n) time, O(1) extra space.

**Common mistake.** Forgetting `k %= n`, so the second reversal runs past the end of the array for `[10, 20]` and `k = 5`; and taking `k % n` before checking for an empty array divides by zero.

## 010 · Number Triangle Rows

**Arrays and Hashing · Easy**

Build the first `n` rows of this number triangle. Row 0 is `[1]`. Each following row is one number longer, starts and ends with `1`, and every number in between is the sum of the two numbers diagonally above it in the previous row. Return the rows as a list of lists; for `n = 0` return an empty list.

```text
Example 1
  input:  n = 5
  output: [[1], [1, 1], [1, 2, 1], [1, 3, 3, 1], [1, 4, 6, 4, 1]]

Example 2
  input:  n = 1
  output: [[1]]
```

Constraints: `0 ≤ n ≤ 30` (the largest value, 77,558,760, fits in a 32-bit integer).

**Approach.** Each number is a binomial coefficient, so one could compute every entry from factorials, but the factorials overflow long before row 30 and each entry costs O(n). The triangle's own rule is cheaper: every row is built from the row above it. Start each row as `r + 1` ones, then fill only the inner positions `1 ≤ c < r` with `rows[r - 1][c - 1] + rows[r - 1][c]`. The output itself has about n²/2 numbers, so no solution can do better than that.

<Solutions n="010" />

**Complexity.** O(n²) time, O(n²) space, all of it the returned rows.

**Common mistake.** Running the inner loop over `0 ≤ c ≤ r`, which reads `rows[r - 1][-1]` and one past the end of the previous row; the first and last 1 already come from the initial row.

## 011 · The Balance Point

**Arrays and Hashing · Easy**

Given an array of integers, return the smallest index `i` where the sum of the elements before `i` equals the sum of the elements after `i`. The element at `i` belongs to neither side, and an empty side sums to 0, so index 0 qualifies when everything after it sums to 0. If no index qualifies, including when the array is empty, return `-1`.

```text
Example 1
  input:  nums = [3, 1, 5, 2, 2]
  output: 2        (3 + 1 = 4 on the left, 2 + 2 = 4 on the right)

Example 2
  input:  nums = [1, 2, 3]
  output: -1
```

Constraints: `0 ≤ nums.length ≤ 10⁵`, `-1000 ≤ nums[i] ≤ 1000`.

**Approach.** The simple solution adds up the left side and the right side again for every index: O(n²). Both sums change by only one element as `i` moves right, so there is no need to recompute them. Add the whole array once to get the total, then walk it keeping a running `left` sum: the right side is `total - left - nums[i]`. Compare before adding `nums[i]` to `left`, because the element at `i` is on neither side.

<Solutions n="011" />

**Complexity.** O(n) time, O(1) space.

**Common mistake.** Adding `nums[i]` to `left` before the comparison, which counts the middle element on the left and returns `-1` for `[7]` instead of `0`.

## 012 · Shared Members of Two Lists

**Arrays and Hashing · Easy**

Shelfwise exports two lists of member IDs, for example the members who borrowed a book in March and those who borrowed one in April. Either list may repeat an ID. Return the IDs that appear in both lists, each exactly once, in the order of their first appearance in the first list. If no ID is shared, return an empty array.

```text
Example 1
  input:  first = [104, 211, 104, 350, 87], second = [87, 104, 999, 104]
  output: [104, 87]        (104 is listed once, in the order of first)

Example 2
  input:  first = [1, 2], second = [3, 4]
  output: []
```

Constraints: `0 ≤ first.length, second.length ≤ 10⁵`, `1 ≤ id ≤ 10⁹`.

**Approach.** The simple solution scans `second` for every ID of `first`, and then scans the result to skip IDs already added: O(n × m). A hash set of `second` turns the first scan into an O(1) lookup. For the duplicates, remove the ID from the set the moment you add it to the result: a later repeat in `first` no longer finds it, so one set does both jobs. In TypeScript, C#, Java and Kotlin the set's remove method returns whether the element was there, so the check and the removal are one call; in Go and Python they are two lines.

<Solutions n="012" />

**Complexity.** O(n + m) time, O(m) space for the set of the second list.

**Common mistake.** Checking membership without removing, which returns `[104, 104, 87]` for Example 1.

## 013 · Collapse Consecutive IDs Into Ranges

**Arrays and Hashing · Easy**

A list of copy IDs is sorted in strictly increasing order. Collapse it into ranges for display: every maximal run of consecutive IDs becomes `"a-b"` (first and last ID of the run, joined by a hyphen), and an ID with no neighbour becomes just `"a"`. Return the strings in order. An empty list gives an empty result.

```text
Example 1
  input:  ids = [1, 2, 3, 7, 9, 10]
  output: ["1-3", "7", "9-10"]

Example 2
  input:  ids = [0, 2, 4]
  output: ["0", "2", "4"]        (no two IDs are consecutive)
```

Constraints: `0 ≤ ids.length ≤ 10⁵`, `0 ≤ ids[i] ≤ 10⁹`, `ids` strictly increasing.

**Approach.** Because the list is sorted, a run is always a stretch of neighbouring elements, so one pass is enough and no hash map is needed. Remember where the run starts, move `i` forward while the next ID is exactly one more than the current one, then emit either the single ID or `start-end` and continue after the run. This is a warm-up for the loop shape, not for the data structure: an inner loop that advances the same index as the outer one, and a string built from two numbers.

<Solutions n="013" />

**Complexity.** O(n) time, O(1) extra space besides the output.

**Common mistake.** Emitting a range only when the next ID breaks the run, which forgets the last run of the list: `[1, 2, 3]` returns `[]` instead of `["1-3"]`.

## 014 · Group Words by Their Letters

**Arrays and Hashing · Medium**

Group the words that use exactly the same letters, the same number of times each (anagrams). Return a list of groups. The groups appear in the order of their first word in the input, and the words inside a group keep their input order. Duplicate words are kept, and the empty string is a word like any other.

```text
Example 1
  input:  words = ["listen", "stone", "silent", "notes", "enlist", "tones", "tab"]
  output: [["listen", "silent", "enlist"], ["stone", "notes", "tones"], ["tab"]]

Example 2
  input:  words = ["loop", "pool", "polo", "lop"]
  output: [["loop", "pool", "polo"], ["lop"]]        (lop has one o, not two)
```

Constraints: `0 ≤ words.length ≤ 10⁴`, `0 ≤ words[i].length ≤ 100`, lowercase `a`–`z` only.

**Approach.** The simple solution compares each word with the first word of every existing group, sorting both to compare them: O(n × g × k log k) for `g` groups. The repeated work is that comparison, and it disappears once every word has a key that is equal exactly for anagrams: its letters in sorted order. A hash map from key to the index of its group in a list of groups puts each word in place in O(1) after sorting it, and the list (rather than the map's own iteration order) keeps the groups in first-appearance order. A key made of 26 letter counts would remove the sort, but the sorted key is shorter to write from memory and fast enough here.

<Solutions n="014" />

**Complexity.** O(n × k log k) time for `n` words of length up to `k`, O(n × k) space for the keys and the groups.

**Common mistake.** Returning the map's values directly: Go, Java's `HashMap` and C#'s `Dictionary` do not promise input order (Go randomises it on purpose), so `["tab", "bat", "cat"]` can come back as `[["cat"], ["tab", "bat"]]`.

## 015 · The k Most Borrowed Books

**Arrays and Hashing · Medium**

Shelfwise logs one title per loan. Given the log and an integer `k`, return the `k` titles with the most loans. Order them by number of loans, highest first; titles with the same number of loans go in ascending order of the title, compared character by character by character code (not by locale). If there are fewer than `k` distinct titles, return all of them in that order.

```text
Example 1
  input:  loans = ["dune", "emma", "dune", "ulysses", "emma", "dune", "beloved"], k = 2
  output: ["dune", "emma"]        (3 loans, then 2)

Example 2
  input:  loans = ["emma", "beloved", "ulysses", "beloved", "emma"], k = 2
  output: ["beloved", "emma"]        (both have 2 loans, so alphabetical)
```

Constraints: `0 ≤ loans.length ≤ 10⁵`, `1 ≤ k ≤ 10⁵`, titles are 1 to 50 printable ASCII characters.

**Approach.** The simple solution counts each title by scanning the whole log again: O(n²). One pass with a hash map from title to count removes that rescanning. Then sort the `m` distinct titles by count descending and title ascending, and keep the first `k`; every language uses this counting map plus a comparison sort. A heap of size `k` would bring the sort down to O(m log k), and bucket sort by count to O(n) before the ties are ordered, but the sort is the version to write in an interview unless the interviewer asks for more. The tie rule is what makes the output unique: without it, titles with the same count come out in the map's iteration order, which differs between languages.

<Solutions n="015" />

**Complexity.** O(n + m log m) time for `n` loans and `m` distinct titles, O(m) space for the counts.

**Common mistake.** Breaking ties with a locale-aware comparison (TypeScript's `localeCompare`, C#'s default string comparer), which puts `"apple"` before `"Zola"` when character codes put `"Zola"` first, or with Python's `Counter.most_common`, which keeps tied titles in first-appearance order.

## 016 · Product of Everything Else

**Arrays and Hashing · Medium**

Given an array of integers, return a new array of the same length where position `i` holds the product of every element except the one at `i`. Do not use division. For an array of one element the answer is `[1]` (the product of nothing), and an empty array gives an empty array.

```text
Example 1
  input:  nums = [2, 3, 4, 5]
  output: [60, 40, 30, 24]        (60 = 3 × 4 × 5)

Example 2
  input:  nums = [4, 0, 5]
  output: [0, 20, 0]        (only the zero's own position skips the zero)
```

Constraints: `0 ≤ nums.length ≤ 10⁵`, `-30 ≤ nums[i] ≤ 30`, every answer fits in a 32-bit signed integer.

**Approach.** The simple solution multiplies the other `n - 1` elements for every position: O(n²). Dividing the total product by `nums[i]` would be O(n), but it breaks as soon as the array contains a zero, which is why the rule forbids it. Instead, notice that the answer at `i` is the product of everything before `i` times the product of everything after `i`. One pass left to right writes the "before" product into the output array; a second pass right to left keeps a running "after" product in a single variable and multiplies it in. No extra array is needed besides the output.

<Solutions n="016" />

**Complexity.** O(n) time, O(1) extra space besides the output array.

**Common mistake.** Updating the running product before writing it (`left *= nums[i]` first), which includes the element itself and turns `[2, 3, 4, 5]` into `[120, 120, 120, 120]`.

## 017 · Longest Run of Consecutive IDs

**Arrays and Hashing · Medium**

Shelfwise issues library cards with numeric IDs, and you get them in no particular order, possibly with repeats. Return the length of the longest run of consecutive integers that all appear among the IDs, such as `101, 102, 103`. Repeats count once. An empty list gives 0. Aim for O(n) time, which rules out sorting.

```text
Example 1
  input:  ids = [104, 7, 101, 5, 103, 6, 102]
  output: 4        (101, 102, 103, 104)

Example 2
  input:  ids = [9, 1, 9, 2, 2]
  output: 2        (1, 2; the repeats add nothing)
```

Constraints: `0 ≤ ids.length ≤ 10⁵`, `-10⁹ ≤ ids[i] ≤ 10⁹`.

**Approach.** Sorting and scanning for neighbours works in O(n log n), and the simplest version, counting upwards from every ID with a linear search for the next one, is O(n²) or worse. Put the IDs in a hash set so that "is `x + 1` here?" costs O(1). Counting upwards from every ID still repeats work, since a run of length `L` would be walked `L` times, so only start counting at an ID whose predecessor `x - 1` is not in the set: that ID is where a run begins. Iterate over the set, not the input, so a repeated start ID is not walked twice. Each ID is then visited at most twice, once in the loop and once while extending a run.

<Solutions n="017" />

**Complexity.** O(n) time, O(n) space for the set.

**Common mistake.** Counting from every ID instead of only from run starts, which is still correct but takes O(n²) on `[1, 2, 3, …, 100000]`.

## 018 · Count Stretches With a Target Sum

**Arrays and Hashing · Medium**

A shelf's stock changes every day by some amount, which can be negative. Given the daily changes and a target, count the stretches of one or more consecutive days whose changes add up to exactly the target. Stretches that overlap or contain each other all count separately. An empty array has no stretches, so it gives 0.

```text
Example 1
  input:  changes = [1, 2, 3, -2, 2], target = 3
  output: 4        ([1, 2], [3], [2, 3, -2], [3, -2, 2])

Example 2
  input:  changes = [0, 0, 0], target = 0
  output: 6        (every stretch sums to 0: three of length 1, two of length 2, one of length 3)
```

Constraints: `0 ≤ changes.length ≤ 2 × 10⁴`, `-1000 ≤ changes[i] ≤ 1000`, `-10⁷ ≤ target ≤ 10⁷`.

**Approach.** The simple solution fixes each start day and extends the stretch to the right with a running sum: O(n²). Because changes can be negative, a sliding window does not work: growing the stretch can make the sum go down. Use prefix sums instead: a stretch ending today sums to the target exactly when an earlier prefix sum equals `sum - target`, where `sum` is today's prefix sum. A hash map from prefix sum to how many times it has occurred gives that count in O(1). Seed the map with `0 → 1` for the empty prefix, so stretches that start on day 0 are counted, and look up before you record today's sum.

<Solutions n="018" />

**Complexity.** O(n) time, O(n) space for the map of prefix sums.

**Common mistake.** Forgetting the `0 → 1` seed, which misses every stretch that starts at the first day: `[3]` with a target of 3 returns 0 instead of 1.

## 019 · Validate a Sudoku Board

**Arrays and Hashing · Medium**

A Sudoku board is given as 9 strings of 9 characters each, one string per row; each character is a digit `1`–`9` or `.` for an empty cell. Return `true` if no digit appears twice in the same row, the same column or the same 3 × 3 box (the nine boxes are rows 0–2, 3–5, 6–8 crossed with columns 0–2, 3–5, 6–8). Empty cells are ignored, and the board does not have to be solvable, only free of repeats.

```text
Example 1
  input:  board = [".9.5.3.46",
                   "5.3.46...",
                   "1........",
                   "9.5.....2",
                   "..1.6...5",
                   "4..9....1",
                   ".583...2.",
                   "3.46.9758",
                   ".2...8.1."]
  output: true

Example 2
  input:  the same board with row 2 changed to "1.9......"
  output: false        (the new 9 repeats the 9 in row 0 inside the top-left box;
                        its row and column have no other 9)
```

Constraints: `board.length = 9`, `board[i].length = 9`, each character is `1`–`9` or `.`.

**Approach.** The simple solution checks each of the 27 units (9 rows, 9 columns, 9 boxes) separately with a fresh set, which is three passes over the board but already O(1) for a fixed size. One pass is enough if you keep three 9 × 9 tables of booleans, `inRow[r][d]`, `inCol[c][d]` and `inBox[b][d]`, where `d` is the digit minus one. The only formula to get right is the box number, `b = (r / 3) × 3 + c / 3` with integer division, which numbers the boxes 0 to 8 left to right, top to bottom. For each digit, return `false` if any of its three flags is already set, otherwise set all three.

<Solutions n="019" />

**Complexity.** O(1) time and space for a fixed 9 × 9 board (81 cells, 243 flags); O(n²) time and space for an `n × n` board.

**Common mistake.** Computing the box as `r / 3 + c / 3`, which sends the box at rows 0–2, columns 3–5 and the box at rows 3–5, columns 0–2 to the same number and reports repeats that are not there.

## 020 · Zero Out Rows and Columns

**Arrays and Hashing · Medium**

Given an `m × n` grid of integers, change it in place: for every cell that is 0 in the original grid, set its whole row and its whole column to 0. Only the zeros of the original grid count; a cell that becomes 0 because of this rule does not spread further. Return nothing.

```text
Example 1
  input:  grid = [[1, 2, 3],
                  [4, 0, 6],
                  [7, 8, 9]]
  output: grid becomes [[1, 0, 3],
                        [0, 0, 0],
                        [7, 0, 9]]

Example 2
  input:  grid = [[0, 1, 2, 0],
                  [3, 4, 5, 6],
                  [1, 3, 1, 5]]
  output: grid becomes [[0, 0, 0, 0],
                        [0, 4, 5, 0],
                        [0, 3, 1, 0]]
```

Constraints: `1 ≤ m, n ≤ 200`, `-10⁹ ≤ grid[r][c] ≤ 10⁹`.

**Approach.** The simple solution copies the grid and reads the zeros from the copy while writing into the original: O(m × n) time and O(m × n) extra space. The copy holds far more than you need: all that matters is which rows and which columns contain a zero. So make one pass that records that in two boolean arrays, one of length `m` and one of length `n`, and a second pass that zeroes every cell whose row or column is marked. Separating the two passes is what keeps new zeros from spreading. As a follow-up, the first row and first column of the grid itself can hold the marks, with two extra flags for whether they contained a zero, which brings the extra space to O(1) at the cost of trickier code.

<Solutions n="020" />

**Complexity.** O(m × n) time, O(m + n) space for the row and column marks.

**Common mistake.** Zeroing rows and columns during the first scan, so the new zeros trigger more zeroing: `[[0, 1], [1, 1]]` ends as all zeros instead of `[[0, 0], [0, 1]]`.

## 021 · Read a Matrix in a Spiral

**Arrays and Hashing · Medium**

Given a grid of numbers with `m` rows and `n` columns, return all its values in spiral order. Start at the top-left cell, go right along the top row, down the right column, left along the bottom row and up the left column, then repeat on the ring inside, until every cell has been read exactly once. All rows have the same length, and a grid with no rows returns an empty list.

```text
Example 1
  input:  grid = [[1, 2, 3],
                  [8, 9, 4],
                  [7, 6, 5]]
  output: [1, 2, 3, 4, 5, 6, 7, 8, 9]

Example 2
  input:  grid = [[10, 11, 12, 13],
                  [20, 21, 22, 23],
                  [30, 31, 32, 33]]
  output: [10, 11, 12, 13, 23, 33, 32, 31, 30, 20, 21, 22]
```

Constraints: `0 ≤ m ≤ 100`, `1 ≤ n ≤ 100` when `m > 0`, `-1000 ≤ grid[r][c] ≤ 1000`.

**Approach.** The simple solution walks cell by cell with a direction, turns right whenever the next cell is outside the grid or already visited, and keeps a second grid of visited flags: O(m·n) time, but O(m·n) extra space for the flags. The flags are only there to say where each side ends, and four numbers say the same thing: the first and last unread row (`top`, `bottom`) and column (`left`, `right`). Read the top row and move `top` down, read the right column and move `right` left, then the bottom row and the left column, and loop while `top ≤ bottom` and `left ≤ right`. The subtle part is that after the first two sides the remaining area can already be empty (a single row or column was left), so check the bounds again before reading the bottom row and before reading the left column.

<Solutions n="021" />

**Complexity.** O(m·n) time, O(1) extra space besides the output list.

**Common mistake.** Leaving out the two checks before the bottom row and the left column, so the last row or column is read twice in the other direction: `[[4, 5, 6]]` returns `[4, 5, 6, 5, 4]`.

## 022 · Rotate a Square Image

**Arrays and Hashing · Medium**

An image is stored as an `n × n` grid of pixel values. Rotate it 90 degrees clockwise **in place**: change the grid you are given, without building a second grid, and return nothing. After the rotation, the first row holds the old first column read from bottom to top, the second row the old second column, and so on. An empty grid stays empty.

```text
Example 1
  input:  image = [[1, 2],
                   [3, 4]]
  after:  image = [[3, 1],
                   [4, 2]]

Example 2
  input:  image = [[11, 12, 13],
                   [21, 22, 23],
                   [31, 32, 33]]
  after:  image = [[31, 21, 11],
                   [32, 22, 12],
                   [33, 23, 13]]
```

Constraints: `0 ≤ n ≤ 200`, `0 ≤ image[r][c] ≤ 255`.

**Approach.** The simple solution builds a new grid with `rotated[c][n - 1 - r] = image[r][c]` and copies it back: O(n²) time and O(n²) extra space, which the rule forbids. A clockwise rotation is the same as two moves that each only swap pairs of cells: transpose the grid (swap `image[i][j]` with `image[j][i]`, mirroring it across the main diagonal), then reverse every row. Neither move needs a second grid. In the transpose, visit only the cells above the diagonal (`j > i`), so each pair is swapped once. The checks compare the grid after the call, since the function returns nothing. Java has no built-in to reverse an `int[]`, so its version reverses each row with two indices.

<Solutions n="022" />

**Complexity.** O(n²) time, O(1) extra space.

**Common mistake.** Running the transpose over every `j` instead of `j > i`, which swaps each pair twice and leaves the grid as it was, so example 1 ends as `[[2, 1], [4, 3]]`: only the row reversal happened.

## 023 · A Set With Random Pick in O(1)

**Arrays and Hashing · Medium**

SeatLock's "any seat" button holds a random free seat. Design `RandomSet`, a set of integers with three operations, each O(1) on average: `add(x)` adds `x` and returns `true`, or returns `false` if `x` is already in the set; `remove(x)` removes `x` and returns `true`, or returns `false` if it is not there; `pick()` returns one of the current elements, each with the same probability. `pick` is only called when the set is not empty.

So that the tests are deterministic, the constructor receives the random source: a function `randomIndex(n)` that returns an integer in `[0, n)`. Each `pick` calls it exactly once, with `n` equal to the current size, and different results must pick different elements. The checks pass a source that returns 0, 1, 2… in turn (modulo `n`), so `n` picks in a row must return every element once.

```text
Example 1
  calls:   add(12), add(7), add(12), add(30), remove(7), remove(7), remove(99)
  returns: true, true, false, true, true, false, false

Example 2
  set:     {12, 30}, and randomIndex returns 0, then 1
  calls:   pick(), pick()
  returns: 12 and 30, one each (which comes first depends on the layout)
```

Constraints: `-10⁹ ≤ x ≤ 10⁹`, at most `10⁵` calls in total.

**Approach.** A hash set alone gives O(1) `add` and `remove`, but it can't return its k-th element without walking it, so `pick` is O(n). An array alone gives O(1) `pick` but needs O(n) to find and delete an element. Use both: an array `items` of the elements and a map from each element to its index in the array. `add` appends and records the index. `remove` looks up the index `i`, pops the last element, and if that element isn't `x` itself, puts it in slot `i` and updates its map entry; then it deletes `x` from the map. `pick` returns `items[randomIndex(items.length)]`. In production you would pass the language's generator: `Math.floor(Math.random() * n)`, `Random.Shared.Next(n)`, `ThreadLocalRandom.current().nextInt(n)`, `Random.nextInt(n)`, `rand.Intn(n)` or `random.randrange(n)`.

<Solutions n="023" />

**Complexity.** O(1) average time per call, O(n) space for the array and the map.

**Common mistake.** Forgetting to update the map entry of the element that moved into the hole: after `add(12)`, `add(7)`, `add(30)` and `remove(7)`, the map still says 30 is at index 2, so a later `remove(30)` empties the wrong slot.

## 024 · The Smallest Missing Positive

**Arrays and Hashing · Hard**

Shelfwise gives each new member card the smallest positive number that no card uses yet. Given the numbers in use, in any order, possibly with duplicates and with zero or negative values left over from an old import, return the smallest positive integer that is not in the array. Use O(n) time and O(1) extra space; you may reorder the array.

```text
Example 1
  input:  nums = [3, 1, -2, 2, 7]
  output: 4        (1, 2 and 3 are taken)

Example 2
  input:  nums = [5, 2, 2, 9]
  output: 1
```

Constraints: `0 ≤ nums.length ≤ 10⁵`, `-2³¹ ≤ nums[i] ≤ 2³¹ - 1`.

**Approach.** The simple solution puts every value in a hash set and tries 1, 2, 3… until one is missing: O(n) time but O(n) extra space; sorting first avoids the set but costs O(n log n). The key fact is that the answer is between 1 and `n + 1`, because `n` values can fill at most the numbers 1 to `n`. So only values in `[1, n]` matter, and the array itself can be the set: value `v` belongs at index `v - 1`. For each index, keep swapping its value into its own slot until the index holds a value outside `[1, n]` or a value whose slot already holds the same value. Then the first index `i` with `nums[i] != i + 1` gives the answer `i + 1`, and if there is none the answer is `n + 1`. Compute the target index `j` before swapping: in Python, `nums[i], nums[nums[i] - 1] = nums[nums[i] - 1], nums[i]` assigns `nums[i]` first and then uses the new value to find the second slot.

<Solutions n="024" />

**Complexity.** O(n) time, since every swap puts one value in its final slot and so there are at most `n` swaps in total; O(1) extra space.

**Common mistake.** Swapping while `nums[i] != i + 1` instead of while the target slot doesn't already hold the value, which loops forever on a duplicate such as `[1, 1]`.

## 025 · Most Points on One Line

**Arrays and Hashing · Hard**

Parcel and Pulse plots delivery stops as points with integer coordinates `[x, y]`. Return the largest number of stops that lie on one straight line. Two stops can share a location; each one still counts, and a shared location lies on every line through it. An empty list returns 0 and a single stop returns 1.

```text
Example 1
  input:  points = [[1, 1], [2, 3], [3, 5], [4, 2], [0, -1]]
  output: 4        (y = 2x - 1 passes through all but [4, 2])

Example 2
  input:  points = [[3, 4], [3, 4], [3, -1], [0, 0]]
  output: 3        (the vertical line x = 3, with the shared location counted twice)
```

Constraints: `0 ≤ points.length ≤ 300`, `-10⁴ ≤ x, y ≤ 10⁴`.

**Approach.** The simple solution takes every pair of points as a line and counts the points on it with the cross product, `(x₂ - x₁)(y - y₁) == (y₂ - y₁)(x - x₁)`: O(n³). Fix one anchor point `i` instead: the points that share a line with it are the ones in the same direction from it, so group the later points `j > i` by the direction from `i` to `j`, and the biggest group plus `i` and its copies is the best line through `i`. Checking only `j > i` is enough, because every line is counted when its first point is the anchor. The direction has to be an exact key, not a floating-point slope (vertical lines divide by zero, and rounding can merge different slopes): divide `(dx, dy)` by their greatest common divisor and flip both signs so that `dx > 0`, or `dy > 0` when `dx` is 0. The key type is vocabulary: a tuple in C# and Python, a record in Java, a `Pair` in Kotlin, a `[2]int` in Go, and the string `"dx,dy"` in TypeScript, whose `Map` compares arrays by reference. Python has `math.gcd`; the other versions write a small `gcd` function.

<Solutions n="025" />

**Complexity.** O(n² log C) time, where the log factor is the gcd on coordinates up to `C`; O(n) space for the direction map of one anchor.

**Common mistake.** Reducing by the gcd but not fixing the sign, so `(1, -1)` and `(-1, 1)` count as two directions: `[[0, 0], [1, -1], [-1, 1], [2, -2]]` returns 3 instead of 4.
