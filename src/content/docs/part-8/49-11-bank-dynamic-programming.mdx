Dynamic programming is recursion that remembers: when the same smaller question comes up again and again, answer each one once and store it. These problems train one habit, said out loud before any code: define the state in words ("`ways[i]` is the number of ways to stand on step `i`"), write the recurrence that builds a state from smaller ones, and only then choose between top-down, a memoised recursion that is quick to write but limited by stack depth (the Python section explains why `@cache` can crash on deep inputs), and bottom-up, a loop that fills the table from the smallest state upwards. The solutions here are bottom-up, so the six languages look alike and none of them hits a recursion limit, and whenever a step reads only the last row or the last few values, they keep those instead of the whole table.

## 163 · Ways to Climb the Stairs

**Dynamic Programming · Easy**

A staircase has `n` steps, and each move climbs either one step or two. Return the number of different sequences of moves that end exactly on the top step; two sequences are different if they differ in any move. For `n = 0` there is exactly one way, the empty sequence.

```text
Example 1
  input:  n = 4
  output: 5        (1+1+1+1, 1+1+2, 1+2+1, 2+1+1, 2+2)

Example 2
  input:  n = 1
  output: 1
```

Constraints: `0 ≤ n ≤ 70`. The answer grows past 2³¹ − 1 at `n = 46` and reaches about 3.1 × 10¹⁴ at `n = 70`, so return a 64-bit integer (`long`, `Long`, `int64`); that is still below 2⁵³, so a TypeScript `number` stays exact, and Python integers have no limit.

**Approach.** The simple solution follows the definition: the last move is one step or two, so the count for `n` is the count for `n - 1` plus the count for `n - 2`, computed by plain recursion. That recursion asks for the same small counts again and again, and the number of calls grows like the answer itself, exponentially. State it as dynamic programming: `ways[i]` is the number of ways to stand on step `i`, with `ways[0] = ways[1] = 1` and `ways[i] = ways[i - 1] + ways[i - 2]`. Filling it from 2 to `n` is O(n), and since each value reads only the two before it, two variables replace the table. Go returns `int64` rather than `int`, whose size depends on the platform.

<Solutions n="163" />

**Complexity.** O(n) time, O(1) space for the two running counts.

**Common mistake.** Keeping the count in a 32-bit `int`: the answer for `n = 46` is 2,971,215,073, larger than 2³¹ − 1, so it wraps to a negative number instead of failing loudly.

## 164 · Rob Houses Without Tripping the Alarm

**Dynamic Programming · Easy**

Houses stand in a row along one street, and `cash[i]` is the amount hidden in house `i`. A burglar may break into any set of houses except two next to each other, because neighbouring houses share an alarm line. Return the largest total the burglar can take. With no houses the total is 0.

```text
Example 1
  input:  cash = [6, 1, 2, 9]
  output: 15        (houses 0 and 3)

Example 2
  input:  cash = [5, 10, 4, 3, 8]
  output: 18        (houses 1 and 4)
```

Constraints: `0 ≤ cash.length ≤ 10⁴`, `0 ≤ cash[i] ≤ 10⁴`.

**Approach.** The simple solution tries every set of houses with no two neighbours, and the number of such sets grows exponentially with the length of the street. Greedy rules such as "take every other house" or "take the richest house first" fail on inputs like `[2, 1, 1, 2]`. State it instead: `best[i]` is the largest total from the first `i` houses. For the next house there are two choices, skip it and keep `best[i]`, or take it, which rules out the house before, for `best[i - 1] + cash[i]`; the larger one wins. Each step reads only the last two values, so, as in problem 163, two variables replace the table: the best total up to here and the best total up to the house before.

<Solutions n="164" />

**Complexity.** O(n) time, O(1) space for the two running totals.

**Common mistake.** Comparing the sum of the even-indexed houses with the sum of the odd-indexed ones, which returns 3 for `[2, 1, 1, 2]` instead of 4: the best plan takes houses 0 and 3 and skips two houses in a row.

## 165 · Best Stretch of Daily Results

**Dynamic Programming · Easy**

A shop records its net result for each day: `results[i]` is the profit (positive) or loss (negative) of day `i`. Return the largest total of a stretch of one or more consecutive days. The stretch cannot be empty, so if every day was a loss the answer is the smallest loss.

```text
Example 1
  input:  results = [-2, 4, -1, 3, -7, 2]
  output: 6        (days 1 to 3: 4 - 1 + 3)

Example 2
  input:  results = [-8, -3, -5]
  output: -3       (day 1 alone)
```

Constraints: `1 ≤ results.length ≤ 10⁵`, `-10⁴ ≤ results[i] ≤ 10⁴`.

**Approach.** The simple solution tries every start day and extends a running sum to every end day: O(n²). The state that removes the repeated work is `endingHere`, the best total of a stretch that ends on the current day. A stretch ending today is either today alone or today added to the best stretch ending yesterday, so for the day's result `r`, `endingHere = max(r, endingHere + r)`, and the answer is the largest `endingHere` seen. Only yesterday's value is needed, so one variable replaces the table (this is Kadane's algorithm). Starting `endingHere` at 0 makes the first day come out as itself, so one loop covers every day, while `best` starts at the first day so that an all-loss input is handled.

<Solutions n="165" />

**Complexity.** O(n) time, O(1) space.

**Common mistake.** Starting `best` at 0, which treats the empty stretch as allowed: `[-8, -3, -5]` returns 0 instead of -3.

## 166 · Count the One Bits for Every Number

**Dynamic Programming · Easy**

Given a non-negative integer `n`, return an array `bits` of length `n + 1` where `bits[i]` is the number of 1s in the binary representation of `i`, for every `i` from 0 to `n`.

```text
Example 1
  input:  n = 5
  output: [0, 1, 1, 2, 1, 2]        (0, 1, 10, 11, 100, 101)

Example 2
  input:  n = 0
  output: [0]
```

Constraints: `0 ≤ n ≤ 10⁵`.

**Approach.** The simple solution counts the bits of each number on its own, shifting right until it reaches zero (or calling a built-in popcount where the language has one): O(log n) per number, O(n log n) in total. Every number shares most of its bits with a smaller one: `i >> 1` is `i` with its last binary digit dropped, it is smaller than `i` and so already computed, and the dropped digit is `i & 1`. That gives `bits[i] = bits[i >> 1] + (i & 1)`, filled from 1 to `n`. Here the table can't shrink to a few variables, because `bits[i >> 1]` reaches back halfway, but the table is also the answer.

<Solutions n="166" />

**Complexity.** O(n) time, O(n) space for the output and nothing else.

**Common mistake.** Leaving out the parentheses: in TypeScript and Python `&` binds more loosely than `+`, so `bits[i >> 1] + i & 1` means `(bits[i >> 1] + i) & 1` and `n = 3` gives `[0, 1, 1, 0]`; in Go the same line happens to be correct, because `&` binds as tightly as `*`, which is one more reason to write the parentheses everywhere.

## 167 · Paths Through a Grid

**Dynamic Programming · Easy**

A warehouse robot starts in the top-left cell of a grid with `rows` rows and `cols` columns and must reach the bottom-right cell. Each move goes one cell right or one cell down. Return the number of different paths.

```text
Example 1
  input:  rows = 3, cols = 4
  output: 10

Example 2
  input:  rows = 2, cols = 2
  output: 2        (right then down, or down then right)
```

Constraints: `1 ≤ rows, cols ≤ 100`, and the inputs are such that the answer is at most 2 × 10⁹. No cell's count is larger than the corner's, so every value fits in a 32-bit `int`.

**Approach.** The simple solution recurses: the paths to a cell are the paths to the cell above plus the paths to the cell on its left. Plain recursion recomputes the same cells exponentially many times. As a table, `paths[r][c] = paths[r - 1][c] + paths[r][c - 1]`, with every cell of the first row and the first column equal to 1, is O(rows × cols). Each row reads only the row above, so one array of `cols` counts is enough: going left to right, `row[c]` still holds the value from above when you read it, and `row[c - 1]` already holds the new value on the left, so the update is `row[c] += row[c - 1]`. There is also a formula, the binomial coefficient C(rows + cols − 2, rows − 1), but computing it without overflow needs more care than the loop.

<Solutions n="167" />

**Complexity.** O(rows × cols) time, O(cols) space for the single row.

**Common mistake.** Starting the inner loop at `c = 0`, which reads `row[-1]`: an out-of-range index in most languages, and in Python silently the last cell, so `grid_paths(2, 2)` returns 3 instead of 2.

## 168 · Paint the Houses for Less

**Dynamic Programming · Easy**

A row of houses must each be painted red, green or blue, and `costs[i]` is `[red, green, blue]`, the price of each colour for house `i`. Two neighbouring houses may not have the same colour. Return the lowest total cost of painting every house; with no houses it is 0.

```text
Example 1
  input:  costs = [[8, 3, 6], [4, 9, 2], [7, 5, 1]]
  output: 8        (green 3, red 4, blue 1)

Example 2
  input:  costs = [[1, 2, 9], [1, 9, 9]]
  output: 3        (green 2, then red 1; starting with the cheapest, red 1, forces 9 next)
```

Constraints: `0 ≤ costs.length ≤ 100`, `costs[i].length == 3`, `0 ≤ costs[i][j] ≤ 1000`.

**Approach.** The simple solution tries every valid colouring, 3 × 2ⁿ⁻¹ of them, and picking the cheapest colour for each house in turn fails on Example 2. The state carries the colour: `red[i]` is the cheapest way to paint houses 0 to `i` with house `i` red, and likewise `green[i]` and `blue[i]`. A red house follows a green or a blue one, so `red[i] = costs[i][0] + min(green[i - 1], blue[i - 1])`, and the other two are symmetric; the answer is the smallest of the three after the last house. Each house reads only the one before, so three variables replace the table, but all three must be computed from the old values: C#, Go, Python and TypeScript assign them together as a tuple, and Java and Kotlin compute three temporaries first.

<Solutions n="168" />

**Complexity.** O(n) time, O(1) space for the three running totals.

**Common mistake.** Updating the three totals one after another, so `green` reads the `red` of the current house instead of the previous one: Example 1 returns 14 instead of 8.

## 169 · Region Totals on a Seat Map

**Dynamic Programming · Easy**

SeatLock shows organisers how much a block of seats has earned. Design a class `RegionSums` built from a seat map `grid`, where `grid[r][c]` is the amount paid for the seat in row `r` and column `c` (0 if it is unsold). Its method `sum(r1, c1, r2, c2)` returns the total of the rectangle whose top-left seat is `(r1, c1)` and whose bottom-right seat is `(r2, c2)`, both included. The map does not change after construction, and every call to `sum` must take O(1) time.

```text
Example 1
  grid:    [[3, 0, 1, 4],
            [5, 6, 3, 2],
            [1, 2, 0, 1],
            [4, 1, 0, 5]]
  calls:   sum(1, 1, 2, 2), sum(0, 0, 3, 3), sum(2, 3, 2, 3), sum(0, 1, 3, 2)
  returns: 11, 38, 1, 13

Example 2
  grid:    [[7]]
  calls:   sum(0, 0, 0, 0)
  returns: 7
```

Constraints: `1 ≤ rows, cols ≤ 200`, `0 ≤ grid[r][c] ≤ 10⁴`, `0 ≤ r1 ≤ r2 < rows`, `0 ≤ c1 ≤ c2 < cols`, at most `10⁴` calls to `sum`. The whole map totals at most 4 × 10⁸, which fits in 32 bits.

**Approach.** The simple solution loops over the rectangle on every call: O(rows × cols) per query. Instead, build a table `prefix` with one extra row and column of zeros, where `prefix[r][c]` is the total of every seat above row `r` and left of column `c`. Each entry comes from three already computed ones: `prefix[r + 1][c + 1] = grid[r][c] + prefix[r][c + 1] + prefix[r + 1][c] - prefix[r][c]`, subtracting the top-left block that the other two both include. A query is the same inclusion and exclusion read backwards: the big block to `(r2, c2)`, minus the block above the rectangle, minus the block to its left, plus the corner block that was subtracted twice. The extra row and column remove every special case for `r1 = 0` or `c1 = 0`. C# uses a rectangular `int[,]`; the other languages use an array of rows.

<Solutions n="169" />

**Complexity.** O(rows × cols) time and space to build the prefix table; O(1) time per `sum`.

**Common mistake.** Forgetting to add back the corner block `prefix[r1][c1]`, which both subtractions removed: in Example 1, `sum(1, 1, 2, 2)` returns 8 instead of 11.

## 170 · Fewest Coins for an Amount

**Dynamic Programming · Medium**

Given coin values `coins` (distinct and positive, with an unlimited supply of each) and an `amount`, return the smallest number of coins whose values add up to exactly `amount`. Return `-1` if no combination does. An amount of 0 needs 0 coins.

```text
Example 1
  input:  coins = [1, 4, 6], amount = 8
  output: 2        (4 + 4; taking the largest coin first gives 6 + 1 + 1)

Example 2
  input:  coins = [5, 10], amount = 3
  output: -1
```

Constraints: `1 ≤ coins.length ≤ 12`, `1 ≤ coins[i] ≤ 10⁴`, `0 ≤ amount ≤ 10⁴`.

**Approach.** Taking the largest coin that fits fails on Example 1, so every choice has to be considered. The simple solution recurses: try each coin, solve the remaining amount, keep the best. It is exponential because it solves the same remainders over and over. State it as `fewest[a]`, the fewest coins that add up to `a`: the last coin is some `coin ≤ a`, so `fewest[a] = 1 + min(fewest[a - coin])`, with `fewest[0] = 0`. Fill it from 1 to `amount`. Mark an amount nobody can reach with `amount + 1`, a count no real answer can have, since even all ones need only `amount` coins; adding 1 to it is safe, and any value above `amount` at the end means `-1`.

<Solutions n="170" />

**Complexity.** O(amount × coins.length) time, O(amount) space for the table.

**Common mistake.** Using the largest `int` as "unreachable" and then adding 1 to it, which wraps to the most negative value and wins every `min`: with `coins = [2]` and `amount = 3`, the answer is a large negative number instead of -1.

## 171 · Longest Rising Sequence

**Dynamic Programming · Medium**

Given an array `nums`, return the length of its longest strictly rising subsequence: elements taken in their original order, not necessarily next to each other, each one larger than the one before. Equal values do not count as rising. An empty array has length 0.

```text
Example 1
  input:  nums = [3, 1, 8, 2, 5, 9, 4]
  output: 4        (1, 2, 5, 9)

Example 2
  input:  nums = [7, 7, 7]
  output: 1
```

Constraints: `0 ≤ nums.length ≤ 10⁵`, `-10⁹ ≤ nums[i] ≤ 10⁹`.

**Approach.** The classic DP defines `len[i]` as the longest rising sequence that ends at `i`, which is 1 plus the largest `len[j]` with `j < i` and `nums[j] < nums[i]`: O(n²), fine for a few thousand values but too slow for 10⁵. The faster method, sometimes called patience sorting, keeps `tails`, where `tails[k]` is the smallest value that can end a rising sequence of length `k + 1`; this list is always strictly increasing. For each value `x`, binary-search the first tail that is `≥ x`: if there is none, `x` extends the longest sequence and is appended; otherwise it replaces that tail, giving a sequence of that length a lower end that is easier to extend. The answer is the length of `tails`, although `tails` itself need not be a valid subsequence. All six languages implement this O(n log n) method with a hand-written binary search (Python's `bisect_left` would do the same job); Java keeps `tails` in an `int[]` with a size counter to avoid boxing.

<Solutions n="171" />

**Complexity.** O(n log n) time, O(n) space for `tails`.

**Common mistake.** Searching for the first tail strictly greater than `x` instead of greater or equal, which lets equal values extend a sequence: `[7, 7, 7]` returns 3 instead of 1.

## 172 · Can the Text Be Split Into Words?

**Dynamic Programming · Medium**

Given a string `text` of lowercase letters and a list of dictionary `words`, return `true` if `text` can be cut into pieces that are all dictionary words, and `false` otherwise. A word may be used any number of times, and the list may contain duplicates. An empty text needs no words, so it returns `true`.

```text
Example 1
  input:  text = "bookseller", words = ["books", "book", "seller"]
  output: true        (book + seller; starting with "books" leaves "eller")

Example 2
  input:  text = "trucking", words = ["truck", "king", "in"]
  output: false       ("truck" leaves "ing", and "king" would need "truc" before it)
```

Constraints: `0 ≤ text.length ≤ 300`, `0 ≤ words.length ≤ 1000`, `1 ≤ words[i].length ≤ 20`.

**Approach.** The simple solution recurses: try every word that starts the text and recurse on what is left. It is exponential on inputs like `"aaaaaaaaab"` with `["a", "aa"]`, because the same suffix is tried again for every way of reaching it. State it instead: `splits[i]` is whether the first `i` letters can be split, with `splits[0] = true`, and `splits[end]` is true when some earlier `start` has `splits[start]` and `text[start:end]` in the dictionary. Put the words in a hash set, and only try pieces up to the length of the longest word, which bounds the inner loop. The table can't shrink, because `splits[end]` reads up to one word length back.

<Solutions n="172" />

**Complexity.** O(n × L²) time, where `L` is the longest word: at most `L` pieces per position, each costing O(L) to cut and hash. O(n) space for the table, plus the set of words.

**Common mistake.** Taking the first or the longest matching word and never reconsidering it: Example 1 takes `"books"`, gets stuck on `"eller"` and returns `false`.

## 173 · Ways to Decode a Digit String

**Dynamic Programming · Medium**

A message of capital letters is encoded by writing each letter as its position in the alphabet, `A` as `1` up to `Z` as `26`, and joining the numbers with no separator, so `"BZ"` becomes `"226"`. Given the digits, return how many different messages could have produced them. A letter's number never has a leading zero, so `"06"` is not a letter, and neither is `"0"` on its own. If no message produces the digits, return 0.

```text
Example 1
  input:  digits = "2612"
  output: 4        (2 6 1 2, 26 1 2, 2 6 12 and 26 12: BFAB, ZAB, BFL, ZL)

Example 2
  input:  digits = "301"
  output: 0        (the 0 must be part of "30" or stand alone, and neither is a letter)
```

Constraints: `1 ≤ digits.length ≤ 45`, `digits` contains only `0`–`9`. The largest possible answer, for forty-five `1`s, is 1,836,311,903, so the count fits in a 32-bit `int`.

**Approach.** The simple solution recurses: the first letter takes one digit or two, so try both and count the decodings of what is left. It is exponential, because the same suffix is counted again for every way of reaching it. State it as `ways[i]`, the number of decodings of the first `i` digits, with `ways[0] = 1` for the empty prefix. The last letter is either digit `i` alone, allowed when it is not `0`, which adds `ways[i - 1]`, or digits `i - 1` and `i` together, allowed when they make a number from 10 to 26, which adds `ways[i - 2]`. Each step reads only the two values before it, so two variables, `oneBack` and `twoBack`, replace the table.

<Solutions n="173" />

**Complexity.** O(n) time, O(1) space.

**Common mistake.** Accepting any pair of digits whose number is at most 26, without checking that it is at least 10: `"06"` then counts as `F`, and `"106"` returns 2 instead of 1.

## 174 · Longest Common Subsequence

**Dynamic Programming · Medium**

A subsequence of a string is what is left after deleting any number of its letters, possibly none, without changing the order of the others: `"pce"` is a subsequence of `"parcel"`, but `"cp"` is not. Given two strings `a` and `b`, return the length of the longest string that is a subsequence of both. If they have no letter in common, or one of them is empty, return 0.

```text
Example 1
  input:  a = "parcel", b = "place"
  output: 4        ("pace")

Example 2
  input:  a = "seat", b = "lock"
  output: 0
```

Constraints: `0 ≤ a.length, b.length ≤ 1000`, both contain only `a`–`z`.

**Approach.** The simple solution lists all 2ⁿ subsequences of `a` and checks each one against `b`, which is hopeless beyond about 20 letters. Look at the last letters instead. Let `best[i][j]` be the answer for the first `i` letters of `a` and the first `j` letters of `b`, with 0 when either prefix is empty. If `a[i - 1]` equals `b[j - 1]`, the two letters can end the common subsequence, so `best[i][j] = best[i - 1][j - 1] + 1`; otherwise at least one of them is not used, so `best[i][j] = max(best[i - 1][j], best[i][j - 1])`. Filled row by row, row `i` reads only row `i - 1` and itself, so the solutions keep two rows, `prev` and `cur`, instead of the whole table.

<Solutions n="174" />

**Complexity.** O(n × m) time, O(m) space for the two rows.

**Common mistake.** On a match, adding 1 to `max(best[i - 1][j], best[i][j - 1])` instead of to `best[i - 1][j - 1]`, which lets one letter be matched twice: `a = "a"`, `b = "aa"` returns 2 instead of 1.

## 175 · Split Into Two Equal-Sum Groups

**Dynamic Programming · Medium**

Parcel and Pulse loads a batch of parcels onto two trucks and wants both trucks to carry exactly the same weight. Given the parcel weights, return `true` if the parcels can be split into two groups with equal total weight, every parcel going into exactly one group, and `false` otherwise. A parcel cannot be divided.

```text
Example 1
  input:  weights = [3, 1, 4, 2, 2]
  output: true     (4 + 2 and 3 + 1 + 2)

Example 2
  input:  weights = [2, 3, 7]
  output: false    (the total, 12, is even, but no group weighs 6)
```

Constraints: `1 ≤ weights.length ≤ 200`, `1 ≤ weights[i] ≤ 100`.

**Approach.** The simple solution tries all 2ⁿ ways to assign the parcels, which is far too many at 200 parcels. If the total is odd the answer is `false`; otherwise the question becomes whether some group weighs exactly `half = total / 2`, since the other parcels then weigh `half` too. The weights are small, so the possible group weights are few: `reachable[s]` says whether some of the parcels seen so far weigh exactly `s`, and at the start only `reachable[0]` is true. A parcel of weight `w` makes `s` reachable whenever `s - w` already was. Walk `s` from `half` down to `w`, so every entry read in this pass still describes the parcels before this one; walking up would let the same parcel be added again and again.

<Solutions n="175" />

**Complexity.** O(n × half) time, at most 200 × 10,000 = 2 × 10⁶ steps, and O(half) space for the array.

**Common mistake.** Walking `s` upwards, which reuses the parcel just added: `[1, 5]` reaches 3 as 1 + 1 + 1 and returns `true` instead of `false`.

## 176 · Largest Product of a Stretch

**Dynamic Programming · Medium**

Given an array of integers, return the largest product of a stretch, that is, of one or more consecutive elements. The stretch cannot be empty, so an array with a single negative number returns that number.

```text
Example 1
  input:  nums = [2, -5, -2, 4, 0, 3]
  output: 80       (2 × -5 × -2 × 4)

Example 2
  input:  nums = [-3, 0, -2]
  output: 0        (the 0 on its own)
```

Constraints: `1 ≤ nums.length ≤ 2 × 10⁴`, `-10 ≤ nums[i] ≤ 10`, and the product of every stretch is between `-2³¹` and `2³¹ − 1`. Every value the solution computes is the product of some stretch, so a 32-bit `int` holds all of them.

**Approach.** The simple solution starts at every index and extends a running product to every end: O(n²). As in problem 165, the better solution tracks the best stretch that ends at the current element, but a product needs two values, because multiplying by a negative number turns the smallest product into the largest. Keep `hi` and `lo`, the largest and the smallest product of a stretch ending here. For the next element `x`, the candidates are `x` alone, `hi × x` and `lo × x`: the new `hi` is the largest of the three and the new `lo` the smallest, and the answer is the largest `hi` seen. Compute both products before overwriting `hi`, since the new `lo` needs the old one.

<Solutions n="176" />

**Complexity.** O(n) time, O(1) space.

**Common mistake.** Tracking only the largest product: `[-2, 3, -4]` returns 3 instead of 24, because the -6 that the last element turns into 24 was thrown away.

## 177 · Edit Distance

**Dynamic Programming · Hard**

When a Shelfwise member mistypes a title, the search box suggests the closest one, and closeness is measured by the edit distance: the fewest single-letter edits that turn `source` into `target`. An edit inserts one letter anywhere, deletes one letter, or replaces one letter with a different one. Return the edit distance. Two equal strings are at distance 0, and turning a string into the empty string takes one deletion per letter.

```text
Example 1
  input:  source = "shelf", target = "shelves"
  output: 3        (replace f with v, then insert e and s)

Example 2
  input:  source = "loan", target = "lone"
  output: 2        (replace a with n and n with e)
```

Constraints: `0 ≤ source.length, target.length ≤ 500`, both contain only `a`–`z`.

**Approach.** The simple solution recurses on two positions: if the letters are equal it moves past both, otherwise it tries all three edits and keeps the cheapest, which is exponential. The same pair of prefixes comes up again and again, so tabulate them: `dist[i][j]` is the fewest edits that turn the first `i` letters of `source` into the first `j` letters of `target`, with `dist[i][0] = i` (delete everything) and `dist[0][j] = j` (insert everything). If the last letters are equal, `dist[i][j] = dist[i - 1][j - 1]`; otherwise it is 1 plus the smallest of `dist[i - 1][j]` (delete), `dist[i][j - 1]` (insert) and `dist[i - 1][j - 1]` (replace). Row `i` reads only row `i - 1` and itself, so the solutions keep two rows and set `cur[0] = i` at the start of each.

<Solutions n="177" />

**Complexity.** O(n × m) time, O(m) space for the two rows.

**Common mistake.** Starting the first row and column at 0 instead of `j` and `i`, as if turning a string into an empty one were free: `("abc", "")` returns 0 instead of 3.

## 178 · Pattern Matching With . and *

**Dynamic Programming · Hard**

A pattern is a sequence of items. An item is a lowercase letter or a dot, optionally followed by a star. A letter item matches exactly that letter, a dot item matches any one letter, and an item followed by `*` matches zero or more consecutive letters, each of which the item alone would match, so `.*` matches any run of letters, including none. A pattern matches a text when its items, in order, match consecutive pieces that together make up the whole text, with nothing left over at either end. Return `true` if `pattern` matches `text` and `false` otherwise. An empty pattern matches only the empty text.

```text
Example 1
  input:  text = "seat", pattern = "se.*t"
  output: true     (".*" matches "a")

Example 2
  input:  text = "seats", pattern = "se.*t"
  output: false    (the final s is left over)
```

Constraints: `0 ≤ text.length, pattern.length ≤ 1000`, `text` contains only `a`–`z`, `pattern` contains only `a`–`z`, `.` and `*`, and every `*` comes straight after a letter or a dot, so a pattern never starts with `*` or has two in a row.

**Approach.** The simple solution backtracks: match the items from the left, and for a starred item try every number of letters it could take. It is exponential on inputs like `"aaaaaaaaaaaaaaaaaaab"` with `"a*a*a*a*a*a*a*a*c"`, where it tries every way to share the `a`s among the eight stars before failing. The same pair of positions keeps coming back, so tabulate: `match[i][j]` says whether the first `i` letters of the text match the first `j` characters of the pattern, and `match[0][0]` is true. If pattern character `j` is not a star, `match[i][j]` needs `i > 0`, the text letter to fit the pattern character (equal, or a dot) and `match[i - 1][j - 1]`. If it is a star, its item either matches nothing, `match[i][j - 2]`, or takes the last letter, which must fit the item, and possibly more letters before it, `match[i - 1][j]`. Row `i = 0` must be computed too, because `"a*b*"` matches the empty text; each row reads only the previous one and itself, so the solutions keep two rows.

<Solutions n="178" />

**Complexity.** O(n × m) time, O(m) space for the two rows.

**Common mistake.** Starting the loop over the text at `i = 1` and leaving row 0 false apart from `match[0][0]`, which forgets that a starred item can match nothing at the start: `("b", "a*b")` returns `false` instead of `true`.

## 179 · Best Profit With at Most k Trades

**Dynamic Programming · Hard**

`prices[i]` is the price of one share on day `i`. A trade buys one share on one day and sells it on a later day. You hold at most one share at a time, so a trade must be sold before the next one is bought, although selling and buying again on the same day is allowed. Return the largest total profit you can make with at most `k` trades. Making no trade is allowed, so the answer is never below 0. Problem 008 is the case `k = 1`.

```text
Example 1
  input:  prices = [3, 8, 5, 1, 7, 8], k = 2
  output: 12       (buy at 3, sell at 8; buy at 1, sell at 8)

Example 2
  input:  prices = [9, 7, 4, 1], k = 2
  output: 0        (prices only fall)
```

Constraints: `0 ≤ prices.length ≤ 1000`, `0 ≤ prices[i] ≤ 1000`, `0 ≤ k ≤ 100`.

**Approach.** The simple solution tries every set of at most `k` non-overlapping buy and sell days, which is exponential, and the greedy shortcuts fail (see the common mistake). Instead, keep two numbers per trade, counting cash from 0 so that cash is profit: `bought[t]` is the most cash you can have while holding the share of your `t`-th trade, and `sold[t]` the most cash after completing `t` trades. On a day with price `p`, for `t` from 1 to `k`, `bought[t] = max(bought[t], sold[t - 1] - p)` (keep holding, or buy today after `t - 1` trades) and `sold[t] = max(sold[t], bought[t] + p)` (keep, or sell today). Start every `bought[t]` at `-prices[0]`, as if the share had been bought on day 0, and every `sold[t]` at 0. Since buying and selling on the same day is allowed and earns nothing, `sold[t]` never drops below `sold[t - 1]`, so `sold[k]` already covers "at most `k`".

<Solutions n="179" />

**Complexity.** O(n × k) time, O(k) space for the two arrays.

**Common mistake.** Adding up the `k` largest rising runs: with `[1, 3, 2, 8]` and `k = 1` that takes the run from 2 to 8 and returns 6, but buying at 1 and selling at 8 earns 7.

## 180 · Count Distinct Subsequences

**Dynamic Programming · Hard**

Given two strings `s` and `t`, count the ways to pick letters of `s`, keeping their order, that spell `t`. Two ways are different when they use a different set of positions in `s`, even though both spell `t`; positions count from 0. The count grows very fast, so return it modulo `10⁹ + 7`. An empty `t` can be picked in exactly one way, by picking nothing, even from an empty `s`.

```text
Example 1
  input:  s = "banana", t = "ban"
  output: 3        (the b, then an a and a later n, at positions 1 and 2, 1 and 4, or 3 and 4)

Example 2
  input:  s = "abc", t = "abcd"
  output: 0
```

Constraints: `0 ≤ s.length, t.length ≤ 1000`, both contain only `a`–`z`.

**Approach.** The simple solution tries every set of `t.length` positions in `s`, which is exponential. Instead, read `s` one letter at a time and keep `ways[j]`, the number of ways to spell the first `j` letters of `t` with the letters read so far, starting with `ways[0] = 1` and the rest 0. When the next letter `c` arrives, every `j` with `t[j - 1] == c` gains `ways[j - 1]`, the ways that finish with this letter. Walk `j` from the end down to 1, so that `ways[j - 1]` still counts only ways that use earlier letters, the same trick as in problem 175. Reduce modulo `10⁹ + 7` after every addition: both terms are below `10⁹ + 7`, so the sum stays below `2³¹ − 1` and a 32-bit `int` never overflows.

<Solutions n="180" />

**Complexity.** O(n × m) time, O(m) space for the array.

**Common mistake.** Walking `j` upwards, which lets one letter of `s` stand for two letters of `t`: `("a", "aa")` returns 1 instead of 0.
